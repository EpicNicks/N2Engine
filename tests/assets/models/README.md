# Test models

Models the engine tests load from disk. Every other glTF file the tests use is built in memory by the test itself
(`tests/common/GltfTestBuilder.hpp`).

| File | What it is | How it was made |
|---|---|---|
| `textured_cube.glb` | A UV-mapped cube mesh with two materials: a procedural 2 x 2 checker texture (16 x 16 PNG, red / green over blue / yellow, nearest, clamped) on the +Z, +X and +Y faces, and plain lit blue on the others. Three nodes use it: `Cube` at the origin, its child `Child` (at y = 1, half size) and `Mirrored` (at x = 2, scale -1 on x). | Generated by `make_sample_models.py` (standard-library Python 3). Re-run it to regenerate the same bytes. |
| `textured_cube.fbx` | The same scene as an ASCII FBX 7.4 file, for the optional ufbx importer (`N2ENGINE_MODEL_UFBX`): Blender's FBX layout, in centimetres, Z up and -Y forward, so a correct import converts axes and units. Its texture is the file name `checker.png`, which is not committed (the tests write it, as an FBX texture names a file). Used by `UfbxImporterTests.cpp` (compared with the glb in world space) and `ModelFbxTests.cpp`. | Generated by the same script (`python make_sample_models.py fbx` writes only this file; the `.glb` embeds a PNG compressed by the local zlib, whose bytes can differ between versions). Plain text, LF line ends on every platform. |

All of them are this repository's own work, under its MIT licence: no third-party model is used.

`textured_cube.glb` stands in for the self-authored Blender export the design asks for (#3, decision 13), so the
tests don't need Blender. A real Blender export of the same scene (File > Export > glTF 2.0, `.glb`, +Y Up, Apply
Modifiers) should be added beside it later, with a test that runs the same checks on both.
