SCOPE (this is PR L2): (1) EXECUTION POLICY: LuaRuntime::SetExecutionPolicy(Run | DeclarationsOnly), process-wide (per design 1.4: edit mode is set only AFTER deserialisation so a per-scene flag is too late); Host.cpp sets DeclarationsOnly when the host is an edit host (options.playScene.empty(), verify in code); default Run so the game, play host and all existing tests are unchanged. (2) In DeclarationsOnly: LuaComponent::SetScript/LoadScriptInstance never touch the global sol::state; they ask a ScriptDeclarationCache keyed by resource path + SOURCE CONTENT HASH (not mtime) and populate the fields (DescribeFields-equivalent data for GetLuaFields/SetEditorFields) from the cache; no instance exists so CallLuaMethod is unreachable (defensive early return/assert); LuaRuntime::ReloadModule in this policy refreshes the cache entry and notifies components to re-read, running nothing; OnDisable/OnDestroy no longer run Lua on the edit host (decision accepted by the user). A failed declaration keeps scriptData and shows its keys with inferred kinds (design decision 5 recommended); unevaluable declarations are reported with the L1 'unevaluable' reason, never silently empty. (3) OFF THE MAIN THREAD (REQUIREMENT from L1's review): Evaluate must NOT run on the editor host's main/command thread. Weak-key (__mode='k') tables make Lua's GC do quadratic work inside ONE C call that neither the instruction hook nor the allocator cap can interrupt, so the host would stall. Run each evaluation on a worker thread with a wall-clock deadline: on overrun the host ABANDONS the call (the worker keeps its own throwaway state alive until it finishes or is torn down, never touches host data after abandonment; results of an abandoned call are discarded; the cache records a failed/timeout entry for that content hash so it is not retried in a loop), and the command that needed it answers promptly with the failed-declaration shape. Bound the number of concurrent/abandoned workers (a small cap; when reached, further evaluations fail fast with a clear reason) and make shutdown deterministic (host exit must not hang or crash on a still-running abandoned worker: detached-with-ownership design or a join with a bounded wait, justify it). The alternative (patching the vendored Lua to bound GC work) is NOT chosen; do not patch vendored Lua. Pick a sensible default deadline (e.g. 2 s) and expose it as a named constant plus a test hook. (4) SINGLE SCENE BUILD: remove the duplicate builds in EditorServer HandleLoadScene (validate once, then AddScene(std::move(scene), true)); keep behaviour (validation errors, name collisions UpdateScene+LoadScene) identical; add a test that counts builds. (5) QUIT GUARD: Application.Quit (LuaApplicationBindings) becomes a logged refusal when the policy is not Run (unreachable in practice, a guard for future paths). (6) Update the CommandClass::Write comment (EditorServer.hpp ~527-529) and docs: docs/scripting-lua.html (#sandbox and the evaluator section: the edit host never runs project code; computed defaults need a declared type=; stubs differ from a real run), docs/editor.html role text, docs/serialization.html reflection-lua if it describes the old behaviour, plus the docs/index.html design-decision callout that L1 could not add (look at how other callouts there are written).
