(3) OFF THE MAIN THREAD (REQUIREMENT from L1's review): Evaluate must NOT run on the editor host's main/command thread. Weak-key (__mode='k') tables make Lua's GC do quadratic work inside ONE C call that neither the instruction hook nor the allocator cap can interrupt, so the host would stall. Run each evaluation on a worker thread with a wall-clock deadline: on overrun the host ABANDONS the call (the worker keeps its own throwaway state alive until it finishes or is torn down, never touches host data after abandonment; results of an abandoned call are discarded; the cache records a failed/timeout entry for that content hash so it is not retried in a loop), and the command that needed it answers promptly with the failed-declaration shape. Bound the number of concurrent/abandoned workers (a small cap; when reached, further evaluations fail fast with a clear reason) and make shutdown deterministic (host exit must not hang or crash on a still-running abandoned worker: detached-with-ownership design or a join with a bounded wait, justify it). The alternative (patching the vendored Lua to bound GC work) is NOT chosen; do not patch vendored Lua. Pick a sensible default deadline (e.g. 2 s) and expose it as a named constant plus a test hook. (4) SINGLE SCENE BUILD: remove the duplicate builds in EditorServer HandleLoadScene (validate once, then AddScene(std::move(scene), true)); keep behaviour (validation errors, name collisions UpdateScene+LoadScene) identical; add a test that counts builds.
