SCOPE: (1) a new static library target (e.g. engine/network/n2net with headers under engine/include/engine/network/n2net/ and sources under engine/src/network/n2net/: do not touch the existing NetworkPresets files in engine/src/network or the files of the in-flight netcode A1 PR (presets/validation/health): keep new files in a clearly separate directory and a separate CMake target linked into the engine/tests only where needed); (3) SimTransport: an in-memory implementation driven by an explicit virtual clock (no wall clock) and a seeded deterministic RNG (your own small portable PRNG, not std::random_device or distributions whose output differs across standard libraries), configurable per link and direction: one-way latency, jitter, loss (independent and burst), reordering, duplication, bandwidth cap and a queue limit; deterministic: the same seed and the same call sequence give byte-identical delivery on every platform (this is the CI network simulator for all later netcode tests); (4) the packet layer per 2.1: little-endian header = protocol id (32-bit), connection id, 16-bit sequence, ack + 32-bit ack bits (Gaffer-on-Games style, handle wraparound correctly), payload = channel blocks; reliable-ordered channel (resend on timeout/ack-gap with an RTT estimator, in-order delivery, flow/window limit) and unreliable-sequenced channel (newest wins, stale dropped); fragmentation and reassembly of large reliable messages (bounded memory per connection, a hard cap on message size and in-flight fragments, timeouts for incomplete messages); RTT/loss statistics per connection; strict, bounds-checked parsing of every untrusted byte (a malformed or hostile packet must never crash, over-read, allocate unboundedly or loop: this will face the internet): no exceptions, return error codes; (5) TESTS (engine unit tests on all legs including web and arm64; web_tests/engine_tests as appropriate: see how existing tests are registered and the web test-exclusion conventions in docs/web-build.html): sequence/ack wraparound, reliable delivery under 30% loss with reordering and duplication (exact in-order exactly-once delivery), unreliable newest-wins, fragmentation at sizes from 1 byte to the cap incl. boundary sizes and out-of-order fragments, caps/timeouts enforced, simulator determinism (golden delivery trace hashed and compared to a constant: identical across legs), a fuzz-style test feeding thousands of random and truncated packets (seeded, bounded run time) that must not crash or leak (use the allocator counters/size caps), RTT estimator sanity, two peers over SimTransport exchanging 10k messages. (6) DOCS: a new docs page docs/netcode.html (link it from the docs index/navigation like other pages) describing for now ONLY what exists: the transport interface, the packet format (byte layout table), channels, fragmentation limits, the simulator and how to use it in tests, security notes (untrusted input handling), and clearly what is NOT there yet (sockets A4, encryption A5, replication B-track); docs/testing.html entry; verify every sentence against the CODE.
