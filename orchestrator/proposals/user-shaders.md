# Proposal: user shaders (`.n2shader`, cooked offline and compiled on the player's machine)

Status: revised 2026-11-17 after an independent review (section 13 lists every change; marks [R] = added or corrected by the review, citations re-checked against master 9f82e072). Research and a throwaway translation spike, N2Engine master b2d37be2 (2026-11-16). Nothing in the repo was changed except this file. Marks: [V] verified by reading the repo (path:line, relative to N2Engine/) or by running a tool on this PC (the spike, section 1.1); [M] from memory / unverified until a CI or GPU run; [E] my estimate, nothing measured. This PC has the Vulkan SDK 1.4.321.1 (glslangValidator 15.3.0, glslc, spirv-val, spirv-opt, spirv-cross) [V]; Tint (the `bin/tint.exe` of Dawn release v20261016.190333, the pin CI uses, `scripts/install-wgsl-validators.sh:27-30`) and naga-cli 30.0.1 (the CI pin, `:36-37`) were fetched/built into a scratch folder for the spike, not installed.

## Executive summary
- **Recommendation: one `.n2shader` file (JSON header + GLSL 450 stage code) cooked offline into SPIR-V, WGSL and GLSL 330, against a fixed engine interface ("contract v1") that generalises the tables the repo already has (`GpuShaderInterface.hpp`); the Material gets an optional shader reference plus a parameter map; the three built-ins and every existing `.mat` stay byte-for-byte what they are.** Fragment stage only in the first release (the engine supplies the vertex stage); the format reserves the vertex stage.
- **The riskiest unknown, GLSL -> SPIR-V -> WGSL for user-style code, is mostly retired by the spike [V, section 1.1]:** glslang + Tint translate a user-style shader with a generated parameter block, texture sampling, `discard`, loops, `inverse()`, derivatives, `texelFetch`, `switch`, uniform float arrays and `row_major` matrices, deterministically, in 0.15 s, and naga validates the result. Three real gaps, all avoidable by a generated prelude and a short authoring list: **combined `sampler2D` must become separate texture + sampler** (naga's SPIR-V reader rejects combined samplers outright; Tint accepts them but invents its own binding numbers), **a `textureSample` after a `discard` or non-uniform branch is a Tint error** (the repo's own `lit.frag` hits it), and **`isnan`/`isinf` are unsupported by both** translators.
- **Contradicts earlier assumptions [V]:** (1) `webgpu-backend-design.md` expected `inverse()` and `row_major` to block option B; both translate fine through Tint (section 1.1). (2) **naga cannot be the translator** (its SPIR-V front end fails on every engine fragment shader; its GLSL front end rejects `row_major` and `sampler2D` with `set/binding`); Tint is, naga stays a validator. (3) The editor host offers only OpenGL and software (`editor-server/src/HostOptions.cpp:235`), so the editor can show a user shader only through OpenGL; Vulkan/WebGPU results come from the cook tool's validation and CI. (4) The Vulkan `kMaterialBlockRange` is 128 bytes (`GpuShaderInterface.hpp:101`): the user parameter block needs it raised (to 256). **[R] `kMaterialBlockRange` is a shared constant, not Vulkan-only:** it is used in `WebGpuDraw.cpp:75,773,861`, `BlockMaterial.hpp:64,87`, `VulkanDraw.cpp:1138,1227` and the parity and lighting tests (`VulkanShaderParityTests.cpp:673`, `WebGpuShaderParityTests.cpp:667`, `VulkanLightingTests.cpp:683`, `WebGpuRendererLightingTests.cpp:683`). The cost is nil only where the device's uniform alignment is already 256 (WebGPU fixes it; many Vulkan drivers report it [M]); on a 64-byte-alignment device a 256-byte range doubles the per-draw ring use of every built-in draw too. Decision: keep 128 for the built-ins and give a user shader its own range (the material block is bound per material, so the range is a property of the material's layout, not of the pipeline layout); if the descriptor cache key (`std::array<uint64_t,11>`) cannot carry a per-material range, stage 2 moves the whole constant and states it, with the built-in goldens as the guard.
- **Compile on the player's machine:** OpenGL yes everywhere (driver compiles GLSL; the prelude expansion is text work, no compiler); desktop Vulkan yes by embedding glslang behind an option (about 4-5 MB [M from the 4.5 MB `glslangValidator.exe` here, V]); web no for GLSL (the browser compiles WGSL, GLSL -> WGSL needs Tint), so web ships cooked WGSL and may allow hand-written WGSL as an escape hatch; Android/iOS cooked SPIR-V only in v1. Always ship source and cooked output together; on-device compile is the fallback for a stale or missing cooked payload and for mods.
- **Recommended stage 1:** the cook tool, the contract's generated prelude and a conformance corpus with CI on the existing `wgsl (Tint, naga)` job. No engine code, no renderer change. Stage 2 is the Vulkan pipeline generalisation (the second unknown).

## 2. What breaks for a non-built-in shader, per backend (b)
Every spot below is keyed on the closed `BuiltInShader` enum (`Unlit, Lit, Text`, `GpuShaderInterface.hpp:39-44`) [V].

**Vulkan** (`renderer/src/vulkan/VulkanDraw.cpp`, `.hpp`):
- `DrawState::shaders` is `std::array<..., kBuiltInShaderCount>` of modules made from embedded SPIR-V (`VulkanDraw.hpp:120`, `VulkanDraw.cpp:139-161`); `IsValidShader`/`CreateMaterial` compare against those three pointers (`:932-940`) and otherwise return null.
- `PipelineKey` is `{shader:uint8, depthTest, depthWrite, cull, blend, additive, wireframe}` packed (`VulkanDraw.hpp:94-110`); `GetPipelineLocked` takes the vertex-input attributes from `Attributes(shaderKind)` (`VulkanDraw.cpp:600-609`). A user shader needs a shader id beyond the enum and attributes from its manifest. The cache stays bounded per shader (about 3 x 2 x 2 x 3 x 3 combinations, as in `vulkan-backend.md`).
- **One pipeline layout serves all shaders**: set 0 = PerDraw (binding 0) + Lighting (binding 1), set 1 = Material block + five combined samplers (`VulkanDraw.hpp:114` comment; `VulkanDraw.cpp:236-246`). **Good news:** a user shader needs no new layout, and may already read the Lighting block, which sits in the layout for every shader. What is gated on `kind == Lit` is only the per-frame *copy* of the lighting data into the ring (`:1136,:1146-1155`).
- `BlockMaterial` holds `BuiltInShader kind`, finds names in `MaterialUniforms(kind)` (`BlockMaterial.hpp:46-91`) and a fixed `std::array<uint8_t, 128>` block. It must take a layout provider (a `span<const Uniform>` plus size) instead of the enum, and 256 bytes.
- Clip space: each built-in vertex shader remaps GL clip z (`z = (z + w) * 0.5`, `renderer/shaders/vulkan/unlit.vert:33-34` [R]), and a test checks every vertex shader does (`VulkanShaderParityTests.cpp:904`). A user shader must not be able to forget it: the engine generates the vertex `main` (section 3.3).
- Matrices are uploaded row-major as given and the GLSL block is `row_major` (`VulkanDraw.cpp:1163-1166`).

**WebGPU** (`renderer/src/webgpu/WebGpuDraw.cpp`): same shape. Shader modules are the three embedded WGSL strings (`:139-156`); the one pipeline layout is `frameLayout` (PerDraw, Lighting) + `materialLayout` (material block + 5 textures + 5 samplers) (`:162-222`); `ShaderIndex(kind)`/`VertexLayoutId(kind)` index by enum (`:82-92`); `CreateShaderProgram`/`CreateMaterial` return null for anything else (`:514-519,:605`). **Differences to handle:** matrices are **transposed on upload** (`WriteTransposed`, `:795-799`) so WGSL reads column-major; a cooked user shader must therefore declare the block *without* `row_major` for this target (the prelude does, section 3.4), otherwise Tint's `transpose()` would transpose twice. The lit gate is `blockMaterial.kind == Lit` (`:771`). Pipelines are created per (shader, state) through `wgpuDeviceCreateRenderPipeline` [M], with the browser's own pipeline compile (first-use hitches: user shaders should be pre-warmed at load, section 7.5).

**OpenGL** (`renderer/src/opengl/`): the least broken: `CreateShaderProgram` compiles any `#version 330 core` source (the context is 3.3 core, `engine/src/platform/DesktopGlfwHost.cpp:60-62`), and values are applied **by uniform name** at draw (`OpenGLMaterial::Apply`, `:100-130`; names that do not exist are location -1 and are ignored by GL). What GL lacks is (a) the engine's per-draw data: `uModel/uView/uProjection` are plain uniforms the renderer sets by those exact names for the *built-in* shaders, and the lighting uniforms (`uDirectionalLights[i].intensity` ...) are set on the lit shader only (`:477-526`); (b) `layout(binding=...)` (needs 4.2), so sampler units are `glUniform1i` by name with `AuxTextureUnit` = 1 + slot (`OpenGLMaterial.cpp:72,102`); (c) the GL <-> Vulkan clip/y differences, which GL does not have (the shaders are written for GL). A user shader for GL is the prelude-expanded 330 text with the same names; no SPIR-V is involved.

**Software**: `CreateShaderProgram` returns an unlit shader and ignores the source (`SoftwareRenderer.cpp:1282`); a Material with a user shader draws with built-in unlit and a one-time warning, as decided.

**The blocks and who owns them for a user shader.** Today: PerDraw and Lighting are the renderer's (written per draw by the backend); the Material block is the engine's (`Material::ApplyUniforms` through `BlockMaterial`). For a user shader: PerDraw and Lighting stay the renderer's, **unchanged in layout and offsets**; the Material block becomes **generated from the declared parameter list** and owned by the (new) user-shader `BlockMaterial` whose layout comes from the cooked manifest.

### 2.1 The interface a user shader may rely on ("contract v1")
| Item | Contract | Source of truth |
|---|---|---|
| Stages / entry | fragment `void main()`, and (reserved) vertex; GLSL 450, no `#version` line (the prelude adds it) | prelude |
| set 0, binding 0 `PerDraw` (std140, 224-byte range) | `n2_Model`, `n2_View`, `n2_Projection` (mat4), `n2_StageDim`, `n2_TintSaturation`, `n2_TintInside`, `n2_TintCircle`. **How the cook step validates a shader against it (replaces the missing reflection).** Reflection is built, not borrowed, in four independent layers: (1) the engine side **generates** the Material block and the prelude, so the author cannot mis-declare an engine block (nothing to drift); (2) glslang compiles with `#line` directives so every error carries `file:line`; (3) a SPIR-V reflection pass (`spirv-cross --reflect` JSON [V], or a small in-tool SPIR-V reader) checks that the module uses only set 0/1, only bindings from the contract, only the generated Material block, a `PerDraw`/`Lighting` declaration identical to the table, input locations from the contract, one colour output, an allowed capability list, and that the **std140 offsets glslang assigns equal the offsets the cook computed** (the self-check that the CPU side and the GPU side agree: the user-shader analogue of `VulkanShaderParityTests`); (4) Tint and naga validate the WGSL. A manifest (section 3.2) records the result, so the runtime never reflects.

## 3. The `.n2shader` format (c)
### 3.1 File layout
One UTF-8 text file (LF or CRLF; the repo's files are CRLF), so it diffs, merges and opens in any editor, and the existing text-asset commands already move it (`ReadTextAsset`/`WriteTextAsset` need `.n2shader` added to their whitelist, `EditorServer.cpp:247`):

```
{ "n2shader": 1,
  "name": "Dissolve",
  "params": [
    { "name": "u_Tint",      "type": "color",   "default": [1,1,1,1], "label": "Tint" },
    { "name": "u_Threshold", "type": "float",   "default": 0.5, "min": 0, "max": 1, "label": "Threshold" },
    { "name": "u_Steps",     "type": "int",     "default": 4,   "min": 1, "max": 8 },
    { "name": "u_Mask",      "type": "texture", "default": "white" }      // white | black | normal | none
  ],
  "uses": ["lighting"],                                   // optional: lighting, time
  "state": { "blend": "alpha", "cull": "none", "depthWrite": false, "queue": "transparent" },
  "targets": { "webgpu": "generated" }                    // or "authored" (section 10, Q4)
}
#stage fragment
void main() { ... }
#stage vertex        // optional, reserved
```
The header is strict JSON (nlohmann in C++, `JSON.parse` in the cook tool, so both read it identically); everything after the first line that is exactly `#stage fragment` is GLSL. The cook inserts `#line <n> "<res path>"` so compiler errors cite the author's file and line. Why not one JSON string per stage: unreadable and loses line numbers. Why not GLSL pragmas for params: the editor and the cook need the declared list without parsing GLSL.

### 3.2 Parameters, types, state, versioning
- **Types** (all map to std140 and to the existing `IMaterial` setters): `float`, `int`, `bool` (an int, as `GpuShaderInterface.hpp:50`), `vec2`, `vec3`, `vec4`, `color` (vec4 plus an editor colour picker; sRGB-authored, passed as given, like `uAlbedo`), `texture` (2D). No arrays and no matrices as parameters in v1 (the author may still use arrays inside the shader).
- **Names**: `u_` or any identifier not starting with `n2_`/`gl_`; unique; they become both the GLSL member name and the by-name key for GL (`glUniform*`) and the C++/Lua setters.
- **Editor data**: `label`, `min`/`max`/`step`, `tooltip`, `group`; ignored by the runtime.
- **Reserved names** bind to the standard Material fields so a custom shader still tints and textures like the built-ins: a `color` param `baseColor` and a `texture` param `baseColorTexture` take `Material::GetBaseColor`/`GetBaseColorTexture` unless the `.mat` sets them (this is what lets `Sprite2D` and the UI `Image` feed a texture to a user shader, section 4).
- **`state`** is a hint that supplies the `.mat`'s defaults only (`alphaMode`, `doubleSided`, `depthWrite`, queue); a value the `.mat` sets wins (`Material::AlphaMode` and `IsDoubleSided` already decide `QueueFor`/`StateFor`, `MeshDrawing.cpp:7-21`). Blend modes: `none`, `alpha` (the Blend alpha mode), `additive` (`RenderState::additive`); anything else (premultiplied, multiply) is out of v1 because `RenderState` has no such state (`RenderState.hpp`).
- **Versioning**: `"n2shader": 1` is the *format*; the *contract* has its own number (`contract: 1`, stamped by the cook into the manifest, bumped whenever the prelude, block layouts or binding map change). A loader reads format 1 and refuses a higher number with a message naming the file; an engine running a shader cooked for another contract recooks if it can compile (section 7) or draws the fallback.
- **Cooked manifest** (JSON next to the payloads): contract version, format version, source sha-256, compiler ids and versions, per-param `{name,type,offset,default}`, block size, texture slots with defaults, `uses`, vertex attributes read, state hints, per-target payload hashes.

### 3.3 Why the engine writes the vertex `main` (fragment-only first)
The z remap (`z = (z+w)*0.5`) and the viewport flip belong to the target, and a user vertex stage can forget them; with an engine vertex stage the user shader cannot. It also means the pipeline's vertex input is fixed (the lit attribute set), the varying matching problem does not exist, and the normal-matrix/tangent maths (`lit.vert:28-37`, which includes `inverse`, `determinant`) is written once. A custom vertex stage (vertex displacement, wind, billboards) is a follow-up stage that adds `#stage vertex`, `n2_SetPosition`, manifest attributes and varying matching.

### 3.4 The generated prelude (the heart of the portability)
Per target the cook concatenates, in order: `#version 450` + the line-directive extension, the **target prelude**, the generated Material block, the user stage with `#line`. The target prelude differs only in four places:
| | Vulkan (SPIR-V) | WebGPU (via Tint) | OpenGL (text) |
|---|---|---|---|
| `PerDraw` block | `std140, row_major` (the engine copies row-major, `VulkanDraw.cpp:1163`) | `std140`, column-major (the backend transposes on upload, `WebGpuDraw.cpp:795`) | plain `uniform mat4 n2_Model; ...` named uniforms, set by the renderer by name |
| Textures | `uniform sampler2D n2_tex0..4` (bindings 1-5, as the built-ins) | `uniform texture2D n2_tex0..4` (1-5) + `uniform sampler n2_samp0..4` (6-10) and `texture(sampler2D(t, s), uv)` inside `n2_texture` | `uniform sampler2D`, unit = slot |
| Clip fix in `n2_SetPosition` | `z = (z + w) * 0.5` | same | none |
| `discard` | plain | **the prelude's `n2_texture` is called before any `discard` in the generated wrapper**, or the cook passes `--allow-non-uniform-derivatives` (section 5.2) | plain |

The Vulkan prelude is the *same* separate-texture form as WebGPU if the user-shader descriptor set later moves to separate images and samplers; keeping combined samplers for Vulkan (as the built-ins do) means no descriptor change.

## 4. Asset import, Material side, built-ins unchanged (c, d)
- **Asset**: `Shader` resource type, extension `.n2shader`, a loader registered like Material's (`ResourceLoader.cpp:80-90,108-116`; `ResourceTypeFor` returns `"Shader"`); the UUID lives in `.import/<...>.meta` like every asset (`AssetMetadata.hpp`, `meta-file-structure.json`); `importSettings` may hold `{ "precompileTargets": [...] }`. `Shader::Load` parses the header and the stage text and, in a player, finds the cooked payload for the current backend (below). Reload (`ResourceLoader::Reload`, `:222`) re-parses; the shader's version counter bumps and so does every dependent Material's GPU version (`Material::GetGpuVersion` is what `GpuCache` keys on, `Material.hpp:210-214`), so draws pick up the new shader on the next frame, the same mechanism a texture change uses.
- **Material** gains `std::shared_ptr<Shader> _shader` and `std::map<std::string, ParamValue> _params` (a variant of float/int/vec/color/texture). `.mat` keys (optional; absent = today's behaviour): `"shader": "res://shaders/dissolve.n2shader"` (path, UUID or relative, parsed exactly like `ReadTexture`, `Material.cpp:116-150`) and `"params": { "u_Threshold": 0.3, "u_Tint": [1,0.5,0,1], "u_Mask": "res://t.png" }`. An unknown or ill-typed param is ignored with the existing `Warn` pattern (`Material.cpp:45-49`), a missing one takes the shader's default. `ToJson` writes them only when a shader is set, so existing `.mat` files round-trip unchanged. `SetShader` and `SetParam*` call `Changed(structural)`: shader and textures bump the GPU version, plain values only the version (they are uniforms, as `ApplyUniforms` treats the rest).
- **Draw path**: `GpuCache::AcquireMaterial` asks the renderer for `CreateUserMaterial(userShader)` (new) when `material->GetShader()` is set, instead of `GetStandardLitShader()` (`GpuCache.cpp:332`); `ApplyUniforms` writes the declared params through the same by-name setters (`SetFloat/SetVec4/SetColor/SetInt`) plus `SetAuxTexture` for slots; no new per-draw cost. A built-in Material never touches the new code (`GetShader() == nullptr` takes the existing branch): that is the guarantee that built-in materials stay unchanged, and a test pins it (section 9).
- **Failure**: if the renderer cannot make the user shader (compile error, unsupported backend, software), `AcquireMaterial` returns the **built-in unlit** material with the base colour and texture (so the object is visible and obviously wrong), logs once with the shader's path, `file:line` and the compiler's message, and in the editor also posts to the log panel. A magenta "error shader" is a better editor-time signal (obviously broken) and the unlit fallback a better shipped-game signal (nothing flashes magenta): recommended: magenta when the host is an editor, unlit when it is a player.
- **C++ API**: `Material::SetShader(std::shared_ptr<Shader>)`, `SetFloat/SetInt/SetVec2/3/4/SetColor/SetTexture(name, ...)` (returns false and warns for an unknown or mistyped name), `GetParam`, `GetShader`. **Lua**: no Material object exists today, so add a small one: `Material.Load("res://m.mat")` and `renderer:GetMaterialInstance(slot)` returning a handle with `:SetFloat(name, v)`, `:SetColor`, `:SetVec4`, `:SetTexture(name, path)`, `:GetFloat(name)`; instance handles are **copy-on-write per renderer slot** (a write clones the shared asset's material so one object's change does not recolour every user, Unity's `.material` vs `.sharedMaterial`) and are **runtime only, not serialized**; a persistent per-object value needs its own `.mat` (scene serialization keeps referencing the `.mat` by UUID, unchanged; per-instance overrides inside scenes and prefabs are deferred, `prefab-overrides.md` would own them). `Sprite2D`/`UIImage` get `SetShader(path)` and `SetShaderParam(name, v)` because they build their own materials (`Sprite2D.cpp:115-148`, `Image.cpp:100-108`): they create a user-shader Material, set `baseColorTexture`/`baseColor` through the reserved names, keep `saturation`/`flash` effects unavailable on a user shader (the shader can implement them), and `Image` moves from a raw renderer material to a Material for this (a small refactor, the only touch to existing code).
- **Editor inspector**: the host needs `ListAssets` type `Shader` and a `GetShaderInfo(uuid)` returning the declared params (name, type, default, min/max, label, group) and the last cook/compile diagnostics; the inspector builds a generic form from it, writes `.mat` through the existing text-asset commands, and a changed `.n2shader` is re-read by `Reload`. The editor frontend is not in this repo [M], so this proposal fixes only the protocol commands and leaves the UI to it.

### 5.2 Translation gaps and the authoring conventions that avoid them
| Gap [V spike] | Avoidance |
|---|---|
| Combined `sampler2D` -> Tint invents bindings; naga rejects it | the prelude never exposes `sampler2D` to the WebGPU target (separate `texture2D` + `sampler`, fixed bindings) and authors call `n2_texture(i, uv)` |

| Sampling after `discard` / non-uniform branch -> Tint error (the built-in `lit.frag` does it) | convention: sample first, then branch; or `textureLod`/`texelFetch` (no derivative); enforced by the Tint validation in the cook, with the message pointing at the `.n2shader` line; the hand-written WGSL lit shader solved the same thing by hand |

| uniformity of non-uniform loops, derivative in loops | Tint reports them; no author rule beyond "fix what the cook reports" |
Recommended authoring subset: **GLSL 450 core minus the "Not available" row of 2.1, plus the three rules above**, enforced mechanically (prelude shape, Tint/naga/spirv-val, a builtin lint) rather than by documentation, with a docs page of conventions and the corpus as examples. ## 6. Per-backend implementation notes (b, e)
1. **Vulkan**: `Renderer::Common::UserShaderBlob` (backend-free struct in `renderer/include/renderer/common/`: manifest, per-target payload bytes) and `virtual IShader* CreateUserShader(const UserShaderBlob&)` + `CreateUserMaterial(IShader*, ITexture*)` on `IRenderer` with default "unsupported, LogOnce, nullptr" (software and test fakes need no change). `VulkanShader` gets a `shaderId`; `PipelineKey` widens `shader` to 16 bits (the packed key is a uint32 of which `Pack()` uses 15 bits); `GetPipelineLocked` takes attributes and a `usesLighting` flag from the shader. `kMaterialBlockRange` -> 256 and the ring math follows (`:1138`).
2. **WebGPU**: `CreateUserShader` -> `wgpuDeviceCreateShaderModule` with the cooked WGSL (the browser validates, so cooked WGSL is untrusted input there too: errors come through the existing uncaptured-error path); the shared layouts already fit.
3. **OpenGL**: `CreateUserShader` builds the GL text through the existing `CreateShaderProgram`; the renderer sets `n2_Model/View/Projection`, `n2_StageDim`, tint uniforms and (opted in) lighting uniforms on any bound user shader by the prelude's names, exactly as it does for the built-ins' names today. OpenGL has **no CI** (GL cannot run on the runners): correctness is text-level parity plus the user's GPU PC.

## 7. Runtime compile on the player's machine (f)
Principle: **a shipped game always carries the cooked outputs, and carries the source unless stripped.** On-device compile is the fallback when the cooked payload is missing, stale (contract or compiler version differs from what this engine build expects), or when a user adds a mod pack. It is a capability each backend has or does not have:

| Platform / backend | Can compile `.n2shader` on device? | How | Recommendation |
|---|---|---|---|
| OpenGL (desktop) | **Yes, always** | the GL text is prelude + source (no compiler of ours); the driver compiles it at `glLinkProgram`; errors from `glGetShaderInfoLog`, mapped back to file:line by the `#line` directives | on; it is the default behaviour |
| Vulkan, Windows/Linux | **Yes, with glslang embedded** | link glslang (`glslang`, `SPIRV`, `glslang-default-resource-limits`; not SPIRV-Tools) behind `N2ENGINE_RUNTIME_SHADER_COMPILER` (off by default in the player, **on in the editor host**), call it with the same prelude and `#line`s, then the same reflection self-check (a small SPIR-V reader in C++) before `vkCreateShaderModule`. Size about +4-5 MB per binary [M]; licence: BSD-3-Clause with NVIDIA/Khronos/BSD-2/MIT/Apache notices (`vulkan-backend.md` §6, to add to `THIRD_PARTY_NOTICES.md` when linked); output is deterministic for a given glslang version [V on this PC], so a cache is keyed on the version | **offer as an option for players that opt in** (mods, user-generated content); cooked SPIR-V is what a normal game ships |
| Vulkan, macOS (MoltenVK) | Yes, same as desktop; glslang builds on macOS [M] | same | same; keep off by default |
| Vulkan, Android / iOS (MoltenVK) | Technically yes (glslang is plain C++), but +4-5 MB per ABI and every APK/IPA [M], and Apple/Google gain nothing | none in v1 | **cooked SPIR-V only** |
| WebGPU, web | **GLSL: no. WGSL: yes, natively** | `createShaderModule` takes WGSL strings and the browser compiles them; translating GLSL -> WGSL needs Tint or naga in the wasm, which the size budgets rule out (`webgpu-backend-design.md` §4.1 option D; wasm budgets `web/budgets.json`) | web ships **cooked WGSL**; hand-written WGSL is possible as an escape hatch (`"targets": {"webgpu": "authored"}` with a `#stage wgsl` section, Q4) which *is* compile-on-device by the browser |
| WebGPU native (Dawn) | not shipped (CI harness only, `cmake/DawnPrebuilt.cmake`) | | n/a |
| Software | n/a | falls back to unlit, one warning | as decided |

**Caching** (all advisory: a missing or corrupt cache entry means recompile, never an error): (1) *shader cache* `user://cache/shaders/<key>/` holding the compiled blob + manifest, `key = sha256(source bytes + prelude version + contract + compiler id/version + target)`, an integrity hash in the entry, written through a temp file and rename (the pattern `AssetMetadata.cpp:68` uses); a changed engine, prelude or compiler is simply a different key, and stale entries are pruned by size or age. (2) *Vulkan pipeline cache* (`VkPipelineCache`, serialised to `user://cache/vk-pipelines-<vendor>-<device>-<driver>.bin`, validated against `pipelineCacheUUID`; the header is checked before use) so first-use pipeline hitches happen once per driver. (3) *Pre-warm*: pipelines for a Material's likely `RenderState` combinations are created at load (the cache bounds the set), moving hitches out of gameplay; the browser does its own compile for WebGPU, so create-at-load applies there too. (4) *GL*: optionally `glGetProgramBinary` [M, needs `ARB_get_program_binary`, core in 4.1; the context is 3.3] later.

**Error handling, never a crash:** every stage returns `std::expected<Blob, ShaderDiagnostics>` where a diagnostic is `{file, line, column, severity, message}` parsed from glslang/Tint/driver output (the `#line` trick gives glslang's and the GL driver's errors the right file:line; Tint's messages carry WGSL positions that the cook maps back through the generated-line table [E]). Surfaces: the logger (`Logger::Error` with `res://` path:line, once per shader version), the editor log panel and `GetShaderInfo`, and the fallback (magenta in the editor, built-in unlit in a player, section 4). A compile failure of a Material's shader never stops the frame; a null `IShader*` is handled where `GpuCache` already handles a null built-in (`GpuCache.cpp:333-336`).

## 8. Security and robustness (g)
Shader sources in a pack or mod are **untrusted input to a driver**, so the engine treats them like any other untrusted file (the Vfs already bounds entry size and refuses path tricks, `Vfs.hpp:57-66`).
- **Size/shape limits before any compiler runs:** source <= 256 KiB, <= 20k lines, params <= 64 and block <= 256 bytes, <= 5 textures, <= 16 varyings, header JSON depth-limited; all fail with a diagnostic, not a crash.
- **Allow-list validation before the driver sees SPIR-V:** `spirv-val`, then the reflection pass: only Shader capability plus a small allow-list (no `Int64`, `StorageBuffer*`, image writes, atomics, `VulkanMemoryModel`), only set 0/1 and contract bindings, entry points and execution modes fixed. For GL the text is generated by us from a header and a stage; the author's text is scanned for `#extension` lines outside a short whitelist and for anything after `#version`.
- **Compilers are parsers of hostile text:** glslang and Tint are fuzzed upstream [M] but have had crashes; the cook runs them as separate processes (a crash is an error message, which `n2build` and the host already handle for other tools); the **runtime** glslang path is therefore only enabled by the opt-in build option and by a project setting (`rendering.runtimeShaderCompile`, default false in a player) and runs on a worker thread with a time budget and the input limits above. Process isolation of runtime compile (a helper executable) is possible but costs a second binary; recommended only if mods from untrusted sources are a goal [M].
- **GPU hangs and expensive shaders cannot be statically ruled out** (halting problem): a `while(true)` cannot be rejected soundly. Mitigations, in order of value: (a) the OS watchdog (Windows TDR, Linux driver timeouts) resets the device, which the engine must survive: Vulkan `VK_ERROR_DEVICE_LOST` is already handled (`_deviceLost`, `VulkanDraw.cpp:722,926,1059`) and WebGPU device loss recovery exists (G5, `webgpu-backend-design.md` status); user shaders must not make that path riskier, and the test suite gains a deliberately slow shader to exercise it on lavapipe (which is slow rather than hung: use a long bounded loop); (b) the lint **requires `for` loops with an integer-literal or `const` bound and rejects `while`/`do`** in the strict mode (a heuristic, not a proof; relaxed in editor-only mode) and the cook warns on a high static instruction count (`spirv-opt` statistics [M]); (c) Vulkan `robustBufferAccess` stays on for user pipelines (cheap, no storage buffers anyway), WebGPU is robust by spec; (d) a frame-time guard is the host's, not the shader's: out of scope.
- **Information leaks:** a shader reads only what the contract exposes (matrices, lights, five textures); it has no window to the filesystem or network; timing side channels via shaders are not in scope.
- Everything a **malicious pack** can do through a shader is therefore: waste GPU time, trigger a driver bug, or produce a wrong picture. The first two are the residual risk, as for any game that loads shaders from content.

## 9. Tests (h)
- **Cook tool** (node, `tools/n2shader/*.test.mjs`, the `n2build.test.mjs` pattern): header parsing and every rejection (bad type, duplicate name, `n2_` prefix, block > 256, > 5 textures, unknown `uses`), std140 offset computation against a table of hand-computed cases (vec3 + float packing, int/bool, vec4 alignment), prelude generation per target, `#line` mapping of an error to `file:line`, the lint (isnan, `gl_Position`, `while`), manifest determinism (same input, same bytes).

CI runs glslang -> spirv-val -> Tint -> naga on all; reflection equality (cook offsets == glslang reflection == the generated C++ layout) is asserted per file. Added to the existing `wgsl (Tint, naga)` job and `scripts/validate-wgsl.sh`.

- **Error-path tests**: a broken shader produces the diagnostic with the right `file:line` and the fallback material draws; a corrupt cache entry recompiles; a stale contract version recompiles or falls back; a hostile corpus (oversized, bad capability, unknown binding) is rejected before the driver, each with a precise message.

## 11. Open questions for the user, with a recommendation (j)
1. **Authoring subset.** Unrestricted GLSL 450 minus the contract's "not available" list, enforced mechanically, or a documented small subset? *Recommend the former* (the spike shows the common subset translates; three rules cover the gaps).
2. **Raw per-backend overrides** (hand-written WGSL for web, GLSL for GL) in v1? *Revised [R]: no raw overrides in v1* (the review's point: an authored-WGSL path is a second, untranslated path that bypasses the prelude, the 256-byte block and the contract checks). It moves to stage 9; the web ships cooked WGSL, and a shader Tint rejects is fixed in the source. GLSL overrides stay out (the GL path is already source).
3. **Fragment-only first or vertex too?** *Recommend fragment-only first* (section 3.3); reserve `#stage vertex`.
4. **Can a user shader take part in scene lighting?** *Yes, opt-in (`"uses": ["lighting"]`).* The Lighting block is already in every pipeline layout (section 2), so the cost is the lit-copy gate, the GL uniform names and the helper functions. A user PBR re-implementation is possible but the supported route is a shader that calls the prelude's light loop. No shadows (none exist).
5. **Compile on device by default?** *Recommend: cooked payloads always shipped (and see the stale/stripped case in section 7 [R]); runtime compile off in players by default, on in the editor host, an opt-in build option and project setting for desktop Vulkan;* web and mobile cooked only. If the user wants it on by default for desktop Vulkan, the cost is +4-5 MB per player [M] and the hostile-input surface of section 8.
6. **Where does the cook live?** *Node tool now (matches `n2build`, CI has node), C++ twin only with stage 7.* Alternative: write it in C++ against glslang from day one (one implementation, but glslang becomes a build dependency of the engine immediately and stage 1 gets about three times bigger).
7. **Error fallback.** *Magenta in the editor, built-in unlit in players.*
8. **Params limits.** 256-byte block, 5 textures, no arrays/matrices as params. *Recommend as stated, and say what is next [R]:* `mat3`/`mat4` params (UV transforms are a common need) are the first addition after v1, in stage 9, with their std140 rules; the 5-texture limit is the existing `kSamplerCount`, raising it changes every backend's layouts.
9. **Texture params vs the `AuxTexture` names.** The five slots are base + Emissive/Occlusion/Normal/MetallicRoughness (`IMaterial.hpp`); a user shader's slots are generic. *Recommend a generic `IMaterial::SetTextureSlot(i, tex)` that forwards to the existing two setters by default,* so no backend interface breaks. [R] Slot 0 is the base colour texture and the reserved name `baseColorTexture` maps to it, so slot 0 cannot also be an ordinary user texture param; user textures take slots 1-4 unless the shader does not use `baseColorTexture`.
10. **Post-processing / full-screen effects** are out of scope: they need a render-target pass model the renderer does not have (the effects proposal also stopped at fixed uniforms, `effects-design.md`). A later proposal would reuse `.n2shader` with a different contract (no PerDraw, a source-colour texture).
11. **Per-instance parameter overrides in scenes and prefabs.** Deferred to `prefab-overrides.md`; v1 has `.mat` params and runtime Lua instances. *Recommend deferral*, otherwise this proposal grows a serialization design.
12. **Which Tint binary does a user's machine get?** The cook runs at project build/pack time on the developer's machine (n2build/editor), so Tint (BSD-3, 7.6 MB on Windows) must be found or fetched there, pinned and hash-checked like `install-wgsl-validators.sh`, and listed in `THIRD_PARTY_NOTICES.md` as a build tool that is not shipped. *Recommend a pinned download by n2build's toolchain check (`toolchains.mjs`) rather than bundling it in the editor;* the alternative is bundling. [R] Decide this before stage 6, not after: the Dawn Windows archive is 119 MB for a 7.6 MB `tint.exe`, so the download must fetch only the binary (or a repackaged archive we host), hash-checked.

## 13. Review revisions (2026-11-17)
An independent review checked 38 of the [V] citations against master (33 held; the 5 stale ones are corrected inline and marked [R]) and found the design gaps below. It could not re-run the translation spike, so the tool-run results of section 1.2 stay as measured on this PC; the Linux Tint SPIR-V reader is covered by stage 0. Each item is a binding amendment to the section named.
1. **Shared material range (sections 2, 6.1, stage 2).** Corrected inline: `kMaterialBlockRange` is shared with WebGPU, the software and fake renderers and four parity/lighting tests. Built-ins keep 128; a user shader gets its own range, or stage 2 moves the whole constant and says so. Guard: the built-in goldens and the four tests named in section 2.
2. **Clip, y and `gl_FragCoord` (section 2.1, 3.4).** `n2_SetPosition` applies the z remap only; Vulkan and WebGPU use a flipped viewport instead of a y fix (`unlit.wgsl:14-17`), and the tint circle is given in rows counted down (`VulkanDraw.cpp:1168`), so `gl_FragCoord.y` differs between GL and Vulkan/WebGPU. Contract: raw `gl_FragCoord`, `gl_FrontFacing` and derivative-sign dependence are linted out; the prelude provides `n2_FragCoord()` (top-left origin on every target). A cross-backend golden covers it. The spike proved only that `gl_FragCoord` translates.
3. **No end-to-end test before stage 5 (section 10).** Stages 2-4 are tested from committed cooked fixtures only, since nothing reaches `CreateUserMaterial` before the engine asset path. Stage 5a's acceptance is a `.mat`-to-pixels golden on Vulkan, WebGPU and the software fallback. Stage 8 (`Image`, Sprite2D) cannot be tested sooner and is not claimed to be.
4. **`PipelineKey` repack (section 6.1).** `shader` occupies bits 0-7 and `depthTest` starts at bit 8, so widening it to 16 bits shifts every field. Stage 2 states the new layout; the guard is the existing pipeline-cache and parity tests, listed in the PR, plus a test that the built-in keys' pipelines are created identically.
5. **`ApplyUniforms` (section 4).** It writes the built-in names (`uAlbedo`, `uHasTexture`, `uAlphaCutoff`, ...), unknown to a user block (a once-per-name warning on Vulkan/WebGPU, silently ignored on GL). A material with a user shader bypasses it: it writes only the declared params, plus the reserved `baseColor`/`baseColorTexture` mapping, which reproduces the tint and the alpha-cutoff semantics for Sprite2D and `Image`.
6. **Sprite2D / `Image` on the software renderer (section 4, stage 8).** Both use `BlendCutOutBelow` because the software renderer cannot blend. A user shader falls back to built-in unlit there, which keeps the cut-out; saturation and flash are lost, as accepted. Stage 8 lists the cut-out and the `Image` golden churn as its risk.
7. **Tint and tooling (section 5.1, Q12).** Stage 0 (a one-hour CI probe) settles the Linux SPIR-V reader before stage 1. How the cook finds Tint on a developer machine is decided before stage 6.
8. **Runtime compile cases (section 7).** Added: a stripped-source pack whose cooked payload is for another contract has no way to recook, so it draws the built-in unlit fallback with one logged error; a shader cooked by an older toolchain is stale after an engine update only if the contract number changed (the compiler version alone does not invalidate a payload, it only changes the cache key); the cook binary and the embedded glslang must use identical flags and optimisation level or the stage-7 cross-check will not be byte-equal.
9. **Resource caps (section 8).** Added: at most 256 user shaders loaded and 4096 live pipelines (LRU-evicted, oldest unused first), a per-shader compile time budget, and a per-pack total; a hostile pack can otherwise grow pipelines as shaders x 3x2x2x3x3. Whether the Vulkan device enables `robustBufferAccess` was not checked and is verified in stage 2; the texel-fetch out-of-range behaviour is stated as clamp-to-zero per spec on WebGPU and as undefined-but-contained on Vulkan with robustness on.
10. **Determinism and replay (new).** Shaders and materials are render-only: nothing a shader computes can feed simulation, replication or the state hash. Lua `Material` instance state (stage 5b) is excluded from the rollback snapshot, the replication data and the golden-replay hashes, and the proposal's tests include a replay that sets a param every frame and checks the hash unchanged. The pipeline creation under the Vulkan mutex (`VulkanDraw.cpp:722`) is a frame-time concern only.
11. **GL is a third, unverified path (section 6.3, stage 4).** The GL text is generated from the same header; the cook cross-checks its uniform names against SPIR-V reflection (`spirv-cross --reflect`), since GL cannot run in CI. Row-major, std140 and the array-of-struct names (`uDirectionalLights[i].intensity`) are different on GL and are tested at text level.
12. **Internal contradictions fixed.** (a) Section 2.1 said matrices are exposed "as given" while 3.4 differs per target: the contract is that `n2_Model * v` means the same on every target (the prelude hides the layout). (b) The binding map differs per target (WebGPU samplers at 6-10); the contract names bindings as per-target tables, generated from `GpuShaderInterface.hpp`. (c) `state.queue` and `alphaMode` are hints: `QueueFor` keys on `IsBlended()`, so `"queue": "transparent"` has no effect unless the Material also blends; the manifest's `state.blend` therefore sets the material's alpha mode default.
13. **std140 per target (section 3.2, 9).** Offsets are checked against glslang reflection and additionally by a per-target test on the WebGPU WGSL (struct size rounds to 16; Tint's padded float-array element is the visible example), since equality with glslang's std140 does not imply equality with the WGSL layout.
14. **Hot reload (section 4).** Pipelines are keyed by shader id and were never evicted: a retired shader id releases its pipelines and ids are recycled.
15. **Packs (section 5.3).** The cooked GLSL 330 payload is readable source, so "strip sources" also omits it for packs that ask; the cook step writes sorted names and no timestamps, as `n2pack` is deterministic. The web size profile has little headroom (`wasm.brotli` limit 2,090,000 at the time of the review, measured 2,090,656 to 2,097,773 on joint PRs), so the stage-3 budget of 20 KB brotli is stated as unmeasured [E] and the first measurement decides whether a raise is needed.
16. **Editor protocol (stage 6).** `GetShaderInfo`, the `Shader` asset type and the magenta fallback need an editor-protocol minor bump, with the protocol docs and generated clients, as the Joint inspector's `visibleWhen` did (1.31.0).
**Stage plan and sizes.** Stage 2 is larger than estimated (shared constant, `PipelineKey` repack, descriptor cache key): about 1,200-1,500 lines. Stage 5 is split (5a asset/material/GpuCache, about 700 lines; 5b Lua `Material`, about 400). Stages 3 and 4 carry the end-to-end golden of item 3 for their backend.
**Still unverified after the review:** the Linux Dawn `tint` SPIR-V reader (stage 0); whether Vulkan device creation enables `robustBufferAccess`; the 20 KB web growth; GL behaviour on real drivers; `.github/workflows/tests.yml:2316-2344`, which the review could not open.

## 14. Stage 2 as built (Vulkan, 2026-11-18)
What the stage-2 PR did, and where it departs from the text above (the departures are decisions, each with its reason):
1. **API.** `Renderer::Common::UserShaderBlob` (`renderer/include/renderer/common/UserShader.hpp`: name, contract, block size, `usesLighting`, the declared params with std140 offsets, the Vulkan SPIR-V words), `IRenderer::CreateUserShader(const UserShaderBlob&)` and `CreateUserMaterial(IShader*, ITexture*)` (the default bodies log once and return null, so the software renderer, OpenGL, WebGPU and the test fakes need no change), and `IMaterial::SetTextureSlot(slot, texture)` (0 = `SetTexture`, 1-4 = `SetAuxTexture`; the generic slot setter of Q9). `DestroyShaderProgram` frees a user shader.
2. **Limits before the driver (section 8).** `ValidateUserShaderBlob` checks the contract, block <= 256, params <= 64, names, std140 alignment, bounds and overlap, texture slots, and the SPIR-V (magic, <= 256 KiB). `ReadFragmentVaryings` is the "small SPIR-V reader": it walks the module with every length checked, applies the capability allow-list of section 8, requires one fragment entry point and reads the entry point's input locations. Shaders <= 256 live, user pipelines <= 4096 (item 9 of section 13).
3. **Material range (item 1 of section 13).** Chosen: built-ins keep 128. `BlockMaterial` takes a layout provider (`MaterialLayout`, built from the blob, shared with the materials so they outlive the shader), its snapshot carries `blockBytes` (128, or the layout's range: the block rounded up to 16, at least 16), and the descriptor-set cache key gained the range (11 -> 12 words). Nothing is raised for the built-ins. The WebGPU backend copies `snapshot.blockBytes` instead of the array size (the array is now 256 bytes); no other WebGPU change.
4. **`PipelineKey` repack (item 4).** The shader field is 16 bits (bits 0-15) and the state bits moved up by 8 (depth test 16, depth write 17, cull 18-19, blend 20, additive 21, wireframe 22). The packed value is only a map key, never stored. Guard: the existing pipeline-cache tests, plus `GetPipelineKeyForTest` pinning the built-ins' ids (0, 1, 2) and the user ids (3 and up).
5. **The vertex stage is a family of 32 variants (not in the proposal).** The validation layer warns about a vertex output no fragment input reads and about an attribute no vertex shader reads, and the Vulkan tests fail on a warning. A user fragment stage reads any subset of the five varyings, so `user.vert` is compiled once per subset (`N2_OUT_UV`, `_COLOR`, `_WORLDPOS`, `_NORMAL`, `_TANGENT`; `renderer/CMakeLists.txt` writes `user_vert_spirv_table.h`), the backend picks the variant from the fragment's interface (`ReadFragmentVaryings`) and the pipeline's vertex input provides exactly the attributes that variant reads (`UserVertexAttributeMask`). Modules are made on first use and shared. It also saves interpolators.
6. **Lifetime (item 14).** `DestroyShaderProgram` retires the shader (its materials draw nothing); the next frame start waits for the device to go idle, destroys its pipelines and fragment module, recycles its id and forgets the failed-pipeline entries of that id. User pipelines record the frame tick they were last used; past the limit the frame start evicts the least recently used down to three quarters of it, and within a frame the cache refuses to grow past twice the limit.
7. **Lighting gate.** The per-frame lighting copy is keyed on the shader's `usesLighting` (the built-in lit shader keeps it), so a user shader with `"uses": ["lighting"]` reads the same block the lit shader does.
8. **Fixtures (section 10, stage 2).** `tests/renderer/fixtures/user-shaders/` holds five `.n2shader` sources and their cooked output (`scripts/cook-user-shader-fixtures.sh`, Vulkan target only, committed `.spv` as binary). `tools/n2shader/n2shader.test.mjs` fails when a committed manifest no longer matches its source (not a byte comparison of the SPIR-V, which depends on the glslang version). `tests/renderer/common/UserShaderFixture.hpp` is the manifest-to-blob mapping the engine's loader will have in stage 5.
9. **Not done here (as planned).** `robustBufferAccess` (item 9) was not changed or measured; the descriptor-range change is limited to user materials. No engine, Lua or `.mat` change (stage 5). The OpenGL prelude's `n2_TargetHeight` is still stage 4.

## 15. Stage 3 as built (WebGPU)
What the stage-3 PR did, and where it departs from the text above:
1. **API.** `UserShaderBlob` gained `fragmentWgsl` (the WGSL Tint wrote; entry point `main`). `ValidateUserShaderBlob(blob, UserShaderTarget)` checks the shared parameters (`ValidateUserShaderParams`, also what `MaterialLayout::FromUserShader` uses) and then the target's payload: for WebGPU non-empty text of at most 256 KiB with no NUL byte and an `@fragment` entry point (the device judges the rest). `WebGpuRenderer` implements `CreateUserShader`/`CreateUserMaterial`; `DestroyShaderProgram` frees a user shader.
2. **One vertex module, not 32 variants.** `renderer/shaders/webgpu/user.wgsl` writes the contract's five varyings always and the pipeline's vertex input provides all five attributes (the lit shader's set): WebGPU accepts a vertex output no fragment input reads and an attribute nothing reads, so the Vulkan validation-layer reason for the variants does not apply. `scripts/validate-wgsl.sh` validates it (entry `vs_main`).
3. **No wait on destroy.** WebGPU keeps objects alive for every recorded command, so `DestroyShaderProgram` releases the shader's pipelines at once and recycles its id (no device-idle wait, no retire-until-next-frame). User pipelines are bounded by `kMaxUserPipelines`; past it the least recently used are released down to three quarters (immediately when a pipeline is created, not at frame start).
4. **Material range.** The ring slot of the material block is `AlignUp(snapshot.blockBytes)` (128 for a built-in, the layout's up to 256 for a user shader), the bind group is cached per range, and the binding's size is the range. Built-in draws are byte-for-byte what they were.
5. **Async error capture.** Module creation and user pipeline creation run inside a validation error scope (`wgpuDevicePushErrorScope`/`PopErrorScope`), so a WGSL error is a logged refusal, never an uncaptured error. Natively the pop is waited for (5 s at most): `CreateUserShader` returns null for WGSL the device rejects, and a pipeline that does not fit the layout becomes a remembered failure. In the browser there is no blocking wait: the verdict arrives later and is kept on the shader (`WebGpuShader::check`); a rejected shader's draws are skipped from then on.
6. **Lighting gate and defaults.** The per-frame lighting copy is keyed on the shader's `usesLighting`; an unset texture slot reads the manifest's default (white, black, flat normal, transparent) from the renderer's existing 1x1 textures.
7. **Fixtures and goldens.** The five fixtures are now also cooked for WebGPU (`shader.webgpu.wgsl`, `scripts/cook-user-shader-fixtures.sh`; the Vulkan SPIR-V did not change). `WebGpuRendererUserShaderTests.cpp` mirrors `VulkanUserShaderTests.cpp` with the same fixtures and the same exact expected colours, which is the comparison with Vulkan: the two backends are asserted to produce the same pixels for each fixture (`webgpu_tests` does not link the Vulkan renderer, so there is no in-process image diff). It adds the transpose-twice trap (a translation through the model matrix), a rejected WGSL, and WGSL that does not fit the pipeline layout.
8. **Not done here.** The fixtures' `naga` validation ran on CI only (the local cook had Tint but not naga). Safari's WGSL compiler is unchecked.


## 16. Stage 4 as built (OpenGL)
What the stage-4 PR did, and where it departs from the text above. OpenGL cannot run in CI, so everything below is verified as text; the visual check is yours (the checklist at the end).
1. **API.** `UserShaderBlob::fragmentGlsl` (the cook's `shader.gl.frag`, GLSL 330 core text), `UserShaderTarget::OpenGl`, and `OpenGLRenderer::CreateUserShader`/`CreateUserMaterial`. `UserGl::ValidateFragmentSource` refuses text before a driver sees it: empty, over 256 KiB, a NUL byte, not starting with `#version 330 core`, a second `#version`, any `#extension`, no `main`.

4. **Lighting.** One function (`SetLightingUniforms`) sets the built-in lit shader's and every user shader's lighting uniforms; the names differ in the spelling only (`n2_EncodeOutputFlag` for the flag the Vulkan and WebGPU blocks call `n2_EncodeOutput`). A shader made after the last `UpdateSceneLighting` gets that lighting at creation. The flag is 1 whenever linear lighting is on: nothing but the shader encodes its output (the framebuffer's sRGB encode is on for the lit shader only).
5. **Materials.** An `OpenGLMaterial` of a user shader starts at the manifest defaults, accepts only the declared names and types (a wrong one warns once and is ignored, as on Vulkan/WebGPU), sets `n2_tex<slot>` to unit `<slot>` and binds the slot's texture (slot 0 the base texture, 1-4 the AuxTexture slots) or the manifest's default (white, black, flat normal, transparent) when the slot is unset or its texture was destroyed. A user program does not warn about a uniform the compiler left out. The material of a destroyed shader draws nothing.
6. **Cook cross-check (section 13, item 11).** `tools/n2shader` compares the plain uniforms the GL text declares with the members glslang reflected from the Vulkan SPIR-V of the same shader (PerDraw, Lighting when used, Material, plus `n2_TargetHeight` and one `sampler2D` per texture), names and types, both ways; the manifest records `gl-uniforms` among the GL target's passed stages. The fixtures now carry `shader.gl.frag`, compared byte for byte (the GL text is generated, not tool output).
7. **Not done here.** Nothing of the Electron frontend. The GL fixtures were not compiled by a driver in CI.

**What to check on a GPU PC (OpenGL).** Build the player/editor with OpenGL, then, with a scene using `CreateUserShader` through a small test harness (stage 5 adds the engine path; until then it is the renderer API) or by running `tests/renderer` fixtures through `CreateUserShader`:
- each of the five fixtures compiles and links with no driver log (watch stderr; a driver error cites the author's line as source string 1);
- `solid`: a full quad is red; setting `u_Color`/`u_Offset`/`u_Flag`/`u_Gain` changes it as the Vulkan test expects (green plus blue offset gives cyan; the flag inverts);
- `textured`: with no texture the tint shows, with a texture in slot 0 it multiplies, slot 1 adds, slot 2 supplies the alpha (flat normal red 0.5 gives 128);

## 17. Stage 5a as built (engine asset, Material, GpuCache)
What the stage-5a PR did, and where it departs from the text above:
1. **`Shader` asset** (`engine/include/engine/rendering/Shader.hpp`): the `.n2shader` file's header (name, parameters with defaults/min/max/label, `uses`, state hints) read in C++ with the same texture-slot rule as the cook (the reserved `baseColorTexture` takes slot 0, the others follow in declaration order). `ResourceTypeFor` gives `"Shader"`, the loader is registered with the others, `.meta` files work as for any asset, and every `Load` bumps `GetVersion`. `ResourceLoader::GetMetadataRoot()` is new (the folder of `.import/`).
2. **Cooked payload, not cooked here.** `Shader::MakeBlob(target)` reads `.import/shaders/<uuid>/manifest.json` and the payload of the backend and returns the `UserShaderBlob`; `SetCookedDirectory` overrides the folder (tests, mods). The payload must match the header (same parameter names and types in the same order, same `uses`): a shader edited since it was cooked is reported stale and not used. Producing `.import/shaders/` for a project is stage 6 (the n2build stage and the editor's cook on save), so until then a project's shaders have no payload and draw with the fallback.
3. **Renderer API additions.** `IRenderer::GetUserShaderTarget()` (nothing by default and for the software renderer; Vulkan, WebGPU and OpenGL answer) and `IMaterial::IsUserShaderMaterial()` (so `Material::ApplyUniforms` writes the declared parameters to a user material and the unlit uniforms to the fallback).
4. **Material.** `SetShader`, typed `SetFloat/SetInt/SetVec2/3/4/SetColor/SetTexture(name, ...)` (false and one warning per name for an unknown name, a mistyped setter or no shader; numbers clamp to the declared min/max), `GetParam`, and the `.mat` keys `"shader"` and `"params"`. `"params"` is applied after the rest of the file (a JSON object's keys come out sorted, and the shader says which names exist). `ToJson` writes the two keys only when a shader is set, so every existing `.mat` reads and writes exactly what it did (a test pins the key set and the bytes). The shader's `state.blend` ("alpha"/"additive") and `state.cull` ("none") are the defaults of `alphaMode` and `doubleSided` when the `.mat` does not say. A texture parameter or a shader change makes a new GPU material; the other setters are uniforms.
5. **GpuCache.** A new `ResourceKind::Shader` (one `CreateUserShader` per renderer, shader and shader version; destroyed with the last material that uses it, after that material). A material with a shader gets `CreateUserMaterial` with its textures in their slots (`baseColorTexture` takes the material's own base texture unless the `.mat` sets it; user textures are never sRGB-decoded), and `ApplyUniforms` writes the declared parameters, with the reserved `baseColor` defaulting to the material's base colour times the draw's tint. `MaterialVersion` carries 30 bits of the shader's version (bits 32-61), so a reloaded shader remakes its materials. A material without a shader takes none of the new code (`GetShader() == nullptr`): its keys, calls and uniforms are what they were, and a test pins it.
6. **Fallback.** Where the shader cannot be drawn (the backend has no user shaders, not cooked, stale, no payload for the backend, or the renderer refuses the shader or the material) the material gets the built-in unlit shader with its base colour and texture and one logged error per shader and version naming the shader (its file when it was loaded) and the reason. `RenderSettings::SetUserShaderErrorStyle(Magenta)` makes the fallback flat magenta; the editor host that edits sets it (a `--play` child keeps the unlit style). The software renderer needs no change: it answers "no user shaders" and draws the fallback.
7. **Acceptance (section 13 item 3).** A `.mat` in a temporary project, with the fixtures cooked into `.import/shaders/<uuid>/`, drawn by `Scene::Render` on a built-in quad: Vulkan (`VulkanUserShaderMatGoldenTests.cpp`), WebGPU (`WebGpuRendererUserShaderMatGoldenTests.cpp`, the same expected colours) and the software renderer (`UserShaderMaterialTests.cpp`, the unlit fallback with one warning, magenta in the editor style). The Vulkan and WebGPU tests also set a parameter between frames and a texture parameter at runtime.
8. **Not done here.** `Sprite2D`/`UI Image`/particles (stage 8), the Lua `Material` (stage 5b), cooking and the editor's `GetShaderInfo` (stage 6), hot reload of a changed `.n2shader` on save (stage 6; a reload that goes through `Shader::Load` already invalidates the GPU materials).

## 18. Stage 6 as built (packs and editor)

When no Tint is found (`TINT`, `PATH`, the copy in `%APPDATA%/N2Engine/tools` or `~/.local/share/n2engine/tools`) n2build streams the release archive, takes `bin/tint` and stops reading (the Windows archive is 119 MB, the exe 7.6 MB), keeps it only if its hash is the pin, and sets `TINT`. Only the web target needs it (WGSL). `THIRD_PARTY_NOTICES.md` lists it under "Not shipped". The editor host never downloads: it uses what it finds.
2. **n2build cook stage** (`tools/n2build/lib/shaders.mjs`, called by `cookPack`): each `.n2shader` under `assets/` is cooked with `cookShader` into `.import/shaders/<uuid>/` (the uuid from `.import/<path under assets/>.meta`; no `.meta` is an error asking for one editor session), the same bytes `n2shader cook` writes, sorted, no timestamps; whatever `.import/shaders/` held on disk is replaced. Payloads per package kind: desktop `vulkan`+`gl`, web `webgpu`, android and ios `vulkan` (a descriptor's `shaderTargets` overrides). Missing glslang, spirv-val, spirv-dis or spirv-cross (and Tint for web) is an error naming what to install, not a pack without payloads. `--strip-shader-sources` (or `build.targets.<T>.stripShaderSources`) keeps each file's header and an empty `#stage fragment`, and leaves the GL payload out. A `--pack folder` build copies the folder as it is.
3. **Editor protocol 1.32.0** (MINOR, additive): `GetShaderInfo` (0xB5, read) answers `ShaderInfo` (0x28): name, usesLighting, state hints, params (type, default, slot, label, min, max) and `cook {status: cooked|not-cooked|stale|failed|unavailable, targets, diagnostics, message?}`; the `shaders` capability; `.n2shader` in the `ReadTextAsset`/`WriteTextAsset` whitelist; `ListAssets` already reports type `Shader`. Clients regenerated (C++, C#, TypeScript), golden vectors, spec tests.
4. **Cook on save and hot reload** (`EditorServer::CookShaderAsset`): `ApplyAssetChanges` (reached by `WriteTextAsset` and the file watcher) cooks added and modified `.n2shader` files before the assets are reloaded, for the renderer the host draws with (only a check when it has none), by running `node tools/n2shader/n2shader.mjs cook ... --cite assets/x.n2shader --require-payload` as a child process (`editor-server/src/ShaderCook.cpp`: Node through `N2ENGINE_NODE` or `PATH`, the script through `N2SHADER_TOOL` or a `tools/n2shader` above the executable; 60 s limit; the cook runs on the main thread, so a save blocks the host for the cook's second or so). `ReloadLoadedAsset` reloads a held `Shader` **in place** (`Shader::Load` bumps its version, which remakes the Materials that use it); before this the generic reload dropped it from the cache and the Materials kept the old object. New CLI options: `--cite` (the path a diagnostic and `#line` cite) and `--require-payload` (a skipped stage that would leave a payload out is an error; naga's is not).
5. **Not done here.** The editor's Node dependency is a stand-in until stage 7 (compile on device); a host started without Node shows `unavailable` and the magenta fallback. Nothing of the Electron frontend. The Inspector UI for a Material's shader params is the frontend's.

## 19. Stage 7 as built (compile on device, desktop)
What the stage-7 PR did, and where it departs from the text above:
1. **`N2ENGINE_RUNTIME_SHADER_COMPILER`** (root `CMakeLists.txt`, default OFF; desktop only, a FATAL_ERROR on web, Android and iOS) pulls glslang **15.3.0** through `cmake/Glslang.cmake` (the GitHub source archive, SHA-256 `c6c21fe1...4201`, `N2Download.cmake` retries and the CI download cache) and links `glslang`, `SPIRV` and `glslang-default-resource-limits` into the engine (`ENABLE_OPT=OFF`: no SPIRV-Tools, no HLSL, no tools). 15.3.0 is the version that cooked the committed fixtures, so the cross-check can compare bytes. One CI leg (Linux x86_64 Clang) builds with it ON. "Off in players, on in the editor host" is run time, not link time: the option is build-wide, the editor host calls `RenderSettings::SetRuntimeShaderCompile(true)` and the project setting `rendering.runtimeShaderCompile` (false/true; absent leaves the host's choice) overrides it.
2. **The C++ twin** (`engine/rendering/UserShaderCompiler.hpp`): `BuildSource` is `prelude.mjs` ported line for line (the templates are embedded at configure time as `UserShaderPrelude.inc`; `//@include`, `//@if-lighting`, `//@each-texture`, the std140 Material block, the `#line`), `Compile` runs glslang with the cook's flags (`-V --target-env vulkan1.1 -S frag`: Vulkan client semantics 100, Vulkan 1.1, SPIR-V 1.3, no optimizer) and checks glslang's reflection of the `Material` block (size, each member's offset) against the layout the header implies, then writes a manifest in the cook's schema (`runtimeCompiled: true`). Verified before this PR on the author's PC with a local glslang 15.3.0 build: the SPIR-V of all five fixtures is **byte-identical** to the committed cook output, and `CompilerId()` prints `Glslang Version: 11:15.3.0` like `glslangValidator --version`. OpenGL needs no compiler: its payload is the generated text, always available (section 7), equal byte for byte to the fixtures' `shader.gl.frag`.
3. **`Shader::MakeBlob`** = the cooked data (`MakeCookedBlob`, the old body, now through `BlobFromManifest`) and then `MakeRuntimeBlob` when that fails (not cooked, stale, no payload for the backend, another contract). Vulkan needs the linked compiler and the setting; a pack with stripped sources has nothing to build from; WebGPU never (Tint is not linked). The error that reaches GpuCache's one logged line names both reasons. `GetShaderInfo` keeps asking the cooked path only, so its `cook` state still says what the cook did.
4. **Shader cache** (`RenderSettings::SetShaderCacheDirectory`, set by `ResourceLoader::Initialize` to `user://cache/shaders`): one folder per key (`sha256` of the file text, a digest of the embedded prelude, the contract, the compiler id and the target), holding `manifest.json` and the payload, written through a temporary file and renamed, used only when the payload hashes to what its manifest says, pruned past 256 entries.
5. **Vulkan pipeline cache** (`renderer/common/PipelineCache.hpp`, `VulkanRenderer::EnsurePipelineCacheLocked`): a `VkPipelineCache` made on the first pipeline, passed to every `vkCreateGraphicsPipelines`, saved at shutdown to `user://cache/vk-pipelines-<vendor>-<device>.bin` and read back only when the 32-byte header names this vendor, device and `pipelineCacheUUID` (at most 64 MiB). The folder is set by `ResourceLoader::Initialize`; without one the cache lives for the session.
6. **Not done, and said so:** pre-warming a Material's likely pipelines at load (the cache bounds the set; the hitch is once per driver now); the cook's lint on the device (an authoring aid: the defence is the size limits and `ValidateUserShaderBlob`); a worker thread, a time limit or a helper process for glslang (it runs on the first draw's thread; the option is off by default for that reason); WGSL; `THIRD_PARTY_NOTICES.md` carries glslang's entry (a binary that links it must carry glslang's `LICENSE.txt`).
## 20. Stage 8 as built (Sprite2D, UI Image, particles, author docs)
What the stage-8 PR did, and where it departs from the text above:
1. **`UserShaderSlot`** (`engine/rendering/UserShaderSlot.hpp`): what a component with no Material of its own keeps to draw with a user shader: the `Shader` asset and a PRIVATE `Material` (unlit shading, Blend, double-sided) holding the shader and its parameter values, plus a `GpuCache::Handle` for the components that draw a raw mesh of their own. `SetShader(nullptr)` forgets the values; the same shader again keeps them; two slots of one shader never share values. `Sync` gives the Material the draw's inputs (the component's texture as the reserved `baseColorTexture`, the software cut-out) and sets each only when it changed. `Prepare` returns the GPU material (`GpuCache::AcquireMaterial` for the Material's current version) with `Material::ApplyUniforms(gpu, tint)` applied.
2. **Sprite2D** (`SetShader`, `SetShaderParam` for a float, vec2, vec3, Color or texture, `SetShaderInt`, `SetShaderVec4`, `GetShaderMaterial`): `EnsureMaterial` returns the slot's Material when a shader is set, so the existing `DrawResources` path (GpuCache material, `ApplyUniforms`, `StateFor`) draws it unchanged; without a shader the built-in path is byte-for-byte the old one.
3. **UI Image** (same API): the golden-churn risk of the proposal was avoided by not refactoring `Image::RenderUI`: with a shader (and no raw `SetTexture` texture, which is not an asset a Material can hold) it draws its own quad with the slot's GPU material; without one the code that ran before runs. No UI golden moved.
4. **ParticleSystem** (same API): the billboards are one dynamic mesh in one draw, so one Material serves every particle; the per-particle colour reaches the shader as `n2_Color`, and the system keeps its blend mode and two-sided quads. The standard material is the fallback when the renderer cannot make the shader's.
5. **Lua** (`Sprite2D`, `Image`, `ParticleSystem`): `SetShader(path|nil)`, `GetShader()`, and `GetMaterialInstance()`, the `MaterialInstance` type of stage 5b on the component's private Material (nil without a shader), so `SetFloat/SetColor/SetVec4/SetTexture` need no second API. `engine-api.lua` documents them.
6. **Render-only, as section 13 item 10 requires:** none of it is a serialized field (a test pins that a Sprite2D's saved JSON has no shader key, so every scene file reads and writes what it did), so it cannot reach a rollback snapshot, replication or a replay hash. Per-instance values in scenes and prefabs stay with `prefab-overrides.md` (Q11).
7. **Saturation and flash are not applied through a user shader** (they are the built-in shaders' uniforms; section 13 item 6 accepted the loss). The software renderer draws the unlit fallback with the cut-out kept, which the tests pin for Sprite2D and Image.
8. **Docs:** `docs/user-shaders.html` (the author's page: the file, parameters, the prelude names, what is refused and the limits, using a shader, the fallback), sections in `sprite2d.html`, `ui.html` and `particles.html`; the sidebar of every page links it.
9. **Not done:** GPU pixel goldens for the components (the Material-level Vulkan and WebGPU goldens of stage 5a cover the same Material; the components hand it over unchanged); a scene field for a component's shader; the Image on a raw texture.

## 22. Stage 9b as built (`isnan` and `isinf`)
1. **Shims, not a lint:** `isnan` and `isinf` are no longer in the cook's banned list. WGSL cannot represent NaN or infinity, so Tint and naga still refuse the built-ins; `renderer/shaders/user/prelude/nan-shims.glsl` defines `n2_isnan` and `n2_isinf` (float, vec2, vec3, vec4; the vector forms return a `bvec`) as tests of the IEEE bit pattern (`floatBitsToUint`), and two function-like macros `isnan(x)` and `isinf(x)` expand to them, so the author writes the built-in's name. Checked with the real glslang and Tint: the WGSL is `bitcast<u32>` tests.
2. **Included only when used:** the text follows the target's prelude (before the Material block, so the `#line` of the author's first line is still right) only when the stage names `isnan` or `isinf` as a whole word. The cook (`usesNanChecks`, a plain word search) and the C++ twin (`UsesNanChecks`) use the same rule, so every shader that uses neither keeps byte-for-byte the text, SPIR-V and WGSL it had: no fixture, manifest or committed payload changed, and the contract number stays 1 (the change only adds names). The cache key already includes the digest of every embedded template, and `nan-shims.glsl` is in the engine's embedded list (`engine/CMakeLists.txt`).
3. **Caveat, documented in the author page:** a GPU compiler may assume values are finite and fold the test away; the shim reports what the bits of the computed value are.
4. **Corpus and tests:** the old negative `negative-isnan` is now the positive `nan-checks`; the node tests cover acceptance by the lint, the shim text in all three targets, the unchanged text of a shader without them, the whole-word rule, a Tint cook (where Tint is installed); a C++ test builds the source for all three targets with and without them. Not verified: a GL or browser pixel with a NaN.
