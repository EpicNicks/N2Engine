Status: research only, no engine changes. Written 2026-11-16 against `master` at `2b3b3a74`. PhysX headers: `external/PhysX/physx/include/` (5.6.1). Web sources were fetched on the date above; where a page could not be read in full or only a search summary was available, the row says so.

## 0. What changed since the first-pass report (read this first)

The issue text and the first-pass report were written when PhysX was the only backend. At `2b3b3a74` that is no longer true:

1. **A second 3D backend exists: Jolt.** Jolt Physics v5.6.0 is vendored (`external/JoltPhysics`, `docs/physics.html:353`), built always with `JPH_CROSS_PLATFORM_DETERMINISTIC` (`cmake/jolt/CMakeLists.txt:21`, FMA off at `:63`) and wrapped as `JoltBackend` (`engine/src/physics/jolt/JoltBackend.cpp`, about 4,000 lines; `engine/include/engine/physics/jolt/JoltBackend.hpp`). Option `N2ENGINE_USE_JOLT` defaults OFF (`CMakeLists.txt:34`); Android and Apple builds force PhysX off and Jolt on (`cmake/N2EngineAndroid.cmake:17,20`, `cmake/N2EngineApple.cmake:13,100`). The project setting `physics.backend` picks `physx` or `jolt` (`engine/include/engine/physics/PhysicsBackendKind.hpp`).
2. **Backends now declare determinism and snapshot support** through `IPhysicsBackend` (`engine/include/engine/physics/IPhysicsBackend.hpp:65` `GetDeterminism()` None < SameBinary < CrossPlatform, `:67` `SupportsSnapshot()`, `:100-101` `SaveState`/`RestoreState`). PhysX declares at most `SameBinary` (`PhysXBackend.hpp:99-102`) and `kSupportsSnapshot = false`, `kSupportsSetState = true` (`PhysXBackend.hpp:105-108`). Jolt returns `CrossPlatform` only with a single-threaded job system and an `N2_STRICT_FP` build, else `SameBinary` or `None` (`JoltBackend.cpp:2925-2940`) and has `SupportsSnapshot` true (`JoltBackend.hpp:97-99`, `SaveState` at `JoltBackend.cpp:3793`). The Deterministic network preset is therefore no longer "disabled for lack of any backend"; it needs Jolt plus strict FP (`docs/physics.html:321`).
3. **PhysX has an engine determinism option.** `physics.deterministic` sets `eENABLE_ENHANCED_DETERMINISM`, 0 worker threads and forces the CPU scene (`PhysXBackend.cpp:636-665`, GPU override with a warning at `:548-554`). The first-pass claim "engine does NOT set the enhanced flag" and "4 worker threads fixed" is outdated: 4 is the default, 0 when deterministic (`PhysXBackend.cpp:643`).
4. **2D physics exists.** Box2D v3.2.0 is vendored (`external/box2d`, option `N2ENGINE_USE_BOX2D` default ON, `CMakeLists.txt:38,402-404`) with `engine/src/physics2d/` (`Physics2DWorld.cpp`, `Rigidbody2D.cpp`, `Collider2D.cpp`, `ContactTracker2D.cpp`) and Lua bindings (`engine/src/scripting/bindings/LuaPhysics2DBindings.cpp`). Design: `orchestrator/proposals/physics2d-box2d-design.md`, `docs/physics2d.html`.
5. **PhysX builds for the web.** `cmake/PhysXWeb.cmake` builds PhysX 5.6.1 from source for wasm32 as CPU-only, single-threaded static libs (about 14 MB of archives, `external/PhysX/physx/bin/emscripten.wasm32`, `docs/web-build.html:139,354-358`). It adds about 770 KB brotli to the `size` profile (`docs/web-build.html:432`).
6. **Gameplay netcode exists** or is designed in detail (`orchestrator/proposals/netcode-runtime-design.md`, `docs/netcode.html`), including the three presets, startup validation and a cross-leg determinism CI job for Jolt (`docs/physics.html:588-597`: equal hashes on five builds, three compilers, x86_64, arm64 and wasm, for ten scenes, single-threaded job system).
7. **Measured PhysX numbers exist** (`physx-determinism-measured-numbers.md`: same-binary bit-identical, cross-platform hashes differ in every scene including single-sphere free fall).

Net effect on the issue: the table below is about "PhysX vs a second/custom engine", and the second engine partly exists. The question for #156 is no longer "build our own?" but "what does Jolt (3D) and Box2D (2D) still not give us?".

## 2. What is left that PhysX cannot do and the existing alternatives can

Remaining real gaps for a networked game after Jolt and Box2D landed:
- Bit-exact cross-platform 3D simulation (Jolt, with caveats below), whole-world rollback snapshot (Jolt).
- Fixed-point simulation: nobody in the tree provides it; only needed if strict-float is judged too fragile.
- Jolt's own caveats the engine must keep honouring (section 3): single-threaded job system, same source and defines everywhere, no platform `std::sort`/`std::hash`/trig in the simulation, creation order, no body add/remove inside a rollback window, `SaveState` does not capture non-step state such as changed friction.
- Jolt is "less tested" for cross-platform than its other features, per its own documentation [V web].

PhysX remains the right backend for the server-authoritative preset (set-state plus reconciliation), for GPU particles and soft bodies, and for the established default.

How lockstep/rollback vs server-authoritative games use physics (from the sources above plus well-known practice [M] where marked): lockstep and rollback (GGPO-style fighters, Quantum, RTS) need bit-identical simulation, serializable state and either fixed-point or strictly controlled IEEE floats, so they use custom or specially built engines (Quantum's FP, Jolt/Box2D/Rapier strict modes). Server-authoritative games (Unity Netcode, Unreal Resimulation, Rocket League per secondary sources) keep a normal engine on both sides, need only set-state/history and tolerate drift by correcting. Source's multiplayer model and Overwatch [M] are the same family. Snapshot interpolation is for remote or cosmetic bodies and needs nothing from the engine.

## 4. Findings in one place

1. The issue's table has aged: web, 2D, platform reach, and (for 3D deterministic play) determinism and snapshot are now answered in-tree by wasm PhysX, Box2D v3 and Jolt.
2. The two limitations that are still real for PhysX are **cross-platform determinism** and **whole-scene snapshot/restore**. Both are structural to PhysX (a closed solver state, no platform promise), and both are what Jolt's `CrossPlatform` mode plus `SaveState` give.
3. **Threading and GPU** are configuration, not a limitation: `physics.deterministic` already turns off workers and forces CPU.
4. **Size** is real but small relative to the whole (about 770 KB brotli on web, large native archives and a download pipeline).
5. A custom physics engine is only justified now by fixed-point (Quantum style), a smaller deterministic 3D-only footprint, or a gap Jolt shows when its determinism CI meets real scenes. #156 should treat Jolt as the baseline.
