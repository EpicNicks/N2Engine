## How the pipeline works (tools in orchestrator/tools/)
- Item = `items/<name>.json` (repo engine|frontend, branch, title, issue text = the developer's plan, allowedPaths regexes, acceptance, requiresDocs, allowProtocol, gate, approved, reviewer). Edit item JSON ONLY with a small script FILE (never `node -e` with backticks/quotes: a failed edit once let me launch unapproved items). Set `approved:true, gate:null`, then ALWAYS `cd orchestrator && node lib/brief.mjs <item>` and check it prints `{"ok":true}` BEFORE launching.
- Launch: Workflow tool with `scriptPath: "orchestrator/tools/orchestrate-items-workflow.js"` and `args: {items: [{name, reviewer}]}` (reviewer opus for security/concurrency/Lua/protocol; sonnet is fine for small harness items). Per item it runs developer -> CI wait + fresh reviewer -> up to 2 fix rounds -> ratify. The ratify runner agent usually REFUSES to merge (auto-mode classifier): that is fine, Claude merges itself.
- Workflow "held / still failing after 2 fix rounds / deviations" notes are often STALE ledger artifacts: always check the real PR head (`api repos/EpicNicks/N2Engine/pulls/<n> --jq .head.sha`), its check-runs (`commits/<sha>/check-runs`), `ledger/<item>/review.json` head vs PR head, and `ledger/<item>/dev.json` (pr, head, deviations). To fix a PR: resume the earlier fixer with SendMessage when it exists, else a fresh opus Agent given the ledger brief + review.json.
- CI polling: copy `tools/poll-template.sh`, sed the SHA (it sleeps 20 min, then polls every 4 min; finishes when nothing is in_progress/queued and >=9 completed, or on any failure), run it in the background. For a failed leg: annotations (`check-runs/<id>/annotations`), `actions/jobs/<id>` step names, then logs only for that leg. Exit code 100 in "Install build dependencies" = transient apt: `POST actions/runs/<run>/rerun-failed-jobs` (only when the run is complete).
- review.json must be of the CURRENT head for ratify: after update-branch/master merges run a cheap sonnet "merge-only re-confirm" agent that checks the delta is master-sourced and writes review.json with the new head.
- Merge: `cd orchestrator && node lib/ratify.mjs <item> --merge` (prints `{decision, reasons, relaxed?, merged}`), or, after the user accepted the deviations, `node tools/accept.js <item> <engine|frontend> <pr>` (needs `ledger/<item>/pr-body.md`; if missing: `api repos/EpicNicks/N2Engine/pulls/<n> --jq .body > that file`; it records the deviations as user-accepted in the PR body, clears them in dev.json, then runs ratify --merge; if ratify holds on allowedPaths, add the regex to the item's allowedPaths with a script file). `node tools/sethead.js <item> <sha>` updates dev.json's head after a push.
