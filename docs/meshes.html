Meshes, models & textures

Textures reach the screen through a Material or the UI Image sprite PR #64.

The assetimport library PR #64

assetimport/ is a static library (N2Engine::assetimport) that turns file bytes into plain CPU structs. It decodes images (assetimport/include/assetimport/ImageDecoder.hpp) and, since P3 PR #TBD, parses glTF models (ModelImporter.hpp, GltfImporter.hpp; see Models). It depends only on math and its vendored parsers, never on the engine, the renderer, GLFW, PhysX or nlohmann. The engine links it privately: no assetimport type appears in an engine header, and no stb or cgltf type appears in an assetimport header.

stb_image 2.30 (external/stb_image/, see THIRD_PARTY_NOTICES.md) is compiled once, in assetimport/src/assetimport/ImageDecoder.cpp, with STB_IMAGE_STATIC so its symbols stay in that file. It is configured there: STBI_ONLY_PNG, STBI_ONLY_JPEG, STBI_ONLY_TGA, STBI_ONLY_BMP (PSD, GIF, HDR, PIC and PNM are left out), STBI_NO_STDIO (the engine reads files itself and decodes from memory), STBI_NO_LINEAR, STBI_MAX_DIMENSIONS 16384, and STBI_ASSERT a no-op in Release builds (stb's own assert in Debug).

Source: assetimport/CMakeLists.txt; assetimport/src/assetimport/ImageDecoder.cpp; external/stb_image/README.md

Design decision: asset import is its own CPU-only library PR #64

Parsers are where untrusted bytes meet the engine, so they need the most tests, and those tests should run anywhere. Putting image decoding (and later glTF and FBX parsing) in a library that depends only on math, as text/ does for fonts, lets assetimport_tests run every decoder without the engine, a window, a GPU or PhysX. Its output is library-neutral structs (ImportedImage), so a decoder can be swapped or a second one added (ufbx beside cgltf) without touching the engine. Decided on #3 (decision 3).

Image decoding PR #64

AssetImport::DecodeImage(std::span<const std::uint8_t> bytes, const ImageDecodeOptions &options) returns std::expected<ImportedImage, ImageDecodeError>.

  • Formats. PNG (1 to 16 bits per channel, every colour type, palette with or without tRNS, interlaced), JPEG (baseline and progressive), TGA (with or without RLE) and BMP (bottom-up and top-down, 1 to 32 bits per pixel). The decoder goes by the content, not the file name.
  • Always 8-bit RGBA. ImportedImage has width, height, channels (always 4), sourceChannels (what the file held: 1 grey, 2 grey + alpha, 3 RGB, 4 RGBA) and pixels, width × height × 4 bytes, rows tightly packed. Grey becomes (g, g, g, 255), so a grey PNG shows grey rather than red as an R8 texture would. Missing alpha is 255. 16-bit channels keep their high byte.
  • Row order. With options.flipY (the default) the bottom row of the picture comes first; without it the top row does. See the UV convention.
  • Size caps. The header is read first (stbi_info_from_memory), and nothing is decoded or allocated for an image wider or taller than kMaxImageDimension (16384), or whose RGBA pixels would exceed kMaxDecodedImageBytes (256 MiB: an 8192 × 8192 image fits, 8192 × 8193 doesn't). ImageDecodeOptions::maxDimension and maxDecodedBytes lower the caps for one call; values above the built-in caps are lowered to them. Decoding can briefly need more memory than the cap (stb's working buffers, about twice it for a 16-bit PNG). Input over 2 GiB is refused, since the decoder takes an int length.
  • Errors. An error has a code and a message for the log: EmptyInput; InputTooLarge; UnrecognizedFormat (not one of the four formats, or a corrupt or truncated header; stb's reason is in the message); DimensionsTooLarge (a side over the cap, or zero); DecodedSizeTooLarge; DecodeFailed (a readable header but corrupt, truncated or unsupported pixel data). A PNG or JPEG header over 16384 a side is refused by stb itself while it reads the header, so it reports UnrecognizedFormat with stb's "too large"; oversized TGA and BMP headers report DimensionsTooLarge. Either way nothing is decoded.
  • Thread-safe. No global decoder state is set (stb's failure reason is thread-local, and the flip is done here, not with stb's global flag).

Source: assetimport/include/assetimport/ImageDecoder.hpp; assetimport/src/assetimport/ImageDecoder.cpp — DecodeImage; tests: ImageDecoderTest.* (tests/assetimport/ImageDecoderTests.cpp)

Guarantee

Truncated or corrupt image data is an error, never a crash or an abort: every prefix of a stored and of a deflate-compressed PNG is decoded in ImageDecoderTest.EveryTruncationOfAPngIsAnErrorNotACrash (the only prefixes that decode are those missing just the final IEND chunk's CRC, which stb doesn't check; they give the whole image). Oversized headers are rejected before any pixel memory is allocated (OversizedDimensionsAreRejectedFromTheHeader, OversizedDecodedBytesAreRejectedFromTheHeader, with crafted BMP headers that carry no pixel data at all).

Design decision: fixed size caps, checked before decoding PR #64

stb_image is small and fast but not hardened; it has a history of CVEs, mostly in formats and paths the engine doesn't need. So only four formats are compiled in, and an image is measured from its header before anything is decoded: a malicious or broken file claiming 100000 × 100000 pixels costs a header read, not a 40 GB allocation. 16384 a side matches what GPUs commonly accept for a texture; 256 MiB decoded allows any 8192 × 8192 image, far beyond what a game texture needs, while a single bad file can't ask for gigabytes. The caps are compile-time constants, so a project can't raise them by accident; a caller can only lower them. Images are still trusted project assets: don't load downloaded images at runtime. Decided on #3 (decisions 2 and C).

The Texture asset PR #64

N2Engine::Rendering::Texture (engine/include/engine/rendering/Texture.hpp) is a Base::Asset with resource type "Texture". It holds CPU data only: GetWidth(), GetHeight(), GetPixels() (8-bit RGBA, the first row being v = 0) and GetSettings(). It never holds a GPU handle, so it loads headless and one texture can serve several renderers; each renderer gets its own GPU copy through GpuCache. A texture is not meant to change after it is made, and a reload through Resources makes a new object. Calling the inherited Load() again on a texture already in use would change its pixels without updating GPU copies that already exist, so don't.

  • Files. .png, .jpg, .jpeg, .tga and .bmp, in any case, load as textures. Texture::RegisterLoader() registers the loader with Resources (and so ResourceLoader, which then scans and indexes those files). It is called by a static registrar in Texture.cpp and, because the linker can drop that file from a program that never names Texture, by ResourceLoader::Initialize too, as for fonts. See Loaders.
  • Loading. Texture::Load(path) reads the file, takes the settings from its .meta when ResourceLoader tracks it (defaults otherwise), and decodes it with DecodeImage. A file that can't be read, or doesn't decode, logs an error ("Cannot load texture <path>: <reason>") and the load returns null. GetSourcePath() is the file it came from.
  • From memory. Texture::CreateFromEncoded(bytes, settings, debugName) decodes image file bytes with the given settings; null and an error on failure.
  • At runtime. Texture::Create(width, height, rgbaPixels, options) makes a procedural texture from width × height × 4 bytes, the first row being v = 0, with TextureOptions for its filter, wrap and mipmaps (the defaults are TextureOptions::Default()). A zero size or a pixel count that doesn't match logs an error and returns null. Its UUID is random, so to be found by UUID (a saved Image sprite, say) it must be registered with Resources::RegisterAsset, and only resolves in that run.
auto icon = IO::Resources::Instance().Load<Rendering::Texture>("res://ui/icon.png");
image->SetSprite(icon); // UI::Image

std::vector<std::uint8_t> rgba = MakeNoise(64, 64);
auto noise = Rendering::Texture::Create(64, 64, rgba); // linear, repeat, mipmaps

Texture import settings PR #64

A project texture takes its settings from its .meta file's customData (see .meta files), in a "texture" object. Every key is optional:

{"texture": {"srgb": true, "filter": "linear", "wrap": "repeat", "mipmaps": true, "flipY": true}}
KeyValuesDefaultEffect
srgbtrue, falsetrueWhether the colours are sRGB-encoded. Recorded only: nothing reads it yet (why).
filter"linear", "nearest""linear"TextureOptions::filter. On the software renderer, bilinear or nearest sampling (below).
wrap"repeat", "clamp""repeat"TextureOptions::wrap (Repeat or ClampToEdge). One value for both axes.
mipmapstrue, falsetrueTextureOptions::mipmaps: OpenGL generates a mip chain (trilinear with linear). The software renderer has none.

filter, wrap and mipmaps map one to one onto TextureOptions, and their defaults are TextureOptions::Default(), what CreateTexture did before options existed. Texture::ParseSettings(customData, defaults) does the parsing exactly as Font::ParseAtlasSettings does: a missing key keeps the default; a key with the wrong type or an unknown value is ignored with a warning (Texture settings: ignoring "filter": "cubic" (expected "linear" or "nearest")); a "texture" member that isn't an object is ignored with one warning; unknown keys are ignored silently. The settings are read when the texture loads, so after editing a .meta the texture must be loaded again (rescan, then Reload or a new run).

Source: engine/src/rendering/Texture.cpp — Texture::ParseSettings, TextureSettings::ToTextureOptions; tests: TextureSettingsTest.*, TextureAssetTest.LoadsWithTheSettingsFromItsMeta, TextureAssetTest.BadSettingsInTheMetaWarnAndKeepTheDefaults

Design decision: sRGB is recorded, not applied PR #64

Image files are almost always sRGB, and correct lighting would decode them to linear (an SRGB8_ALPHA8 texture on OpenGL, a lookup table on the software renderer) and encode the result for display. Neither backend has sRGB textures or an sRGB framebuffer today, and the engine lights in gamma space. Turning sRGB on for textures alone would darken every textured surface, and doing it properly changes every colour the engine draws, UI included. So P1 reads and keeps the setting, defaulting to true to describe typical files, and it changes nothing until the engine-wide linear-lighting option arrives in P4a, which will default to off. Projects can set the flag correctly now and it will take effect then. Decided on #3 (decision A).

The UV convention PR #64

The engine's texture coordinates are v-up: v = 0 is the first row of pixel data, and that row is the bottom of the picture. u = 0 is the left edge. This is what the existing geometry already assumes:

  • the UI Image quad has uv (0, 0) at the bottom-left of its rect (Image);
  • the CubeRenderer's bottom vertices have v = 0 and the QuadRenderer's top-left has v = 1;
  • OpenGL samples v = 0 from the first row uploaded.

Image files store the top row first, so texture assets are decoded with flipY on by default: the stored rows go bottom to top and the image shows upright everywhere above. SoftwareImageGoldenTest.ASpriteFromAnImageFileShowsUpright pins this: a 2 × 2 BMP whose top-left pixel is red shows red in the top-left quadrant of the screen. A raw texture given to IRenderer::CreateTexture is uploaded as given, so its first row is v = 0.

Two exceptions keep their own conventions: the SDF glyph atlas uses y-down uvs internally, because the text code produces and consumes them (TextRenderer's mesh); and formats whose UVs are v-down, such as glTF, are converted by their importer with v' = 1 − v (P3), never by the renderer.

Design decision: textures are stored bottom row first PR #64

Something has to flip: image files are top row first, and the engine's existing geometry (the UI quad, the cube, sphere and quad primitives) and OpenGL's upload are v-up. Flipping the images once, at import, changes nothing that exists and costs one row copy per load. The alternative, top row first with v-down UVs everywhere, would mean changing every primitive and the Image quad, and every future importer still has to agree with one or the other. Unity makes the same choice. The flip lives in the importer, not the renderer, so a texture's pixels mean the same thing to every backend, and a format with v-down UVs (glTF) flips its UVs instead. Decided on #3 (decision 4).

GpuCache: shared GPU resources PR #64

Rendering::GpuCache (engine/include/engine/rendering/GpuCache.hpp, engine-internal) holds one GPU resource per (renderer, source asset, kind), created on first use, shared by every component that asks for it, and destroyed when the last one lets go. It holds:

  • Textures PR #64: AcquireTexture(renderer, texture) for Texture assets (uploaded as RGBA8 with the texture's filter, wrap and mipmaps) and AcquireFontAtlas(renderer, font) for fonts' SDF atlases (single channel, TextureOptions::SdfAtlas()).
  • Meshes PR #65: AcquireMesh(renderer, mesh), one IMesh per (renderer, Mesh). The entry records the mesh version it uploaded; SyncMesh(handle), which every user calls before drawing (and every acquire does), re-uploads a changed mesh in place with UpdateMesh, or, on a backend that can't update meshes, makes a new IMesh and destroys the old one, then points the handle at the current one.
  • Materials PR #65: AcquireMaterial(renderer, material), one IMaterial per (renderer, Material, GPU version): the standard lit or unlit shader with the material's base colour texture, whose own texture entry the material's entry holds a share of. The GPU version (Material::GetGpuVersion) changes only with what the IMaterial is made of, the shading and the base colour texture; then its users acquire a new GPU material on their next draw and the old one goes with its last user. Every other field is a uniform or render state set per draw, so animating a material's colour makes nothing new. A user takes the new share before giving up the old one, so a texture both versions use isn't destroyed and uploaded again.

Users are the UI Image (its sprite), every TextRenderer and UIText (their font's atlas, through TextDrawing::DrawResources), and every MeshRenderer and built-in shape (their mesh and materials, through MeshDrawing::DrawResources).

An acquire returns a move-only GpuCache::Handle: one user's share. It is false when there is nothing to upload (a null or unloaded asset, an empty atlas) or the renderer couldn't create the resource, and then no entry is made. The rules, the ones the text atlas cache had:

  1. Refcounted. Each handle is one user. Release(true), or a move assignment over a handle, gives the share up; the last share destroys the resource on its renderer, if that renderer is still alive.
  2. The asset stays alive. An entry holds its asset's shared_ptr, so the asset's address, half the key, can't be reused by another asset while the entry exists.
  3. Renderers are told apart by their lifetime token. Each entry keeps its renderer's lifetime token. An entry whose renderer has been destroyed or shut down is never handed out and its resource is never destroyed (the renderer freed it); the next acquire with that key replaces it.
  4. A stale handle can't touch a new entry. A release names the token its handle was acquired with, so a handle from a destroyed renderer never releases, or destroys, the entry that a new renderer at the same address has made since.
  5. Destructors don't call the renderer. A handle destroyed without Release gives up its share without calling the renderer, which may be gone or mid-destruction; a resource whose last share went that way stays with the renderer until it shuts down.
  6. Leaked on purpose. The cache is never destroyed, so a component that Lua keeps alive until exit can still release its share after function-local statics are gone.

An entry that holds a share of another entry (a material's texture) gives it up after the entry itself is gone, so the texture outlives the material that samples it. GetEntryCount() and GetUserCount(renderer, source, kind, version) report the cache's state for tests and diagnostics (the version only matters for a material). The cache is used on the main thread only, like the components that draw.

Source: engine/include/engine/rendering/GpuCache.hpp; engine/src/rendering/GpuCache.cpp; engine/src/rendering/TextDrawing.cpp — DrawResources::EnsureAtlasTexture; engine/src/ui/Image.cpp — Image::EnsureSpriteTexture; engine/src/rendering/MeshDrawing.cpp; tests: GpuCacheTest.*, ImageSpriteTest.* (tests/engine/rendering/GpuCacheTests.cpp), GpuCacheMeshTest.*, GpuCacheMaterialTest.* (tests/engine/rendering/GpuCacheMeshMaterialTests.cpp), and unchanged, TextRendererTest.*, UITextTest.*, SoftwareTextGoldenTest.*

Design decision: one GPU cache for every shared resource PR #64

Textures, and soon meshes and materials, are CPU assets that many components draw. Uploading one copy per component wastes memory and upload time, and each kind of resource would otherwise need its own copy of the subtle rules for renderers that are destroyed or re-created at the same address. Text already had those rules, privately, for font atlases. GpuCache is that cache generalised: keyed by renderer, source asset and kind, refcounted, guarded by the lifetime token, and leaked for static-destruction order, with the text atlas moved onto it so there is one implementation, tested once. A component keeps only handles, so the lifetime scenarios (a new renderer, one re-created at the same address, release after the renderer is gone) behave the same for every user. Decided on #3 (decision B).

Sampling on the software renderer PR #64

The software renderer's unlit and lit shaders sample a texture through SWTexture::SampleFiltered, following its filter:

  • Linear (the default for texture assets and for CreateTexture without options): SampleBilinear, every channel filtered as OpenGL's GL_LINEAR without mipmaps. Texel centres are at (i + 0.5) / size; the four texels around the sample point are weighted by distance; neighbours outside the texture are clamped or wrapped as wrap says. It shares its footprint code with the text shader's SampleFirstChannelBilinear. Each channel is rounded to 8 bits.
  • Nearest: Sample, picking the texel as GL_NEAREST does: texel i covers i / size to (i + 1) / size, and a clamped u = 1 is the last texel. (It used to scale by size − 1, so a texture two texels wide showed its second texel only at u = 1 exactly.)

Both read missing channels as OpenGL reads R8/RG8/RGB8 textures (green and blue 0, alpha 255), and read a NaN or infinite coordinate as 0. There are no mipmaps on this backend, so distant textures alias. The text shader is unchanged. SoftwareImageGoldenTest.ALinearSpriteIsFilteredIntoAGradient checks a Linear 2 × 1 texture draws a gradient between its texel centres and the Nearest one two flat halves.

Source: renderer/include/renderer/software/SWTexture.hpp — SWTexture::Sample, SampleBilinear, SampleFiltered; renderer/src/software/SoftwareRenderer.cpp — ShadeUnlitPx, ShadeLitPx; tests: TextureOptionsTest.SoftwareNearestSamplingPicksTexelsAsGLNearestDoes, TextureOptionsTest.SoftwareBilinearRgbaSamplingMatchesGLLinear

The Mesh asset PR #65

N2Engine::Rendering::Mesh (engine/include/engine/rendering/Mesh.hpp) is a Base::Asset with resource type "Mesh": a triangle mesh in CPU memory, never a GPU handle, so it works headless and one mesh serves every renderer. Each renderer gets one GPU copy per mesh through GpuCache, shared by every component that draws it.

  • Geometry. GetVertices() and GetIndices() (GetMeshData() gives both, as IRenderer::CreateMesh takes them). Renderer::Common::Vertex stays 48 bytes: position, normal, uv and colour (decision 11; tangents arrive with normal maps in P4, skinning data in a separate stream later).
  • Submeshes. GetSubmeshes() returns at least one Submesh{firstIndex, indexCount, bounds}: a run of whole triangles in the one index buffer, drawn with its own material. They may overlap or leave indices unused.
  • Bounds. GetBounds() is the axis-aligned box around every vertex, and each submesh's bounds the box around the vertices its indices use, in mesh space (BoundingBox from Camera.hpp, which Frustum::IsVisible takes). Nothing culls with them yet.
  • Versions. GetVersion() is 1 for a new mesh and goes up on every change, so GPU copies are re-uploaded (GpuCache::SyncMesh).
  • At runtime. Mesh::Create(MeshData, submeshes) makes a procedural mesh; with no submeshes, one covers every index. SetData(MeshData, submeshes) replaces the geometry. Both check it and refuse (null, or false, with an error naming why) a mesh with no vertices or indices, an index count that isn't a multiple of 3, an index past the last vertex, or a submesh that is empty, isn't whole triangles, or runs past the indices. Bounds are always computed, never taken from the caller. A runtime mesh's UUID is random; register it with Resources::RegisterAsset to have a saved reference find it in the same run.
  • Files. There is no mesh file format in P2: meshes come from code, the built-ins below, and, from P3, glTF models as sub-assets.
Renderer::Common::MeshData data = BuildTerrain(); // two materials: grass first, then rock
auto terrain = Rendering::Mesh::Create(std::move(data), {
    Rendering::Submesh{0, grassIndexCount, {}},
    Rendering::Submesh{grassIndexCount, rockIndexCount, {}},
});

Source: engine/include/engine/rendering/Mesh.hpp; engine/src/rendering/Mesh.cpp — Mesh::Create, Mesh::SetData, Mesh::Validate, Mesh::ComputeBounds; tests: MeshTest.* (tests/engine/rendering/MeshAssetTests.cpp)

Design decision: submeshes are index ranges in one GPU mesh PR #65

A model's parts usually share vertices, and glTF primitives that share a mesh map naturally onto one vertex buffer with several index ranges (the importer concatenates their vertices and offsets their indices). So a Mesh is one vertex and index buffer, each submesh a range of the indices, and the renderer gained one call to draw a range: DrawMesh(mesh, model, material, state, IndexRange{first, count}) (IndexRange draws), a glDrawElements offset on OpenGL and a loop bound on the software renderer. The alternative, one GPU mesh per submesh, needs no renderer change but duplicates shared vertices and multiplies GPU objects. The overload has a default body so test fakes keep compiling, and it never draws the whole mesh for a partial range (that would draw the wrong material over the other submeshes); it draws nothing and logs once. Decided on #3 (decision 5).

Built-in meshes PR #65

Mesh::GetBuiltin(BuiltinMesh::Cube | Sphere | Quad) returns a mesh every program has, made once on first use and shared. Their vertices are exactly what CubeRenderer, SphereRenderer and QuadRenderer built for themselves before P2, byte for byte, and so are the cube's and quad's indices (BuiltinMeshTest.TheBuiltinsAreExactlyTheShapesTheRenderersUsedToBuild compares them with the old generators). The sphere's triangles are the old ones wound the other way: SphereRenderer wound them clockwise seen from outside, so back-face culling kept its inner faces and dropped its outer ones (see the visible changes). Every built-in triangle now faces outward (BuiltinMeshTest.EveryBuiltinTriangleFacesOutward).

Design decision: the built-in shapes are shared meshes PR #65

Before P2 every CubeRenderer built its own GPU cube, so a thousand cubes were a thousand identical meshes. As shared assets with fixed UUIDs, every cube on a renderer draws one GPU mesh, a scene file can name a cube for a MeshRenderer, and the shape components are thin wrappers over the same drawing code instead of a separate CRTP family with its own resource rules. The geometry is copied exactly, so existing scenes look the same. Decided on #3 (decision 8).

The Material asset PR #65

N2Engine::Rendering::Material (engine/include/engine/rendering/Material.hpp) is a Base::Asset with resource type "Material": how a surface is drawn, as CPU data. Each renderer gets one GPU material per material and version through GpuCache.

Only a new shading or base colour texture bumps GetGpuVersion() and makes renderers build a new GPU material; the other fields (colour, alpha mode and cutoff, double-sided, smoothness, and the P4 fields) are applied per draw, so changing them every frame is cheap.
  • Defaults. Material::GetDefault() (lit white) is what a MeshRenderer draws an empty slot with; Material::GetDefaultUnlit() (unlit white) is what the built-in shapes draw with, tinted by their colour. Both are shared and fixed (const).
  • Uniforms. ApplyUniforms(gpuMaterial, tint) sets uAlbedo (base colour × tint), uHasTexture, uAlphaCutoff (the cutoff for Mask, else 0) and, lit, uSmoothness and uMetallic. The drawing code calls it before every draw, so a GPU material shared by many users always draws with the right values.

.mat files PR #65

A .mat file (any case) under assets/ is a material: ResourceLoader gives it resource type "Material" and a stable UUID like any asset (resource types). Material::RegisterLoader() registers the loader; a static registrar in Material.cpp calls it, and so does ResourceLoader::Initialize, as for textures and fonts. The file is one JSON object; every key is optional:

{
  "shading": "lit",
  "baseColor": {"r": 1, "g": 0.8, "b": 0.6, "a": 1},
  "baseColorTexture": "../textures/crate.png",
  "alphaMode": "mask",
  "alphaCutoff": 0.5,
  "doubleSided": false,
  "smoothness": 0.3,
  "metallic": 0,
  "emissive": [0, 0, 0],
  "normalTexture": null
}
  • Values. shading is "lit" or "unlit"; alphaMode is "opaque", "mask" or "blend" (any case, so glTF's "MASK" works); colours are {"r", "g", "b", "a"} objects as scene files write them (a missing channel is 1) or [r, g, b] / [r, g, b, a] arrays; alphaCutoff, smoothness and metallic are numbers from 0 to 1 (outside that, clamped with a warning).
  • Textures. A res:// or user:// path, an asset UUID, or a path relative to the .mat file's folder; null for none. Each loads through Resources, so it is the same Texture asset an Image or another material gets.
  • Warnings, as for texture settings. A key with the wrong type or an unknown value, a texture that doesn't load, or an unknown key is ignored with a warning naming the file (Material res://materials/crate.mat: ignoring "alphaMode": "cutout" (expected "opaque", "mask" or "blend")), and the rest of the file still loads. A file that isn't valid JSON, or isn't an object, fails to load with an error.
  • Writing one. ToJson() gives every field in this format, textures as their res:// paths (or source file, or UUID for a texture made at runtime); Material::FromJson(json, baseDirectory) reads one from memory.

MeshRenderer PR #65

N2Engine::Rendering::MeshRenderer (engine/include/engine/rendering/MeshRenderer.hpp) is the component that draws a mesh at its object's transform. It is registered as "MeshRenderer", and creates a Positionable if its object has none.

  • Mesh and materials. SetMesh(mesh) (null draws nothing). One material slot per submesh: SetMaterial(i, material), GetMaterial(i), SetMaterials(list). Slot i draws submesh i; an empty or missing slot draws with Material::GetDefault(), lit white; slots past the last submesh are kept but unused. GetMaterialCount() is the mesh's submesh count; GetEffectiveMaterial(i) what slot i draws with.
  • Drawing. Each submesh is one DrawMesh(gpuMesh, world, gpuMaterial, state, IndexRange), its uniforms set from its material first.
  • Queues. A submesh with a Blend material draws in the Transparent queue (blended, sorted back to front by the object's position); the others in the Opaque queue, unblended. A renderer with both kinds draws in both (DrawsInQueue, see the render queue), each submesh once, in its own queue. GetRenderQueue() is Opaque unless every submesh blends.
  • Culling. Back faces are culled, except with a double-sided material (cull None). A mirrored world matrix (a negative determinant, such as a scale of −1 on one axis, common in Blender scenes) culls front faces instead, because both backends tell front faces by their winding on screen and mirroring reverses it.
  • GPU resources. Shares from GpuCache (one mesh and one material per renderer and asset), held with the renderer's lifetime token in a MeshDrawing::DrawResources, which the built-in shapes use too. A renderer that is destroyed, shut down or replaced at the same address is never called. OnDestroy releases the shares; Render(nullptr) does nothing.
  • Bounds. GetBounds() is the mesh's box in its own space (nullopt without a mesh).
  • Saved as "_mesh" (the mesh's UUID; built-ins by their fixed UUIDs) and "_materials" (a list of material UUIDs, null for an empty slot, through RegisterAssetRefList).
auto crate = GameObject::Create("Crate");
auto *renderer = crate->AddComponent<Rendering::MeshRenderer>();
renderer->SetMesh(Rendering::Mesh::GetBuiltin(Rendering::BuiltinMesh::Cube));
renderer->SetMaterial(0, IO::Resources::Instance().Load<Rendering::Material>("res://materials/crate.mat"));

Design decision: one MeshRenderer, no MeshFilter PR #65

Unity splits the mesh reference (MeshFilter) from the drawing component so SkinnedMeshRenderer and MeshCollider can share it. Nothing here needs that yet: a future MeshCollider takes its own mesh reference (as Unity's does anyway), and one component is simpler to serialize, to script and, later, to edit. So MeshRenderer holds the mesh and the materials itself. Decided on #3 (decision 6).

Design decision: a renderable can draw in both queues PR #65

A model often mixes opaque parts with glass. If the whole renderer had one queue it would either draw its opaque parts late, without depth sorting benefits and blended, or draw the glass early, before what is behind it. Splitting it into separate objects would change the model's hierarchy. Instead IRenderable::DrawsInQueue(queue) lets a renderable say it draws in both, and Scene::Render calls RenderInQueue once per queue, with the queue, so each submesh draws in its own pass. The default keeps every existing renderable in its one queue, and the Opaque order is unchanged. Decided on #3 (decision 9).

Design decision: blending follows the alpha mode PR #65

Before P2 every draw blended: RenderState::Opaque() had blend = true, so an opaque surface with a translucent colour blended with whatever happened to be drawn before it, unsorted. Now the Opaque queue's state (the RenderState default) doesn't blend, and only the Transparent queue does: a material blends exactly when its alpha mode is Blend, which also puts it in the Transparent queue, sorted back to front and not writing depth. Mask materials stay opaque and cut holes with the alpha test instead, which needs no sorting. The UI pass keeps blending (its own state). Decided on #3 (decisions 10 and F).

The built-in shapes PR #65

Example::CubeRenderer, SphereRenderer and QuadRenderer keep their type names, saved fields (_color, _size, the sphere's _latitudeSegments and _longitudeSegments) and C++ API, so scenes and scripts written before P2 load and run unchanged (PolygonRendererCompatibilityTest.APreP2SceneLoadsUnchanged loads a pre-P2 scene object). Inside they are thin: PolygonRenderer, no longer a CRTP template, draws the built-in mesh (GetMesh()) scaled by _size through the same MeshDrawing code as MeshRenderer.

  • Still unlit, in their colour. Without a material they draw with Material::GetDefaultUnlit() tinted by _color, set per draw, so every shape of a kind on a renderer shares one GPU mesh and one GPU material whatever its colour.
  • An optional material. SetMaterial(material) (saved as "_material", null when unset; older scenes load with none) replaces the unlit default, still tinted by the colour, so a shape can be lit, textured, cut out or see-through. Its alpha mode picks the queue as for MeshRenderer.
  • Visible change: no blending in the Opaque queue. A shape with a translucent _color (alpha below 1) used to blend over what was drawn before it on OpenGL; it now draws opaque, as every Opaque-queue draw does. To draw a see-through shape, give it a material with alphaMode "blend". (The software renderer never blended, so nothing changes there.)
  • Visible change: the sphere is no longer inside out. The built-in sphere's triangles now wind counter-clockwise seen from outside, like every other front face; SphereRenderer's wound clockwise, so back-face culling drew the far inner half of the sphere instead of the near outer half. Flat and unlit, the silhouette is the same, but where another object passes through a sphere the depth now comes from the near surface, so the intersection looks different; lit or textured spheres now shade the side that faces the camera. A sphere drawn by a MeshRenderer (SetMesh("Sphere")) or a SphereRenderer with a lit material is right only with this fix.
  • Visible change: mirrored shapes cull front faces. A shape whose world matrix mirrors it (a negative _size on one axis, or a parent's negative scale) now culls its front faces, as MeshRenderer does, so it shows its outside rather than turning inside out. Before, it culled back faces and showed its inside.
  • Spheres. At the default 16 × 32 subdivision a SphereRenderer draws the shared built-in sphere; any other subdivision makes a mesh of its own, made again when the subdivision changes (which now works at any time, not only before the first draw).
  • Lifetime. As before, a renderer recreated at the same address, a switch to another renderer, a shutdown and re-initialise, and destruction after the renderer is gone are all handled; the resources are now shares counted in the cache (PolygonRendererLifetimeTest.*).

Vertex colour and the alpha test PR #65

The standard unlit and lit shaders, on OpenGL and the software renderer alike, now:

  • multiply by the vertex colour: the colour is uAlbedo × texture × vertex colour (the lit shader lights that). Every mesh the engine made before P2 (the shapes, the UI Image quad) has white vertex colour, so nothing looks different; text has its own shader, which always read it. Visible change: a mesh made by game code with coloured vertices and drawn with the standard unlit or lit shader now shows tinted by them on OpenGL (before, only the text shader read vertex colour; the software renderer ignored it too, and now applies it the same way). The software renderer skips the multiply when every vertex of a mesh is white, so those meshes shade bit for bit as before.
  • alpha-test against uAlphaCutoff: a pixel whose final alpha is below it is discarded, colour and depth (discard on OpenGL; skipped on the software renderer, in SWMaterialSnapshot::alphaCutoff). CreateMaterial gives every standard material 0, which discards nothing, so existing materials are unaffected. Mask materials set their cutoff.

Source: renderer/src/opengl/OpenGLRenderer.cpp — CreateStandardShaders, CreateMaterial; renderer/src/software/SoftwareRenderer.cpp — ShadeUnlitPx, ShadeLitPx, RasterTri; tests: SoftwareVertexColourTest.*, SoftwareAlphaCutoffTest.*, SoftwareMeshGoldenTest.AnAlphaMaskMaterialLeavesHoles

Design decision: the standard shaders read vertex colour PR #65

Vertex has always carried a colour, but only the text shader read it. glTF models use vertex colours (COLOR_0) for painted or baked detail, and procedural meshes are easiest to colour per vertex, so the unlit and lit shaders multiply it in, matching glTF's base colour × texture × vertex colour. Every existing mesh is white per vertex, so this changes no output; the software renderer even skips the work for all-white meshes. Decided on #3 (decision 10).

Models and glTF import PR #TBD

A 3D model file (.glb, or .gltf with its .bin files and images) is a Model asset: a node hierarchy plus the meshes, materials and images inside the file, which become Mesh, Material and Texture sub-assets. Model::Instantiate() builds a GameObject hierarchy from it, with a MeshRenderer on every node that has a mesh. glTF 2.0 is the format: Blender exports it natively, and its axes (right-handed, Y up), winding (counter-clockwise front faces) and units (metres) are the engine's, so nothing is converted except the texture v (see the UV convention). Optional FBX and OBJ through ufbx come in P5 (#62), behind the same importer interface.

scene->AddRootGameObject(robot->Instantiate()); // "robot", with one child object per root node

The parsing happens in the assetimport library, behind a library-neutral interface: IModelImporter::Import(bytes, baseDirectory, settings) returns std::expected<ImportedScene, ModelImportError> (assetimport/include/assetimport/ModelImporter.hpp). ImportedScene (ImportedScene.hpp) is plain CPU structs with no cgltf type: nodes (name, local translation, rotation and scale, a mesh index, children), meshes (vertices laid out exactly as the engine's Vertex, triangle-list indices, and one submesh per primitive with its material index), materials (every field the engine's Material has, including the ones stored for P4), images (the encoded bytes, the URI they came from, and the sampling their texture asks for) and the warnings. GltfImporter is the one implementation.

The glTF importer PR #TBD

cgltf 1.15 (external/cgltf/, MIT) parses the file; it is compiled once, as C, in assetimport/src/assetimport/CgltfImplementation.c, and only GltfImporter.cpp includes it. On top of the parse, the importer:

  • Reads every buffer itself. A .glb's BIN chunk, a base64 data: URI, or an external file, never through cgltf's loader (which would open any path the file names). An external URI is percent-decoded (my%20mesh.bin is my mesh.bin) and must be a relative path that stays inside the model's folder once normalised (AssetImport::ResolveModelUri): a scheme (http:, file:), a drive letter, an absolute path, a NUL or a .. that climbs out is rejected. A buffer it rejects is an error; an image it rejects is skipped with a warning.
  • Checks every range. Every buffer view against its buffer, and every accessor and sparse substitution against its views, with overflow-safe arithmetic, before cgltf_validate runs (which also must pass). Then, while reading: a stride below the element size, an index past the last vertex, a sparse index past the accessor's end, or an unsupported component type is an InvalidData error.
  • Reads what files contain. Indices as unsigned 8, 16 or 32-bit; attributes as floats or (normalised) integers; sparse accessors, with or without a base view. POSITION, NORMAL, TEXCOORD_0 and COLOR_0 (RGB or RGBA; white when absent) fill the vertex. A value that isn't a finite number reads as 0, with a warning.
  • Makes triangle lists. Strips and fans become lists in the order the glTF spec gives (so the winding is kept, and degenerate strip triangles are dropped); points and lines are skipped with a warning.
  • Flips v (v' = 1 − v), since glTF's v runs down the image and the engine's up; the images are stored bottom row first as every texture is, so they show upright.
  • Generates normals flat for a primitive without them (and for every primitive with generateNormals: "always"): each triangle gets its own three vertices with its face normal. Flat, because the glTF spec says a client must use flat normals when they're missing; smooth normals belong in the file.
  • Concatenates a mesh's primitives into one vertex buffer with one submesh each (and its material). Primitives that use the same attribute accessors, as exporters write a mesh with several materials, share one run of vertices.
  • Decomposes node matrices into translation, rotation and scale; a mirroring matrix gets a negative x scale. Nodes keep negative scales: MeshRenderer culls front faces for a mirrored world matrix (winding).
  • Maps materials. KHR_materials_unlit gives an unlit material, otherwise lit; baseColorFactor and the base colour texture, alphaMode and alphaCutoff, doubleSided, and smoothness = 1 − roughnessFactor drive drawing; metallicFactor, emissiveFactor and the normal, occlusion, metallic-roughness and emissive textures are stored for P4. A texture's sampler gives its image nearest filtering (a nearest magnification filter) and clamping (clamp-to-edge in s or t).

Fixed caps (ModelImporter.hpp), checked before memory is allocated: a model file of at most 512 MiB; glTF JSON (a .gltf, or a .glb's JSON chunk) of at most 64 MiB; any one buffer at most 512 MiB and all of them at most 1 GiB; an image at most 64 MiB encoded; an accessor at most 16 M elements; a mesh at most 64 M vertices or indices; a node tree at most 256 deep. A .glb's header and chunk lengths are checked against the file before cgltf sees it.

Source: assetimport/src/assetimport/GltfImporter.cpp — CheckGlb, LoadBuffers, CheckRanges, VisitAccessor, ImportPrimitive, Decompose, ImportMaterial; tests: GltfImporterTest.* (tests/assetimport/GltfImporterTests.cpp)

Guarantee

A malformed or hostile model is an error value, never a crash: a .glb cut short at every byte, and a .gltf cut at every byte, are rejected (GltfImporterTest.AGlbCutShortAtAnyByteIsAnErrorNotACrash); so are out-of-range indices, bad strides, a view past its buffer, an offset so large the sums would wrap, a sparse index past the end, and URIs that leave the model's folder in any spelling (../, %2E%2E/, ..\, absolute, drive letters, schemes, an embedded NUL). Models are still trusted project assets: don't load downloaded ones at runtime.

The Model asset PR #TBD

Rendering::Model (GetResourceType() == "Model") loads .gltf and .glb files (any case). Its loader registers itself statically and from ResourceLoader::Initialize, like Font, Texture and Material. Model::LoadFromMemory(bytes, baseDirectory, settings, name) makes one from bytes, outside any project.

Sub-assets and their keys PR #TBD

A model's meshes, materials and textures are sub-assets: assets inside another asset's file. Each has a key naming it inside the model: mesh/<name>, material/<name>, texture/<name> (a texture's name is its glTF image's). The name is used when every name of that kind in the file is non-empty and unique; if any name of a kind is missing or repeated, every sub-asset of that kind is keyed by its index instead (mesh/0, mesh/1, ...). Model::MakeSubAssetKeys applies the rule; Model::FindSubAsset(key) and GetSubAssets() look them up. A sub-asset reports IsSubResource(), its GetSubAssetKey(), and its model's resource path as its own.

A project model's sub-assets get deterministic UUIDs when it loads: ResourceUUID::FromSubAsset(modelPath, key). Scene files save a MeshRenderer's mesh and materials by those UUIDs like any other asset reference, and loading one (Resources::LoadByUUID, which asset references use) loads the model, or reuses it if it's loaded, and returns the sub-asset. A .mat-style texture reference inside a model's material is saved as its UUID. Lua names a sub-asset with its model's path, # and its key: "res://models/robot.glb#mesh/Body".

When a model first loads, its .meta gets a sub-asset index in customData.subAssets, beside its import settings:

{
  "customData": {
    "model": { "scale": 1.0 },
    "subAssets": {
      "mesh/Body":      { "type": "Mesh",     "uuid": "..." },
      "material/Red":   { "type": "Material", "uuid": "..." },
      "texture/Albedo": { "type": "Texture",  "uuid": "..." }
    }
  }
}

The scan reads the index back (re-deriving each UUID from the path and key), so after a restart a sub-asset UUID is found without loading anything first. A project whose .import folder is new has no index yet: LoadByUUID of an unknown UUID then loads every model that has none, once, and looks again. If a key disappears in a re-export, references to it resolve to nullptr with the usual "Asset not found" warning, and that MeshRenderer draws nothing. Outside a project (LoadFromMemory, or a file Resources loads from elsewhere), sub-assets have random UUIDs, as such files themselves do; Resources registers them so references resolve during that run.

Design decision: sub-asset UUIDs from their own namespace, keyed by name PR #TBD

A scene must be able to name "the Body mesh of robot.glb" as plainly as it names a file, so a sub-asset UUID is derived the same way a file's is, from a path-like name, and RegisterAssetRef and the scene format don't change at all. It is derived in a namespace of its own (itself derived from the project's) rather than by hashing "robot.glb#mesh/Body" as a path, so no file name can ever produce a sub-asset's UUID. Keys use names because a Blender re-export reorders meshes freely but keeps their names; when names can't identify every asset of a kind (missing or repeated), all of that kind fall back to indices together, so one renamed duplicate can't silently swap two keys. ResourceLoader keeps a UUID → (parent, key) map that LoadByUUID checks after its cache. Decided on #3 (decisions 7 and 12).

Design decision: the .meta index is written when the model loads, never by the scan PR #TBD

The scan runs over every file at startup and on every rescan; parsing models there would make the engine core depend on the glTF parser and make every rescan as slow as loading every model. Instead, ResourceLoader::Load asks a just-loaded asset for its sub-assets (Asset::GetSubAssets), gives them their UUIDs, and records them through ResourceLoader::SetSubAssetIndex, which rewrites the .meta only when the index changed and keeps the rest of customData. The scan merely reads indexes back. The cost is that a never-loaded model has no index, which the one-time "load the unindexed models" fallback in LoadByUUID covers. Decided on #3 (decision 7, revised).

Instantiating a model PR #TBD

Model::Instantiate() returns a new root GameObject, in no scene (add it with Scene::AddRootGameObject or GameObject::AddChild):

  • The root is named after the model and has an identity transform; it has one child object per root node, and so on down the tree.
  • Each object has its node's name (an unnamed node is "Node <index>") and a Positionable with the node's local position, rotation and scale.
  • A node with a mesh gets a MeshRenderer drawing that mesh, with material slot i holding submesh i's material (an empty slot for a primitive without one). Every instance shares the model's meshes and materials, and so their GPU copies.
  • It goes through PrefabManager::InstantiatePrefab: the model builds prefab JSON for its tree once, so every call gives every GameObject and component a fresh UUID. The mesh and material references are then set directly, so a model loaded from memory instantiates the same way as a project one.
  • There is no live link: the instance is ordinary GameObjects. Re-importing changes the meshes and materials a saved instance references (by UUID), but not nodes added to or removed from the file.

Mirrored nodes (a negative scale, common in Blender) draw correctly: MeshRenderer culls front faces for a world matrix with a negative determinant. SoftwareModelGoldenTest draws an instantiated model with a mirrored node headless and checks it covers its bounds and shows both materials.

Exporting from Blender

  1. File → Export → glTF 2.0 (.glb/.gltf).
  2. Format: glTF Binary (.glb), one self-contained file. (glTF Separate, .gltf + .bin + textures, works too; keep the files together inside the project's assets folder.)
  3. Include: the objects you want (Selected Objects, or a collection).
  4. Transform: +Y Up (on by default): Blender is Z up, the engine Y up.
  5. Data → Mesh: Apply Modifiers, so mirror, subdivision and array modifiers are baked into the exported mesh. UVs and normals on; vertex colours if you painted any.
  6. Data → Compression: off. Draco compression can't be read.
  7. Materials: Export. A Principled BSDF's base colour (and image), alpha, roughness and metallic come through; the engine draws base colour, texture, alpha and smoothness today (physically based shading arrives in P4). A material Blender exports with KHR_materials_unlit (the Blender manual's glTF page describes the node setup it writes as unlit) draws unlit.

Animation, skins and shape keys export but are ignored, with a warning. Scale in Blender's units (metres); if a model arrives at the wrong size, set the scale import setting instead of re-exporting. To automate exports, run blender --background --python export.py yourself; the engine never runs Blender.

Axes, winding and units PR #65

  • Axes. Right-handed, Y up. Objects face +Z (Positionable::GetForward); the camera looks down its −Z (Camera).
  • Winding. Front faces wind counter-clockwise as seen on screen; back faces are culled by default. A mirrored object (negative determinant) has its winding reversed on screen, so MeshRenderer culls front faces for it.
  • Units. Metres (what PhysX assumes). The built-in shapes are 1 unit across.
  • Texture coordinates. v up: see the UV convention. The cube's faces each map the full texture upright as seen from outside the face; SoftwareMeshGoldenTest.ATexturedCubeShowsItsCheckerUprightOnTheFacesTheCameraSees checks the front, right and back faces with a 2 × 2 checker.
  • The built-in sphere's v runs from 0 at the top pole (unchanged from SphereRenderer), the reverse of the v-up convention, so a texture shows upside down on it. Flipping it would change the vertex data every existing sphere has, so it is left for its own change. (Its winding, which was clockwise from outside, is fixed: see the visible changes.)

Scripts reach textures through the UI Image PR #64: image:SetSprite("res://ui/icon.png") loads the file through Resources (an error, keeping the current sprite, if it doesn't load), image:SetSprite(nil) clears it, and image:GetSprite() returns the path or nil. See UI from Lua. There is no Texture table yet.

local icon = UI.CreateElement("Icon")
local image = icon:AddComponent("Image")
image:SetSprite("res://ui/coin.png")
print(image:GetSprite()) -- res://ui/coin.png

MeshRenderer and the shapes PR #65: go:AddComponent("MeshRenderer"); SetMesh(nameOrPath) takes a built-in name ("Cube", "Sphere", "Quad") or a mesh asset's path, and GetMesh() returns the name or path (nil without a mesh); GetMaterialCount(); SetMaterial(i, path) and GetMaterial(i) take 1-based slots and .mat paths (nil empties a slot); GetBounds() returns a BoundingBox (or nil). A name, path or slot that doesn't work raises an error and changes nothing. QuadRenderer now has a Lua type too, and the three shapes have SetMaterial(path) / GetMaterial().

local crate = GameObject.Create("Crate")
local renderer = crate:AddComponent("MeshRenderer")
renderer:SetMesh("Cube")
renderer:SetMaterial(1, "res://materials/crate.mat")
print(renderer:GetMaterialCount(), renderer:GetBounds().max.y) -- 1   0.5

Models PR #TBD: Model.Instantiate(path [, parent]) returns the root GameObject of a new instance. With a parent it becomes that object's child (at its origin); without one it is in no scene yet and the script owns it, as with GameObject.Create, until a scene or parent holds it. A model that doesn't load raises an error. Wherever Lua takes a mesh, material or texture path, a model's sub-asset is "<model path>#<key>", and the getters report sub-assets the same way.

local robot = Model.Instantiate("res://models/robot.glb")
SceneManager.GetCurrentScene():AddRootGameObject(robot)
local body = robot:FindChild("Robot"):GetComponent("MeshRenderer")
print(body:GetMesh()) -- res://models/robot.glb#mesh/Body

local copy = GameObject.Create("Copy"):AddComponent("MeshRenderer")
copy:SetMesh("res://models/robot.glb#mesh/Body")
copy:SetMaterial(1, "res://models/robot.glb#material/Red")
