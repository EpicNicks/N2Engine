Text & fonts

The text library loads fonts, builds single-channel SDF glyph atlases and lays out UTF-8 text into glyph quads, all on the CPU. The engine wraps it in the Text::Font asset for .ttf/.otf files, ships one embedded default font, and draws world-space text with the TextRenderer component on OpenGL and the software renderer. UI text comes in a later phase of issue #1. This page covers the font backend interface, the atlas, layout rules, the asset and the component.

The text module PR #45

text/ is its own static library, like math/. It depends only on math and the vendored external/stb_truetype (plus FreeType when the optional FreeType backend is built), never on the engine, the renderer, GLFW or nlohmann, so text_tests runs without any of them. The engine links it publicly. Its public headers are under text/include/text/, and none of them mention a font library's types.

Font backends

A backend reads font files; a face is one loaded font. IFontBackend::LoadFace(bytes, &error) takes the whole file in memory (TrueType .ttf or CFF-flavoured .otf) and returns an IFontFace, or null with a reason. The face copies the bytes, so the caller's buffer can go. A face answers:

  • GetMetrics(): ascent, descent, line gap and units per em, in font units, y-up (descent is negative).
  • FindGlyph(codepoint): the glyph id, or nullopt when the font has none. It never returns .notdef (glyph 0).
  • GetGlyphMetrics(glyph) (advance and left side bearing), GetGlyphBounds(glyph) (the outline's box, or nullopt for an empty glyph) and GetKerning(left, right) (pair kerning between two glyphs). Invalid glyph ids give zeros or nullopt.
  • RenderSdf(glyph, pixelsPerEm, spreadPx): the glyph's signed distance field, with spreadPx pixels of border. The outline is at 128, inside is higher, and each pixel of distance changes the value by 128 / spreadPx. Spaces return an empty bitmap.

Selecting a backend. FontBackendKind names the backends (StbTrueType, FreeType). GetAvailableFontBackends() lists the ones compiled in, default first; CreateFontBackend(kind) returns null for one that isn't; CreateDefaultFontBackend() is stb_truetype. stb_truetype is always built; FreeType joins the list when the build turns on N2ENGINE_TEXT_FREETYPE, and comes second, so the default never changes. Every font test is parameterised over the list, so the same tests run against each backend in the build. The Font asset and the default font always use the default backend.

Checks before loading PR #47

Every backend runs the same structural checks on the data before its library sees it (SfntValidation.cpp), so all backends accept and reject the same files. The font start is found the way stbtt_GetFontOffsetForIndex(data, 0) finds it: a single TrueType/OpenType font, or the first font of a .ttc collection. Data shorter than 16 bytes, or that isn't an sfnt font, is rejected. Then the backend rejects, with an error naming the problem, a font where:

  • a table in the directory runs past the end of the data;
  • head is missing or shorter than 54 bytes, or indexToLocFormat isn't 0 or 1;
  • maxp is missing or numGlyphs is 0;
  • hhea is missing or short, or numberOfHMetrics isn't between 1 and numGlyphs, or hmtx is shorter than 4·nHM + 2·(numGlyphs − nHM);
  • for TrueType outlines, loca is shorter than (numGlyphs + 1) entries, or an entry is smaller than the one before it or past the end of glyf (CFF fonts have no loca; a font with neither glyf nor CFF is rejected).

The checks exist because stb_truetype is handed a pointer, not a size, and reads tables at fixed offsets without checking their lengths. FreeType checks more for itself, but running the same checks keeps the backends interchangeable: the corrupt-font tests expect the same rejections from every backend.

stb_truetype

The default backend, compiled once in StbTrueTypeBackend.cpp with STBTT_STATIC so its symbols stay private. stb's internal asserts are compiled out, so a font it still can't handle fails or renders nothing in Debug and Release alike. Kerning comes from GPOS pair adjustments when the font has GPOS, otherwise from the legacy kern table.

Warning

Font parsing is not hardened against malicious files: the table check stops truncation, not crafted tables. Fonts are trusted project assets; don't load fonts downloaded at run time.

FreeType (optional) PR #47

An alternative backend built on FreeType 2.13.3. It is off by default; turn it on when configuring:

cmake -S . -B build -DN2ENGINE_TEXT_FREETYPE=ON

With the option on, CMake fetches the FreeType release tarball (pinned by tag and SHA-256) with FetchContent and builds it as a static library with the repo's static MSVC runtime. Every optional FreeType dependency is disabled (zlib, bzip2, libpng, HarfBuzz, Brotli), so nothing is looked up on the build machine. FreeType is linked privately into text; only FreeTypeBackend.cpp includes its headers, and the public interface doesn't change. FontBackendKind::FreeType then appears in GetAvailableFontBackends(), after stb_truetype. One CI job builds with the option on (see Testing).

Choose it explicitly with CreateFontBackend(FontBackendKind::FreeType) and pass it to SdfFont::Create. For the same font it gives the same results as stb_truetype:

  • Metrics come from hhea; advances are read unscaled (FT_LOAD_NO_SCALE); left side bearings are read from hmtx, as stb_truetype reads them (FreeType's own bearing is the outline's left edge, which is 0 for an empty glyph); glyph bounds are the unscaled outline box; kerning is FT_Get_Kerning unscaled. All are in font units, as the interface requires.
  • SDFs come from FreeType's sdf renderer (FT_RENDER_MODE_SDF, with its spread property set to spreadPx). Its output already uses the contract's convention: 128 on the outline, higher inside, 128 / spread per pixel of distance. The backend scales the unscaled outline itself, so fonts that ask for integer ppem aren't rounded, and copies FreeType's bitmap into the box stb_truetype would produce: the outline box scaled, rounded outwards, plus the spread on every side. FreeType's own box can differ by a pixel at an edge; the pixels it lacks are beyond the spread and are 0. Sizes and offsets are therefore identical for both backends. The values differ by a few levels, because each library computes distances its own way.
  • FreeType's renderer takes spreads of 2 to 32 pixels. A spread of 1 is rendered at 2 and its distances doubled; a spread over 32 renders nothing. The RenderSdf contract allows 1 to FontAtlas::kMaxSpreadPx (32), which is also the most the atlas asks for.
  • Composite glyphs (built from other glyphs, such as accented letters) and glyphs flagged as having overlapping contours (FT_OUTLINE_OVERLAP, common in instances of variable fonts) render with the sdf module's overlaps mode. Its default mode takes the sign from the nearest edge, which is wrong where contours overlap: it put part of the default font's Ç, whose cedilla component overlaps the C, outside the glyph. Simple glyphs keep the default mode, because the overlap mode gets nested contours such as © wrong.
  • An outside pixel less than spread / 128 of a pixel from the outline is 128 under FreeType, which truncates distances towards zero, and 127 under stb_truetype. Either way the edge found by thresholding at 128 moves by under 1/16 of a pixel.
  • A face also needs a Unicode cmap and scalable outlines, as with stb_truetype. Each face has its own FreeType library instance.

Where the backends can differ

Not with the bundled default font, whose kerning is a legacy kern table for exactly this reason. With other fonts: FreeType reads only the kern table, while stb_truetype prefers GPOS pair kerning, so a font with only GPOS kerning has none under FreeType. And a TrueType glyph whose hmtx left side bearing differs from its glyf xMin has its outline (its bounds and SDF) placed at the bearing by FreeType, as the TrueType spec says, but at its raw coordinates by stb_truetype; the reported bearing is the hmtx value in both.

Licence. FreeType is used under the FreeType License (FTL), which requires a credit in the documentation of any product that ships it. A build or product that turns the option on must carry this notice, which is also in THIRD_PARTY_NOTICES.md at the repository root:

Portions of this software are copyright © 2024 The FreeType
Project (www.freetype.org).  All rights reserved.

Builds without the option contain no FreeType code and need no notice.

SDF atlas

FontAtlas::Build(face, settings) rasterises every glyph the settings ask for into one single-channel bitmap (std::vector<uint8_t>, row 0 first). SdfFont::Create does this when a font loads.

SettingDefaultMeaning
basePx48Rasterisation size in pixels per em (4 to 256)
spreadPx8SDF distance range each side of the outline, in pixels: 1 to half of basePx, and at most 32 (MaxSpreadPx)
paddingPx2Empty pixels between glyphs and at the atlas edge, so filtering doesn't bleed (0 to 16)
charsetLatin1Ascii is U+0020–U+007E; Latin1 adds U+00A0–U+00FF. Both also contain U+FFFD.
extraCharsemptyMore codepoints; duplicates and control characters are ignored
  • Every codepoint the face has gets an AtlasGlyph; codepoints it lacks are skipped and lay out as the fallback glyph. Glyph 0 (.notdef) is always included.
  • Each AtlasGlyph has its advance and plane rect in ems (the bitmap's quad relative to the pen on the baseline, y-up, including the SDF border), its uv rect (0..1, y-down: uv.minY is the top row) and its pixels rect. Spaces have an advance but no bitmap.
  • U+FFFD is always in the charset, whatever charset says: ill-formed UTF-8 decodes to it, and it should draw as the replacement character rather than as a missing glyph.
  • Packing is a shelf packer: glyphs sorted by height, then width, then glyph id, placed in rows with paddingPx between them and around the edge. Width and height are powers of two, at most 8192; an atlas that would be larger fails to build.
  • Invalid settings fail the build with a reason rather than being clamped. The limits keep a load to seconds: SDF rasterisation costs roughly glyph pixels times outline edges.
  • A charset of more than 4096 codepoints (kMaxCodepoints) fails before any glyph is looked up. The packed area is then estimated from the outline boxes (GetGlyphBounds), and an atlas that wouldn't fit fails before any glyph is rasterised.

Guarantee

The same font bytes, backend and settings always give a byte-identical atlas with the same glyph rects. Glyph rects never overlap, keep the padding between each other and from the edges, and every charset codepoint the font has is present.

Source: text/src/text/FontAtlas.cpp — FontAtlas::Build, ResolveCharset; tests: AtlasCharsetTest.*, Backends/FontAtlasTest.BuildingTwiceGivesIdenticalAtlases, GlyphRectsDontOverlapAndKeepThePadding, EveryCharsetGlyphIsPresent

UTF-8 decoding

DecodeUtf8 never throws. Ill-formed input becomes U+FFFD following Unicode's "maximal subpart" rule: a stray continuation byte, an overlong form (C0/C1, or E0/F0 with a too-small second byte), an encoded surrogate, a value above U+10FFFF or a byte F5–FF gives one U+FFFD per byte, and a sequence cut short gives one U+FFFD for its valid prefix, after which the interrupting byte decodes on its own ("\xE2\x82A" is U+FFFD, A).

Source: text/src/text/Utf8.cpp — DecodeUtf8Next; tests: Utf8DecodeTest.*

Layout

LayoutText(font, utf8, options) returns a TextLayout: one GlyphQuad per visible glyph, one LineInfo per line, the block's bounds, the lineHeight, and the codepoints the font couldn't draw. Distances are in layout units: fontSize layout units per em, which are world units for world-space text and pixels for UI.

  • Quads. position is y-up and uv is y-down, so a quad's top-left corner is (position.minX, position.maxY) with uv (uv.minX, uv.minY). Each quad carries its codepoint and cluster, the byte offset of its source text. Spaces and tabs take room but have no quad.
  • Advances. Each glyph advances by its advance plus letterSpacing ems, plus pair kerning with the next glyph only when that glyph is on the same line. Shapers report kerning separately from the advance (ShapedGlyph::kern) for this reason: a line's last glyph is never kerned against the next line's first, so the line's width (and so its centre or right alignment) isn't off by the kerning. A tab moves to the next multiple of tabWidth space widths from the line start; with tabWidth 0 it is as wide as a space.
  • Option limits. fontSize, maxWidth, lineSpacing and tabWidth below 0 (or NaN) are treated as 0: a negative maxWidth means no wrapping, and a negative lineSpacing stacks every line on one baseline. letterSpacing may be negative, to tighten text.
  • Line breaks. \n and \r\n end a line; a lone \r and other control characters are ignored. A trailing \n gives a final empty line; empty text gives no lines and all-zero bounds.
  • Wrapping (when maxWidth > 0). A line breaks after the last space, tab or hyphen (-, U+2010) that fits. A word with no break opportunity that doesn't fit breaks between characters, but every line holds at least one glyph. Spaces never cause a wrap and trailing spaces don't count towards a line's width; they stay on the line they end. No-break space (U+00A0) is not a break opportunity.
  • Line height is (ascent − descent + lineGap) × fontSize / unitsPerEm × lineSpacing.
  • Horizontal alignment is per line and relative to the origin: Left starts the line at x = 0, Center centres it on x = 0, Right ends it at x = 0. A line's width excludes trailing spaces.
  • Vertical alignment places the block relative to y = 0: Top at the first line's ascent, Middle centred, Bottom at the last line's descent, Baseline at the first line's baseline.
  • Bounds span the widest line horizontally and from the first line's ascent to the last line's descent. Glyph quads can extend past them by the SDF border.

Source: text/src/text/TextLayout.cpp — LayoutText, LineBuilder; tests: Backends/TextLayoutTest.*

Missing glyphs

A codepoint the atlas doesn't have draws as the font's fallback glyph: .notdef if it has an outline, otherwise ?, otherwise nothing (no room taken). The layout's missingCodepoints lists them in order of first appearance. The text library has no logger, so SdfFont::SetMissingGlyphHandler takes a callback, which runs the first time layout meets a missing codepoint and never again for that font. The engine's Font installs one that logs a warning.

Source: text/src/text/Shaper.cpp — BasicShaper::Shape; text/src/text/SdfFont.cpp — SdfFont::ReportMissingGlyph; tests: Backends/TextLayoutTest.MissingGlyphsUseTheFallbackAndAreListed, MissingGlyphsAreReportedOncePerFont

The shaper seam

Layout turns each paragraph into ShapedGlyphs (glyph id, codepoint, cluster, advance and offsets in ems) through an IShaper, then wraps and positions those. The default BasicShaper does no shaping: one glyph per codepoint plus pair kerning. There are no ligatures, combining marks or bidi. LayoutOptions::shaper can point at another implementation, which is where HarfBuzz would plug in without changing callers.

Source: text/include/text/Shaper.hpp; tests: Backends/TextLayoutTest.ACustomShaperReplacesTheBasicOne

The Font asset PR #45

N2Engine::Text::Font (engine/include/engine/text/Font.hpp) is a Base::Asset with resource type "Font". It owns an SdfFont built with the default backend and holds no GPU objects, so it loads headless; renderers create their own textures from its atlas (see TextRenderer).

  • ResourceLoader::Initialize calls Font::RegisterLoader(), which registers the loader for .ttf and .otf with IO::Resources (and so ResourceLoader). It runs once per process; later calls do nothing. Registering from Initialize matters because the static registrar in Font.cpp only runs if the linker keeps that file, and a program that never names Font wouldn't. A program that loads fonts through Resources without ever initializing ResourceLoader should call Font::RegisterLoader() itself. New metadata for those extensions gets resourceType: "Font".
  • When the file is a project asset, the atlas settings come from its .meta customData. Every key is optional; a missing key keeps the default, and a key with the wrong type or an out-of-range value is ignored with a warning. A spreadPx too large for the basePx is reduced to the largest allowed, with a warning. Fonts outside the project use the defaults.
  • A file that can't be read, or isn't a font, logs an error and the load returns null.
  • Font::Layout(utf8, options) is LayoutText with this font, or an empty layout for a font that never loaded. GetAtlasSettings() returns the defaults for a font that never loaded; GetSdfFont() requires IsLoaded().
{
  "uuid": "...",
  "resourcePath": "res://fonts/body.ttf",
  "resourceType": "Font",
  "customData": {
    "font": { "basePx": 48, "spreadPx": 8, "paddingPx": 2, "charset": "latin1", "extraChars": "€…" }
  }
}

charset is "ascii" or "latin1"; extraChars is UTF-8 text whose characters join the charset. Settings are read when the font loads, so after editing them, reload the asset (for example re-Initialize the ResourceLoader, or ClearCache and load it again).

auto font = N2Engine::IO::Resources::Instance().Load<N2Engine::Text::Font>("res://fonts/body.ttf");

N2Engine::Text::LayoutOptions options;
options.fontSize = 0.5f;   // world units per em
options.maxWidth = 4.0f;   // wrap at 4 units
options.horizontalAlign = N2Engine::Text::HorizontalAlign::Center;
const auto layout = font->Layout("Hello, world", options);
// layout.quads: one quad per visible glyph, with uvs into font->GetSdfFont().GetAtlas()

Design decision: fonts are CPU-only assets

A Font holds its face and atlas in memory and never touches a renderer. It loads without a window or GPU (in tests, in the editor host, before the renderer exists), and one font can serve several renderers, each creating its own texture. This avoids the trap audio clips are in, which can't exist without an OpenAL context (no audio clips without a context). The atlas is generated at load time from settings in the .meta, so no generated binaries are committed.

Source: engine/src/text/Font.cpp — Font::ParseAtlasSettings, Font::Load, Font::RegisterLoader, LoadFontFromFile; engine/src/io/ResourceLoader.cpp — ResourceLoader::CreateOrUpdateMetadata; tests: FontSettingsTest.*, FontAssetTest.*

The default font

Font::GetDefault() returns the built-in font with the default atlas settings. It is built on first use and shared after that. It is null only if the embedded font fails to build, which means the build itself is broken: that logs an error, asserts in Debug, and every later call returns null. The font is Noto Sans Regular 2.015 (SIL Open Font License 1.1), subset to printable ASCII, Latin-1 and U+FFFD, about 23 KB. Its pair kerning is stored as a legacy kern table so every backend reads the same pairs. The file, its licence and a README with its source and the subsetting script are in engine/assets/fonts/.

The text target embeds it at build time: a custom command runs text/cmake/EmbedBinary.cmake, which reads the .ttf and writes a C++ array to the build tree, and GetDefaultFontData() returns it. The generated source is never committed, and programs don't need the font file at run time. The script itself is committed: the repository's .gitignore ignores *.cmake, with an exception for text/cmake/*.cmake.

Source: engine/src/text/Font.cpp — Font::GetDefault; text/CMakeLists.txt; text/cmake/EmbedBinary.cmake; engine/assets/fonts/README.md; tests: DefaultFontAssetTest.LoadsFromTheEmbeddedBytes, FontBackendRegistryTest.TheEmbeddedDefaultFontIsATrueTypeFile

The TextRenderer component PR #49

N2Engine::Rendering::TextRenderer (engine/include/engine/rendering/TextRenderer.hpp) is an IRenderable that draws a block of UTF-8 text in the world. The text lies on its GameObject's local x/y plane and faces +Z, so the default camera (looking down −Z) sees it from the front. Adding the component creates the object's Positionable if it has none, like the example renderers. Its scene-file type name is "TextRenderer".

SettingDefaultMeaning
SetTextemptyUTF-8 text; \n breaks lines (see Layout)
SetFontnullA Font asset; null draws with Font::GetDefault(). GetFont() returns what was set, GetEffectiveFont() the font actually used.
SetFontSize1World units per em, so a line of the default font is about 1.36 units tall
SetColorwhiteMultiplies the glyphs; its alpha fades the text
SetHorizontalAlign, SetVerticalAlignLeft, TopWhere the block sits relative to the object's origin, as in Layout
SetMaxWidth0Wrap width in world units; 0 or less never wraps
SetLineSpacing1Multiplies the font's line height
SetLetterSpacing0Extra space between glyphs, in ems; negative tightens

GetLayout() returns the current TextLayout in the object's local units (its bounds are the block's box). It needs no renderer, and lays the text out again only if a setting changed. GetLayoutOptions() gives the LayoutOptions the settings make.

How it draws

  1. Queue. GetRenderQueue() is Transparent with sort key 0, so the text draws after the opaque geometry, sorted back to front by its object's position, with RenderState::Transparent(): blended, depth-tested, not writing depth, back faces culled. Render(renderer) outside a scene uses the same state. (See Rendering the scene.) On the software renderer, which can't blend, the text shader alpha-tests instead and writes depth where it draws PR #TBD; see the software text shader.
  2. Layout. The text is laid out with Font::Layout when any input changes: the text, the effective font, the size, either alignment, the wrap width, or the line or letter spacing. Setting a value equal to the current one is not a change, and a value changed by loading a scene is detected the same way. The colour is not a layout input.
  3. Mesh. TextRenderer::BuildMesh(layout) turns each GlyphQuad into 4 vertices and 6 indices, at z = 0 with normal +Z and white vertex colour. Corners go bottom-left, bottom-right, top-right, top-left (counter-clockwise from +Z), and take the glyph's atlas uvs as they are: uvs are y-down, so the top corners get uv.minY. One text is one mesh and one draw call. The first draw creates the mesh; after a layout change the next draw replaces its data with IRenderer::UpdateMesh, keeping the same mesh. A backend that can't update meshes gets the old one destroyed and a new one created.
  4. Atlas texture. Each font's atlas is uploaded once per renderer, as a single-channel texture with TextureOptions::SdfAtlas() (linear, clamp to edge, no mipmaps; see Texture options). Every TextRenderer drawing that font on that renderer shares it; it is destroyed when the last of them releases it.
  5. Material. Each component has its own material (the text shader plus the shared atlas), whose uAlbedo is set to the colour before every draw.
  6. Draw. The mesh is drawn with the object's local-to-world matrix. Empty text, or text that is only spaces, has no quads and draws nothing; the mesh is kept for when text comes back.

Releasing resources. CleanupRenderResources(renderer) destroys the component's mesh and material on that renderer and releases its share of the atlas texture; for a renderer it holds nothing on, it does nothing. OnDestroy calls it, so destroying the object (or unloading its scene) frees everything. Drawing with a different renderer first releases what the old one held. A component freed without OnDestroy (its object was never in a loaded scene) releases its share of the atlas without calling the renderer, which may already be gone; anything it had created stays with the renderer until the renderer shuts down.

A destroyed renderer. The component keeps the renderer's lifetime token next to the pointer. Once that renderer has been destroyed, the component never calls it again: on its next draw it drops what it held, without destroying anything, and creates new resources on the renderer it is given, even if that renderer has the old one's address (as when Window recreates its renderer). The shared atlas entries carry the token too, so a texture of a destroyed renderer is never handed out.

Guarantee

Drawing the same text again, or changing only its colour, creates and updates nothing: no layout, no mesh upload, no texture or material. A changed layout input updates the existing mesh once, on the next draw. Two texts with the same font on the same renderer share one atlas texture.

Design decision: one cached mesh per text, updated in place

Text that changes every frame (a score, a timer) would otherwise destroy and create a GPU mesh each frame. So each TextRenderer keeps one mesh and compares a snapshot of its layout inputs every draw; only a real change lays the text out again and rewrites the mesh's buffers through UpdateMesh, which on OpenGL reuses the buffers when the new text fits. Comparing inputs, rather than setting a dirty flag in each setter, also catches values written by scene loading, which bypasses the setters. The atlas is a per-font resource, not a per-text one, so it is uploaded once per font and renderer and shared; the colour is a material uniform so that fading or tinting text rebuilds nothing. Batching several texts into one draw is left for later. Decided on #1.

Design decision: renderers are told apart by a lifetime token, not their address PR #49

A component remembers which renderer its resources live on. The pointer alone can't say that: a renderer recreated by Window is a new object that can sit at the old address, and the component would then draw with meshes and textures the old renderer freed. Telling components when a renderer goes away would mean a registry every renderable joins. Instead each IRenderer owns a token, and a holder keeps a weak_ptr to it: unexpired, the pointer is still that renderer; expired, the resources are gone and the pointer is never called. It costs a weak_ptr per component and needs nothing from backends or test fakes. The atlas cache is also deliberately leaked, so a TextRenderer that Lua keeps alive until exit can still release its entry after other statics are gone.

The SDF text shader

IRenderer::GetStandardTextShader() returns the built-in text shader. On OpenGL it reads the atlas's red channel as the distance d (the outline at 0.5, inside higher; the atlas stores the edge at 128, which is 0.502), and computes the coverage as smoothstep(0.5 − w, 0.5 + w, d) with w = 0.5 · fwidth(d): a ramp one screen pixel wide around the outline, so edges stay antialiased at any size or distance with nothing to tune. The colour is uAlbedo times the vertex colour, with the coverage multiplied into its alpha; a fragment whose alpha is below 0.01 is discarded. Outlines, shadows and other effects come later (P5).

Source: renderer/src/opengl/OpenGLRenderer.cpp — OpenGLRenderer::CreateStandardShaders

The software text shader PR #TBD

On the software renderer, GetStandardTextShader() returns a built-in SWShader of type SWShaderType::Text. It exists from the renderer's construction, like the unlit and lit shaders, and DestroyShaderProgram never destroys it. Per pixel that passes the depth test:

  1. Sample. The material's texture is sampled bilinearly at the perspective-correct uv, whatever the texture's filter option, reading only the first channel as the distance d (0 to 1). Texel centres sit at (i + 0.5) / size, as with OpenGL's GL_LINEAR, and neighbours past the edge are clamped or wrapped by the texture's wrap (the atlas is ClampToEdge).
  2. Alpha test. A pixel with d < 0.5 is left untouched: no colour, no depth. The colour is uAlbedo times the interpolated vertex colour; a pixel whose alpha is below 0.01 is also left untouched, as OpenGL discards it.
  3. Write. A covered pixel is written opaque with that colour (its alpha goes into the buffer unchanged, as with the other software shaders), with no blending and no antialiasing, so edges are hard.
  4. Depth. A covered pixel writes its depth whenever the draw depth-tests, even though RenderState::Transparent() says no depth write. With the depth test off (the UI pass's state) nothing writes depth, as in OpenGL.

A text material without a texture draws nothing (OpenGL's unbound sampler reads 0, below the edge). Uniforms are resolved once per draw, like the other software shaders: the per-pixel cost is one bilinear sample and, only for covered pixels, the colour interpolation.

Draw order. The software renderer reorders runs of draws that depth-test and write depth front to back for early-Z (Rendering the scene). Text is ordered by the state it was submitted with: a Transparent-queue text draw doesn't write depth by its state, so it keeps its submission position, after all opaque draws and back to front among the transparent ones. Its depth writes then only affect draws submitted after it.

Design decision: alpha-tested, depth-writing text on the software renderer PR #TBD

The software renderer has no blending, and adding it would mean read-modify-write per pixel on every transparent draw and an ordering the reordering rasterizer would have to respect. An SDF doesn't need it: thresholding the distance at 0.5 gives the glyph's outline exactly, so the shader keeps a pixel or rejects it, like an alpha test. A kept pixel is then an opaque surface, so it writes depth: otherwise anything drawn later behind the text (a transparent quad further back, intersecting geometry) would paint over the glyphs. The price is hard, aliased edges and no fading (alpha only decides whether text draws at all), which is acceptable for a CPU fallback and for tests. Sampling is bilinear because a nearest-sampled distance makes the outline follow the atlas's texel grid; interpolating it keeps outlines smooth at any scale. Keeping text's draw order keyed on its submitted state, rather than on the depth it writes, changes nothing for correctness: an alpha-tested, depth-writing draw gives the same image wherever it sits among depth-writing draws (its rejected pixels write nothing, like occluded ones), and in the Transparent queue it keeps the back-to-front order Scene::Render chose. Decided on #1.

Golden-image tests PR #TBD

Text pixels are tested in CI with the software renderer in headless mode, which needs no window or GPU. Each test renders a frame, reads it back with ReadFramebuffer and checks its structure:

  • Renderer level (SoftwareTextShaderTest in renderer_tests): a quad with a synthetic SDF disc and the text shader. The covered-pixel count is within 8% of πr², the bounding box within a pixel of the disc's; pixels clearly inside are the text colour and pixels clearly outside are untouched (nothing in between: no blending). An opaque quad drawn behind it afterwards leaves every text pixel alone (depth was written), while an unlit draw in the same state is painted over. Also: albedo times vertex colour, alpha 0 and a missing atlas draw nothing, and no depth is written with the depth test off.
  • Engine level (SoftwareTextGoldenTest in engine_tests): a TextRenderer saying "Hi" in the default font, drawn through Scene::Render with an orthographic camera. Every touched pixel is the text colour; the ink's bounding box lies within the projected GetLayout().bounds (2 px tolerance) and stands on the projected baseline (3 px); the glyphs form two clusters of columns separated by a gap, each inside its glyph quad, the H wider than the i. A second test recolours a glyph and checks the same pixels change colour.

Design decision: golden images compare structure, not pixels PR #TBD

CI runs the tests in Debug and Release, whose float code differs (contraction, vectorisation, intermediate precision), and a distance sampled at an edge can land a hair either side of 0.5. An exact image or hash would fail on a one-pixel change no one could see, and would need re-baselining after every harmless rasterizer change; stored reference images would also be binaries in git. So the tests assert what matters and what is stable: counts and bounding boxes within a pixel or a few percent, colours exact (they are not interpolated across the edge), structure such as separated glyphs, and anything relative between two frames of the same run (which is deterministic). Nothing is compared against a file. Decided on #1.

From Lua and scene files

GameObject:AddComponent("TextRenderer") returns a handle with SetText/GetText, SetColor/GetColor, SetFontSize, SetMaxWidth, SetLineSpacing and SetLetterSpacing (each with its getter), plus:

  • SetAlignment(horizontal, vertical) with the names "Left", "Center", "Right" and "Top", "Middle", "Bottom", "Baseline". An unknown name is a Lua error and changes neither alignment. GetAlignment() returns both names.
  • SetFont(path) loads a font through Resources (for example "res://fonts/Title.ttf"); SetFont(nil) goes back to the default font. A path that doesn't load a font is a Lua error and keeps the current font.
  • GetBounds() returns minX, minY, maxX, maxY of the laid-out block, in local units (all 0 for empty text).
local label = GameObject.Create("Label")
local text = label:AddComponent("TextRenderer") -- also gives the object a Positionable
label:GetPositionable():SetPosition(Vector3.new(0, 2, 0))
text:SetText("Score: 0")
text:SetFontSize(0.5)
text:SetAlignment("Center", "Middle")
text:SetColor(Color.Yellow)
SceneManager.GetCurrentScene():AddRootGameObject(label)

Scene files save every setting. Alignments are saved by name, and an unknown name loads as Left / Top. The font is saved as its asset UUID, or null for the default font.
