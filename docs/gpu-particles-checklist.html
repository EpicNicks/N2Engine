GPU particles checklist PR #129

What to run by hand on a Windows PC with an NVIDIA GPU to check the PhysX PBD particle backend, which CI cannot run. Nothing here needs more than the repository and a build with PhysX ON. Report which steps pass, and the text of any warning or crash.

Hardware rule

The PhysX GPU backend is not merged until this checklist and the GPU test have been run on a real GPU PC and their results reported.

Requirements

  • Windows 10 or 11 x64, an NVIDIA GPU of compute capability 7.0 or newer (GeForce RTX 20 series, GTX 16 series or later) and a driver recent enough for CUDA 12.8 (about 570 or newer).
  • Visual Studio with the C++ workload and CMake. The PhysX package for Windows includes PhysXGpu_64.dll; the build copies it next to the executables.

1. Build with PhysX ON

cmake -S . -B build -A x64 -DN2ENGINE_BUILD_TESTS=ON -DN2ENGINE_USE_PHYSX=ON
cmake --build build --config Release --parallel --target engine_tests lua_project
  • Expected: the configure output says PhysX GPU support enabled, and build\bin\Release holds engine_tests.exe, lua_project.exe and PhysXGpu_64.dll.
  • If the configure output says PhysX is unavailable, the build has no GPU backend and every step below will skip or fall back: fix that first.

2. Run the GPU test

build\bin\Release\engine_tests.exe --gtest_filter=PhysXGpuParticlesGoldenTest.*
  • Expected: a line [ GPU ] PhysX GPU: <your card> (CUDA device 0) and [ OK ] PhysXGpuParticlesGoldenTest.SpawnedParticlesFallRespectTheCapAndReleaseCleanly.
  • [ SKIPPED ] means the test could not run; its message says why (no CUDA device, the GPU scene did not come up, PhysXGpu_64.dll missing). That is a failed step here, not a pass.
  • Any crash, hang or a CUDA error printed during the run is a failure, including at the end, when the backend shuts down with a particle system still alive.
  • Also run the whole executable once (engine_tests.exe, no filter) and note whether anything else fails.

3. Run a scene with a PhysX particle system

This uses the existing lua_project scene (station 1 has a static floor at y = -5). Make two small temporary edits, and revert them afterwards.

  1. In lua_project/project.n2proj set the physics setting: "settings": { "physics": { "gpu": "on" } }.
  2. In lua_project/assets/scene.lua, after the floor is created (the for _, gameObject in ipairs({ cube, sphere, floor }) loop), add: 
    local fountain = GameObject.Create("GpuFountain")
fountain:CreatePositionable()
fountain:GetPositionable():SetPosition(Vector3(6.0, 4.0, 0.0))
local ps = fountain:AddComponent("ParticleSystem")
ps:SetBackend("PhysX")
ps:SetPbdMaterial("Water")      -- try "Sand" and "Smoke" in later runs
ps:SetMaxParticles(5000)
ps:SetEmissionRate(400)
ps:SetShape("Cone")
ps:SetShapeRadius(0.3)
ps:SetConeAngle(10)
ps:SetSpeed(1, 2)
ps:SetLifetime(8, 10)
ps:SetSize(0.12, 0.12)
ps:SetStartColor(Color.new(0.3, 0.6, 1.0, 1.0))
ps:SetEndColor(Color.new(0.3, 0.6, 1.0, 1.0))
table.insert(roots, fountain)
  3. Run it with the OpenGL renderer: build\bin\Release\lua_project.exe --renderer opengl (the camera starts at station 1; keys 1 to 7 move between stations).

Expected:

  • The log has no warning mentioning PhysX GPU or couldn't create the system. One line from the probe is fine. If a warning says the GPU backend was switched off, copy it.
  • Blue particles stream from a point to the right of the cube and fall onto the grey floor, where they pile up and spread as a liquid (water preset) instead of passing through it. The count grows to a few thousand and stays there (maxParticles) while old ones expire after 8 to 10 seconds.
  • The cube and the sphere still fall and settle as in the checklist for station 1 (the whole scene now runs on the GPU pipeline, so small differences in how they come to rest are expected).
  • Frame rate stays interactive (note the number; thousands of particles should not stall).
  • Close the window with Escape: the process exits promptly and cleanly, with no crash and no hang.

4. Presets and fallback (optional, short)

  • Change SetPbdMaterial to "Sand", then "Smoke", and rerun: sand should pile into a heap and stop flowing, smoke should drift and spread. These presets are untuned guesses, so say what looks wrong.
  • Set "gpu": "off" (or remove the setting) and rerun: the particle system, still asking for PhysX, must fall back to the CPU backend with one warning, draw particles that fall through the floor (the CPU backend has no collision with it), and nothing else about the scene changes.
  • Run with "gpu": "auto": the same as "on" when the GPU works.

5. Revert the edits

Restore lua_project/project.n2proj and lua_project/assets/scene.lua (git checkout -- lua_project).

What to report

  • The GPU name and driver version, and the lines printed by step 2.
  • For step 3: whether the particles appeared and landed on the floor, the particle count and frame rate you saw, any warning in the log, and how the exit went.
  • Anything that looks wrong in the presets (step 4).
