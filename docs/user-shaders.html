User shaders

A .n2shader file is a fragment shader you write once and use on a Material, a Sprite2D, a UI Image or a particle system, on Vulkan, WebGPU (the browser) and OpenGL, with the editor cooking it when you save. This page is for the person writing one: the file, the names you can use, what is not available, and how to set its parameters. The engineering behind it is in orchestrator/proposals/user-shaders.md; how a pack and the editor handle it is in Packs and Editor projects.

The file

A .n2shader is one text file: a JSON header, then a line that is exactly #stage fragment, then GLSL (version 450 core, no #version line of your own). The engine writes the vertex stage, so a shader is fragment-only and the vertex input and the five varyings are fixed.

{ "n2shader": 1,
  "name": "Dissolve",
  "params": [
    { "name": "baseColor",        "type": "color",   "default": [1, 1, 1, 1] },
    { "name": "baseColorTexture", "type": "texture", "default": "white" },
    { "name": "u_Threshold",      "type": "float",   "default": 0.5, "min": 0, "max": 1, "label": "Threshold" },
    { "name": "u_Edge",           "type": "color",   "default": [1, 0.5, 0, 1] },
    { "name": "u_Noise",          "type": "texture", "default": "white" }
  ],
  "state": { "blend": "alpha", "cull": "none" }
}
#stage fragment
void main() {
    vec4 base  = baseColor * n2_texture(baseColorTexture, n2_UV) * n2_Color;
    float n    = n2_texture(u_Noise, n2_UV).r;
    if (n < u_Threshold) { discard; }
    float edge = 1.0 - smoothstep(0.0, 0.08, n - u_Threshold);
    n2_FragColor = mix(base, u_Edge, edge);
}
  • Header keys: n2shader (the format, 1), name, params, uses (optional, ["lighting"]), state (optional hints) and targets ({"webgpu": "generated"}, the only value). Any other key is an error that names it.
  • Errors cite your file. The generated GLSL is compiled behind a #line directive, so a message reads assets/dissolve.n2shader:14: error: ... with your line number, in the editor (GetShaderInfo, the host log), in n2build and in the engine's log.
  • Line endings may be LF or CRLF; a leading byte order mark is ignored.

  • Names are GLSL identifiers, unique, and do not start with n2_ or gl_ (those are the engine's). They are also the keys scripts and code use.
  • Editor hints label, min, max, step, tooltip and group are ignored by the shader; min and max also clamp a number that is set (it is clamped, not refused).
  • Reserved names bind to the standard fields so a custom shader tints and textures like the built-ins: a color named baseColor is the Material's base colour times the draw's colour (a Sprite2D's or Image's colour, a particle's), and a texture named baseColorTexture is the Material's base colour texture (the sprite's texture) and takes slot 0. Other textures take slots 1–4 in the order declared (or 0–3 without a baseColorTexture).
  • Limits: at most 64 parameters, 5 textures and a 256-byte block (std140 layout, in declaration order). No arrays as parameters (you may use arrays inside the shader); a mat4 takes 64 bytes of the block, so four of them and a few floats use it up.
  • state supplies defaults for a Material that does not set them: blend (none, alpha, additive), cull (none or back), depthWrite, queue (opaque, transparent). They are hints: a value the .mat sets wins, and queue has no effect unless the Material also blends.

What the fragment stage can use

NameWhat it is
n2_UV, n2_Color, n2_WorldPos, n2_Normal, n2_TangentThe vertex stage's outputs: texture coordinates (vec2), vertex colour (vec4; a particle's start-to-end colour, white on a sprite), world position, world normal, world tangent (vec4)
n2_FragColorThe one output, vec4
n2_texture(slot, uv), n2_textureLod(slot, uv, lod), n2_texelFetch(slot, texel, lod), n2_textureSize(slot, lod)Sampling. The slot is the texture parameter's name. Write these, never sampler2D: the spelling differs between backends and the prelude hides it
n2_FragCoord()The pixel position, origin top-left on every backend (raw gl_FragCoord differs, so it is refused)
n2_Model, n2_View, n2_ProjectionThe draw's matrices; n2_Model * v means the same everywhere
n2_StageDim, n2_TintSaturation, n2_TintInside, n2_TintCircleThe per-draw screen-tint values the built-in shaders read (the editor's and the game's screen tint)

Lighting is opt-in: with "uses": ["lighting"] the scene's lights are in the prelude (n2_CameraPos, n2_AmbientLight, n2_NumDirectionalLights and the light arrays) and so are three helpers: n2_LightDiffuse(normal, worldPos), the lit shader's Blinn-Phong diffuse part (ambient plus each light), n2_Attenuation(distance, range, attenuation), and n2_EncodeOutput(color), the sRGB encode for authors lighting in linear space (a no-op unless the project's linear lighting is on). There are no shadows. A shader without uses does not pay for any of it.

What is not available, and the limits

The cook refuses these with a message at your line, so you find out when you save, not when a player runs it:

  • isnan and isinf (WGSL cannot represent NaN or infinity: compare against a large finite number); gl_Position (the vertex stage is the engine's); gl_FragCoord (use n2_FragCoord()), gl_FrontFacing, gl_FragDepth, gl_VertexID, gl_InstanceID and other gl_ inputs.
  • Any uniform, in, out, layout or buffer declaration of your own (parameters come from the header), #extension lines, and 3D, cube, array, shadow and integer textures and images.
  • Atomics, barriers and image access; textureGrad and textureGather.
  • Sample, then branch. Sampling after a discard or inside a non-uniform branch is an error on WebGPU (the browser's rule); sample first (as the example does) or use n2_textureLod / n2_texelFetch, which need no derivatives.
  • In the default (strict) mode, loops need an integer literal or const bound: while and do are refused (a shader that never ends cannot be ruled out in general, so a bounded for is the rule). The cook tool has a --relaxed option for your own use (node tools/n2shader/n2shader.mjs cook --relaxed).
  • Size limits: 256 KiB and 20,000 lines for the file, a 64 KiB header. Everything else that translates to all three backends (inverse, determinant, arrays, switch, fwidth) is allowed.

The conformance corpus in renderer/shaders/user/corpus has a working example of each of these and a refused one of the rest.

Using a shader

  • On a Material: set "shader": "res://shaders/dissolve.n2shader" and "params": {...} in the .mat (or Material::SetShader and the typed setters), and every user of the Material draws with it. In Lua, Material.Load gives the shared asset and renderer:GetMaterialInstance(slot) a copy that is yours alone (Materials).
  • On a Sprite2D, a UI Image or a ParticleSystem (a component with no Material of its own): SetShader gives it a private Material, so one object's values never reach another's. 
    local fx = go:AddComponent('Sprite2D')
fx:SetTexture('res://art/hero.png')
fx:SetShader('res://shaders/dissolve.n2shader')
local m = fx:GetMaterialInstance()       -- the shader's parameters, on this sprite's own material
m:SetFloat('u_Threshold', 0.3)
m:SetColor('u_Edge', Color.Red)
m:SetTexture('u_Noise', 'res://art/noise.png')
    sprite->SetShader(shader);                 // a std::shared_ptr<Shader>, or nullptr for the built-in one
sprite->SetShaderParam("u_Threshold", 0.3f);
sprite->SetShaderParam("u_Edge", Common::Color::Red);
sprite->SetShaderInt("u_Steps", 4);

    The component's texture is the shader's baseColorTexture, its colour the baseColor, and on a renderer that cannot blend the cut-out of a texture's transparent pixels stays. Its saturation and flash are not applied (they are the built-in shaders'; a user shader declares what it reads). A UI Image shows only its sprite through a shader, not a raw texture set with SetTexture. Setting nil goes back to the built-in shader.

  • Not in scene files. A component's shader and its values are runtime state: set them from a script or code, for example in Start. Saving values per object in scenes and prefabs is a later stage.
  • Per frame. Setting a number, vector or colour every frame costs nothing extra (they are uniforms); setting a texture makes a new GPU material, so do it when it changes.

When it cannot be drawn

A Material, sprite, image or particle system whose shader cannot be drawn is never skipped, and never stops a frame: it draws the built-in unlit shader with its base colour and texture, and logs one error naming the shader and the reason. In the editor host the fallback is flat magenta so the failure is obvious; in a player it looks like the object without the shader. The reasons: the shader was never cooked for this backend (or was cooked from an older header: stale), the cook failed (the diagnostics are in GetShaderInfo), the backend has no user shaders (the software renderer), or the compile on the device failed. A pack whose shader sources were stripped (Packs) cannot recompile and uses the fallback when its payload does not fit.

Shaders are not game state

Guarantee

A shader and its parameter values are render-only. Nothing a shader computes can reach the simulation, and no shader value, Material instance or component shader is part of a rollback snapshot, a replication payload or a golden-replay hash. A test sets a Material parameter every frame and checks the state hash does not move; a component's shader is not even a serialized field.
