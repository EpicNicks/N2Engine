GPU soft bodies checklist PR #146

What to run by hand on a Windows PC with an NVIDIA GPU to check the PhysX soft-body backend (deformable volumes), which CI cannot run. Nothing here needs more than the repository and a build with PhysX ON. Report which steps pass, and the text of any warning or crash. If you are also running the GPU particles checklist, do both in one session: the build, the GPU and the project.n2proj edit are shared.

Hardware rule

The PhysX soft-body backend is not merged until this checklist and the GPU test have been run on a real GPU PC and their results reported.

Requirements

  • Windows 10 or 11 x64, an NVIDIA GPU of compute capability 7.0 or newer (GeForce RTX 20 series, GTX 16 series or later) and a driver recent enough for CUDA 12.8 (about 570 or newer).
  • Visual Studio with the C++ workload and CMake. The PhysX package for Windows includes PhysXGpu_64.dll; the build copies it next to the executables.

1. Build with PhysX ON

cmake -S . -B build -A x64 -DN2ENGINE_BUILD_TESTS=ON -DN2ENGINE_USE_PHYSX=ON
cmake --build build --config Release --parallel --target engine_tests lua_project
  • Expected: the configure output says PhysX GPU support enabled, and build\bin\Release holds engine_tests.exe, lua_project.exe and PhysXGpu_64.dll.
  • If the configure output says PhysX is unavailable, the build has no GPU backend and every step below will skip or fall back: fix that first.

2. Run the GPU test

build\bin\Release\engine_tests.exe --gtest_filter=PhysXGpuSoftBodiesGoldenTest.*
  • Expected: a line [ GPU ] PhysX GPU: <your card> (CUDA device 0), a line [ GPU ] cube at rest: height ..., sphere lowest point ... (the cube's height should be a little under 1 and the sphere's lowest point close to 0), and [ OK ] for PhysXGpuSoftBodiesGoldenTest.BodiesFallRestOnTheFloorAndReleaseCleanly and PhysXGpuSoftBodiesGoldenTest.ASoftBodyAndPbdParticlesCoexistInOneScene.
  • [ SKIPPED ] means the test could not run; its message says why (no CUDA device, the GPU scene did not come up, PhysXGpu_64.dll missing). That is a failed step here, not a pass.
  • Any crash, hang or a CUDA error printed during the run is a failure, including at the end, when the backend shuts down with a body still alive. If an assertion fails, copy its text: the messages say which expectation (falling, resting above the floor, finite positions, bounded size, AddVelocity) and the values.
  • The second test needs a soft body and a PBD particle system in one scene: if it fails and the first passes, say so; it is the "one GPU module for particles and deformables" assumption.
  • Also run the whole executable once (engine_tests.exe, no filter) and note whether anything else fails.

3. Run a scene with a PhysX soft body

This uses the existing lua_project scene (station 1 has a static floor whose top is at y = -4.5; there is no soft-body station yet, so you add one). Make two small temporary edits, and revert them afterwards. Run it once with physics.gpu on, then with auto.

  1. In lua_project/project.n2proj set the physics setting: "settings": { "physics": { "gpu": "on" } }.
  2. In lua_project/assets/scene.lua, after the floor is created (the for _, gameObject in ipairs({ cube, sphere, floor }) loop), add: 
    -- A soft sphere (CoRotational) and a soft cube (NeoHookean) above the station 1 floor
local function Jelly(name, mesh, x, model)
    local jelly = GameObject.Create(name)
    jelly:CreatePositionable()
    jelly:GetPositionable():SetPosition(Vector3(x, 2.0, 0.0))
    local mr = jelly:AddComponent("MeshRenderer")
    mr:SetMesh(mesh)
    local sb = jelly:AddComponent("SoftBody")
    sb:SetBackend("PhysX")
    sb:SetResolution(8)
    sb:SetStiffness(100000)         -- try 20000 (softer) and 1000000 (stiffer) in later runs
    sb:SetPoisson(0.3)
    sb:SetMaterialModel(model)
    table.insert(roots, jelly)
    return sb
end
local gpuJellySphere = Jelly("GpuJellySphere", "Sphere", -4.0, "CoRotational")
local gpuJellyCube = Jelly("GpuJellyCube", "Cube", -7.0, "NeoHookean")
  3. Run it with the OpenGL renderer: build\bin\Release\lua_project.exe --renderer opengl (the camera starts at station 1).

Expected:

  • The log has no warning mentioning PhysX GPU soft bodies, GPU soft bodies unavailable or couldn't create the body. One line from the probe is fine. If a warning says the GPU backend was switched off, copy it. The SoftBodies row of the health (Logging, health & editor, or the editor's health panel) should say PhysX GPU: <your card>; SoftBodies: 2 PhysX and be Running.
  • The two jellies fall from about 2 m onto the grey floor (the GPU body collides with the scene's colliders, not a ground plane: collideWithGround is not used), squash, wobble and settle on top of it instead of falling through. They look like deformed meshes, not rigid ones. The cube, the sphere and the floor of station 1 behave as usual.
  • Nothing explodes, flickers to NaN or turns inside out. Note how long the wobble lasts and how stiff each looks; the parameter mapping is an untuned guess.
  • Frame rate stays interactive (note the number).
  • Close the window with Escape: the process exits promptly and cleanly, with no crash and no hang.

4. Material model and fallback checks

  • CoRotational vs NeoHookean. Swap the two model arguments (the sphere NeoHookean, the cube CoRotational) and rerun, then try SetStiffness(20000). CoRotational should be crisper and stiffer, NeoHookean should stay stable at low stiffness. Say which one looks wrong, jitters or turns inside out, and on which mesh.
  • Self collision. Add sb:SetSelfCollision(true) and rerun: nothing should break (the pushes are covered by the GPU test in step 2).
  • Mirrored and scaled objects. Set the cube's scale (jelly:GetPositionable():SetScale(Vector3(-1, 1, 1)) and then Vector3(2, 0.5, 1)) before it is added to roots: both must still fall and settle as soft bodies, never inside out.
  • DLL missing. Rename build\bin\Release\PhysXGpu_64.dll and rerun: the jellies must start on the CPU backend (physics.gpu on reports the failed probe as an error status, auto a quiet one) with one warning each at most, fall onto the floor only if you give them sb:SetGround(true, -4.5) (the CPU body collides with the ground plane, not the floor collider), and nothing crashes. Put the file back.
  • physics.gpu off. Set "gpu": "off" (or remove the setting) and rerun: the bodies (still asking for PhysX) start on the CPU backend with one warning each, and nothing else about the scene changes.
  • Both features. Add the particle fountain of the particles checklist as well: particles and jellies run in one scene and neither feature fails.

5. Revert the edits

Restore lua_project/project.n2proj and lua_project/assets/scene.lua (git checkout -- lua_project), and put PhysXGpu_64.dll back if you renamed it.

What to report

  • The GPU name and driver version, and the lines printed by step 2 (including the cube and sphere numbers).
  • For step 3: whether the bodies appeared, fell, landed on the floor and settled, the frame rate, any warning in the log, the SoftBodies health row text and how the exit went.
  • For step 4: which material model looked better on which mesh, whether anything went inside out or unstable, how the pushes, mirrored and scaled bodies and the fallbacks behaved, and what the missing DLL logged.
  • Anything that looks wrong in the stiffness, damping or wobble compared with the CPU backend (sb:SetBackend("CPU") with sb:SetGround(true, -4.5) is the comparison).
