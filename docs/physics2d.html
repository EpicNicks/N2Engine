2D physics

2D rigid bodies, colliders, triggers, events and queries on Box2D v3. It is separate from the 3D physics and follows the same rules wherever it can. Scripts use it through the same names.

Components

ComponentWhat it does
Rigidbody2D PR #313A body: Static, Dynamic or Kinematic; linear and angular velocity; damping; gravity scale; fixed rotation; bullet; mass; forces and impulses.
BoxCollider2D, CircleCollider2D, PolygonCollider2DOne shape each, on the object's Rigidbody2D, or on a static body of its own when it has none. Each has an offset, trigger flag, PhysicsMaterial, density and surface speed.

Include engine/physics2d/Rigidbody2D.hpp, Collider2D.hpp and Physics2DQueries.hpp. The namespace is N2Engine::Physics2D.

The plane and units

  • A body uses the object's world x, y and rotation about z. z is left alone.
  • X or Y tilt on a rotating body is replaced by a pure z rotation at the first sync. A body with fixed rotation keeps the rotation it has.
  • 1 unit is 1 metre. Box2D is tuned for moving objects of about 0.1 to 10 units.
  • Collider sizes ignore the transform's scale, as the 3D colliders do.
  • Gravity starts at (0, -9.81). Physics2DWorld::SetGravity changes it for every world, live and future, and wakes their dynamic bodies. A top-down game sets it to zero.

The world

Each Scene owns one world, created by the first 2D component that attaches, so a scene without 2D components has no world. It is freed when the scene is cleared. The prefab stage's parked scene keeps its own world, so its bodies and the stage's cannot meet, and only the loaded scene steps.

An object moved to another scene gets a new body in that scene's world, and its velocity is not carried over.

The fixed step

  1. 3D and then 2D ApplyPendingChanges: transforms changed since the last step reach the bodies.
  2. scene.FixedUpdate().
  3. The 3D step, sync and events.
  4. 2D: simulate, write moved bodies back to their transforms, then deliver events.

It is single-threaded (one worker, no task system), reads no clock that affects the result, and runs with the same fixed delta as 3D. 2D works with no 3D backend. See Fixed steps and physics.

Changing a transform on aDoes
Kinematic bodyMoves there in one step, with velocity, so it carries what stands on it. Then the velocity the game set applies again. A move too far for one step at Box2D's speed limit (400 units per second, so 8 units in a 0.02 s step) teleports instead.
Dynamic or static bodyTeleports, and wakes the body and what touches it. This differs from 3D, where a dynamic body ignores it. A touch that really ends gets its Exit in that step.

Events

Every Component has OnCollisionEnter2D, Stay2D and Exit2D taking const Collision2D &, and OnTriggerEnter2D, Stay2D and Exit2D taking const Trigger2D &. They follow the 3D rules:

  • Per body pair: Enter on the first touching shape pair, Exit on the last, and Stay every step while touching, including the step of the Enter. A pair that ends and begins again within one step, such as a body crossing between two shapes of a compound body, raises neither.
  • In order: Exits of removed things, collision Enter, Stay, Exit, then trigger Enter, Stay, Exit. Pairs go in body handle order.
  • Both sides receive each event, every component on the object, each from its own point of view. An inactive object gets nothing.
  • A contact normal points from the other collider to this one.

Design decision: changes inside a handler run immediately

No engine or game code runs while Box2D is stepping, because no callback that runs inside the step is registered. Events are copied before the first handler, and each component's data is built just before it is called, so a collider or Rigidbody2D that an earlier handler removed reads as null. A handler that ends a pair before its Enter was delivered cancels that Enter and its Exit. So a handler can create and destroy bodies directly. Queuing those changes would make SetLinearVelocity right after creating a body silently do nothing. GameObject::Destroy stays deferred to the end-of-frame purge, as always.

Warning: collision data is after the solve

relativeVelocity is this body's velocity minus the other's after the step, so it is not the approach speed. For a mirror, give the shapes restitution 1 and friction 0 instead of reflecting by hand.

Warning: fast projectiles

A fast moving trigger can miss overlaps. Make a projectile a solid bullet body filtered by layer, or use a shape cast.

Bodies and shapes

  • Mass comes from the solid colliders' density (default 1) unless SetMass overrides it, which rescales the inertia. In 3D the mass is always authoritative. UseAutoMass goes back.
  • Triggers add no mass. A dynamic body with only triggers gets mass 1, so it still responds to forces.
  • Toggling a trigger re-creates the shape, because Box2D cannot change it. Its pairs end with an Exit and start again if still overlapping.
  • Material: dynamicFriction and restitution apply. staticFriction does not, as Box2D has one coefficient. Box2D combines two shapes by the geometric mean of friction and the larger restitution, unlike the 3D average.
  • Conveyors: SetSurfaceSpeed moves what touches the surface. On a shape's top surface, a positive speed moves things toward +x.
  • Invalid values (a negative density, damping, friction or restitution, anything not finite) log a warning and use a safe value, or make no shape for bad geometry.
  • Polygons take 3 to 8 points, wrapped in their convex hull. Geometry Box2D cannot use logs a warning and makes no shape. Vertices save in scenes and prefabs as JSON; the editor has no dedicated list editor for them yet.

Layers

2D uses the same 32 layers and collision matrix, with no second copy. A shape's category is its object's layer and its mask is that layer's matrix row. A matrix change or GameObject::SetLayer reaches every live world; a pair the matrix now rules out ends with an Exit, and one it now allows starts with an Enter. Triggers obey it too. The matrix does not affect queries, only their layer mask does.

Queries

Raycast, RaycastAll, CircleCast, BoxCast, OverlapCircle and OverlapBox, on the loaded scene's world, with a layer mask and QueryTriggers. They follow Physics::QueryRules:

  • Degenerate input finds nothing, and so does an empty mask or having no world.
  • A start inside a collider hits at distance 0, with the normal against the direction and the point at the start. For a ray, a start on a surface and pointing away, as in a ricochet, is not inside.
  • Nearest first; hits within the tie tolerance go by body handle, then collider order. Overlaps go by body handle, then collider order.
  • Triggers are hit by default.
  • One difference: every distance is clamped to kMaxSweepDistance, rays included.

From Lua PR #314

The components have the same method names as in C++, through AddComponent("Rigidbody2D") and the rest, with the same checked handles as 3D: using one after its object is gone is a Lua error.

local Crate = {}
Crate.__index = Crate

function Crate:OnCollisionEnter2D(collision)
    local contact = collision:GetContact(1)
    if contact then print(collision.otherGameObject:GetName(), contact.normal.y) end
end

function Crate:OnTriggerEnter2D(trigger)
    trigger.otherGameObject:Destroy()
end

return Crate

A script handles OnCollisionEnter2D, OnCollisionStay2D, OnCollisionExit2D, OnTriggerEnter2D, OnTriggerStay2D and OnTriggerExit2D. The argument is safe to keep after the callback. It has every member of the 3D Collision and Trigger, and also collider and otherCollider, as their concrete types, and nil when removed.

A layer mask is a whole number; -1 means every layer, and the default is every layer but Ignore Raycast. An optional argument of the wrong type is a Lua error, not the default. A negative distance finds nothing. BodyType2D.Static, Dynamic and Kinematic are the body types. Annotations are in engine-api.lua.

Networking

Covered by rollback and the desync hash issue #381

The 2D world is in the rollback snapshot and in the state hash. A RollbackRuntime whose scene has a 2D world keeps its rollback window; the lockstep fallback and the stop for a late 2D world of PR #382 and #390 are gone. Since snapshot format 3 a late joiner or spectator of a scene with a 2D world starts from the 2D state too (Rollback, late join). What still does not work is listed there: a 2D world created after the session started cannot be rewound past its creation. Creating a world in SimulationMode::Deterministic logs one warning about the strict floating-point build. A game that uses it should build with N2ENGINE_STRICT_FP (the default now, math), as for any physics under the Deterministic preset.

Rollback

Physics2DWorld::SaveState and RestoreState are the 2D side of the rollback seam (orchestrator/proposals/custom-physics-156.md, sections 4.2 and 8), next to IPhysicsBackend::SaveState for 3D. RollbackWorld::Save puts the bytes in WorldSnapshot::physics2d (with hasPhysics2d) when the scene has a 2D world, and Restore puts them back after the objects, the fields and the 3D physics, so the transforms the restore writes are the restored poses.

The state is Box2D's own snapshot (b2World_GetSnapshot and b2World_RestoreFromSnapshot, vendored v3.2.0, which Box2D marks experimental: the format may change in a later version, so the bytes belong to the build that made them and are never stored; they travel only to a late joiner of the same session, below) plus what the engine keeps beside it: per body its enabled flag, type, fixed rotation and mass mode, which collider owns which shape (the collider is named by its index among the Collider2D components of the body's object, never by address), and the touching pairs that OnCollision*2D and OnTrigger*2D are made from. Box2D's image holds the contact cache, sleep timers, the id pools and every solver set, so a restored world steps exactly like the world that was saved: Physics2DWorld::HashState (Box2D's deep hash over bodies, contacts and id pools) is equal after save, restore and the same ticks again (Physics2DRollbackTest in tests/engine/physics2d).

Hash. The network state hash has one more leaf on object 0, kPhysics2DFieldId, from HashSimulatedState: pose, velocities, sleep state and type of every enabled body, in handle order, not the handles. A body a rollback keeps parked (disabled) is left out, so a peer that has not released a despawned object yet hashes like one that has, the same rule as the 3D leaf. The leaf is present whenever the scene has a 2D world, in lockstep and rollback alike. Unlike HashState it does not cover the contact cache; a difference there shows in the poses within a tick.

Bodies made after the restored instant. A body that did not exist when the snapshot was taken is gone after a restore (Box2D rebuilds the world from the image), and its Rigidbody2D and Collider2D lose it (OnBodyLost). For a networked object that was spawned since, this is what makes the rollback exact: the object is not pooled for the respawn, a fresh instance is made and gets its body from the same id pool in the same order as the first time (RollbackWorld::Spawn). (A spawned object always gets a net id past the snapshot's counter, so its body is always one of those: a 2D object is never taken back from the pool.) A body made after the snapshot by an object that is not networked has no such second life: its components stay without a body after a rollback. Create such objects before the session, or make them networked. A body destroyed after the snapshot by an object that is not networked is removed again after the restore, not brought back.

Late join and spectators snapshot format 3. The serialised snapshot (SerializeWorldSnapshot, netcode) carries the 2D state, each networked object's 2D bodies (per hierarchy node: its Rigidbody2D's body, then each Collider2D's own static body, with the node's pose and the body's velocities) and the objects that were parked when it was saved. A host answers a spectator's snapshot request for a scene with a 2D world. RollbackWorld::RestoreForJoin makes and parks the parked objects too (so their disabled bodies are in the joiner's world, as on the host), then calls Physics2DWorld::RestoreStateForJoin: each 2D body of a networked object takes the handle the snapshot gives the body of the same net id, node and order (the joiner made its bodies in net id order, the host in whatever slots Box2D had free), the rest keep theirs (scene objects that are not networked load the same way on both), and Box2D's world becomes the host's, contacts, sleep timers and id pools included. Body and shape ids are moved into the joiner's own world slot. Before that, every 2D node of a networked object, live or parked, is placed at its saved pose (transforms are not replicated values, and the restore writes back only enabled dynamic bodies' poses, so a static collider's object the game moved after spawning it would keep its prefab's pose otherwise). An object parked on both peers takes the snapshot's park reason and tick (NetworkWorld::Repark), so both release it at the same tick, and every object the join instantiates keeps what Spawn keeps for a fresh instance, so a later spawn of its id can take it back from the pool as on the host. JoinRestoreResult::exactPhysics2d is true when every 2D body matched; lost2d counts bodies of the joiner that are not the snapshot's (they lose their body, as after a rollback) and removed2d bodies of the snapshot no component of the joiner owns. When the joiner's build cannot read the Box2D image (another Box2D version, precision or layout: the image header is compared first, and nothing changes), the networked objects' 2D bodies are put back from their saved poses and velocities and exactPhysics2d is false; RollbackRuntime::CheckJoinPhysics then fails a spectator unless the host allows inexact physics, the same rule as for the 3D part. Tests: Rollback2DJoinTest (a spawned static wall the host moved, and a parked one, are placed where the host has them; a joiner takes a snapshot whose shots reused freed Box2D slots and that holds parked shots: the root and Box2D's deep hash, id pools included, equal the host's at the join and for 60 ticks after; a changed image header is refused with the bodies put back from their saved poses, and a snapshot without a 2D part into a scene with one is refused) and the spectator of Rollback2DApplicationTest (served through the relay by the rollback player, its view's checkpoint roots equal the player's).

Limits. (1) A joiner and the host agree after the join only as far as they release parked objects at the same ticks: ReleaseConfirmed frees Box2D slots, and a later shot takes the slot freed last. Lockstep peers release at the same confirmed ticks; rollback peers release when their confirmations arrive, so their id pools can differ afterwards (the session hash names no handles, but it lists bodies in handle order). (2) A 2D world created after the session started has no state in the snapshots older than itself: restoring one fails with an error that stops the session, rather than rewinding everything but Box2D. Create the 2D world before the session starts. (3) Box2D's joints, chains and the engine's own queries are not part of what the wrapper creates, so they are not in the wrapper's records; the 2D components create none of them. (4) Box2D's results are the same across CI legs (tests/box2d), but only on a strict floating-point build can two machines be expected to agree.

Source: engine/src/physics2d/Physics2DWorld.cpp (SaveState, RestoreState, HashSimulatedState), engine/src/network/RollbackWorld.cpp, engine/src/network/StateHash.cpp; tests Physics2DRollbackTest, Rollback2DTest and Rollback2DJoinTest.

Leaving it out of a game

A game that does not use 2D physics can build with -DN2ENGINE_USE_BOX2D=OFF:

  • No Box2D code is in the binary. Only engine/src/physics2d/Physics2DWorld.cpp names Box2D, and without the option it compiles to a Create that returns null.
  • The components still register and keep their data, so a scene loads and saves unchanged and the network fingerprint does not depend on the option. They do nothing, with one warning, and queries find nothing. Scripts keep working: Physics2D and the component types are still there.

Compiled in but unused costs a null check per step and per transform change, and no Box2D allocation. The linker cannot remove the module by itself, because RegisterBuiltinComponents names every component type. Sizes are in the web build page.
