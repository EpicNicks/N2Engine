2D physics

2D rigid bodies, colliders, triggers, events and queries on Box2D v3. It is separate from the 3D physics and follows the same rules wherever it can. Lua bindings are not in yet.

Components

ComponentWhat it does
Rigidbody2D PR #313A body: Static, Dynamic or Kinematic; linear and angular velocity; damping; gravity scale; fixed rotation; bullet; mass; forces and impulses.
BoxCollider2D, CircleCollider2D, PolygonCollider2DOne shape each, on the object's Rigidbody2D, or on a static body of its own when it has none. Each has an offset, trigger flag, PhysicsMaterial, density and surface speed.

Include engine/physics2d/Rigidbody2D.hpp, Collider2D.hpp and Physics2DQueries.hpp. The namespace is N2Engine::Physics2D.

The plane and units

  • A body uses the object's world x, y and rotation about z. z is left alone.
  • X or Y tilt on a rotating body is replaced by a pure z rotation at the first sync. A body with fixed rotation keeps the rotation it has.
  • 1 unit is 1 metre. Box2D is tuned for moving objects of about 0.1 to 10 units.
  • Collider sizes ignore the transform's scale, as the 3D colliders do.
  • Gravity starts at (0, -9.81). Physics2DWorld::SetGravity changes it for every world, live and future, and wakes their dynamic bodies. A top-down game sets it to zero.

The world

Each Scene owns one world, created by the first 2D component that attaches, so a scene without 2D components has no world. It is freed when the scene is cleared. The prefab stage's parked scene keeps its own world, so its bodies and the stage's cannot meet, and only the loaded scene steps.

An object moved to another scene gets a new body in that scene's world, and its velocity is not carried over.

The fixed step

  1. 3D and then 2D ApplyPendingChanges: transforms changed since the last step reach the bodies.
  2. scene.FixedUpdate().
  3. The 3D step, sync and events.
  4. 2D: simulate, write moved bodies back to their transforms, then deliver events.

It is single-threaded (one worker, no task system), reads no clock that affects the result, and runs with the same fixed delta as 3D. 2D works with no 3D backend. See Fixed steps and physics.

Changing a transform on aDoes
Kinematic bodyMoves there in one step, with velocity, so it carries what stands on it. Then the velocity the game set applies again. A move too far for one step at Box2D's speed limit (400 units per second, so 8 units in a 0.02 s step) teleports instead.
Dynamic or static bodyTeleports, and wakes the body and what touches it. This differs from 3D, where a dynamic body ignores it. A touch that really ends gets its Exit in that step.

Events

Every Component has OnCollisionEnter2D, Stay2D and Exit2D taking const Collision2D &, and OnTriggerEnter2D, Stay2D and Exit2D taking const Trigger2D &. They follow the 3D rules:

  • Per body pair: Enter on the first touching shape pair, Exit on the last, and Stay every step while touching, including the step of the Enter. A pair that ends and begins again within one step, such as a body crossing between two shapes of a compound body, raises neither.
  • In order: Exits of removed things, collision Enter, Stay, Exit, then trigger Enter, Stay, Exit. Pairs go in body handle order.
  • Both sides receive each event, every component on the object, each from its own point of view. An inactive object gets nothing.
  • A contact normal points from the other collider to this one.

Design decision: changes inside a handler run immediately

No engine or game code runs while Box2D is stepping, because no callback that runs inside the step is registered. Events are copied before the first handler, and each component's data is built just before it is called, so a collider or Rigidbody2D that an earlier handler removed reads as null. A handler that ends a pair before its Enter was delivered cancels that Enter and its Exit. So a handler can create and destroy bodies directly. Queuing those changes would make SetLinearVelocity right after creating a body silently do nothing. GameObject::Destroy stays deferred to the end-of-frame purge, as always.

Warning: collision data is after the solve

relativeVelocity is this body's velocity minus the other's after the step, so it is not the approach speed. For a mirror, give the shapes restitution 1 and friction 0 instead of reflecting by hand.

Warning: fast projectiles

A fast moving trigger can miss overlaps. Make a projectile a solid bullet body filtered by layer, or use a shape cast.

Bodies and shapes

  • Mass comes from the solid colliders' density (default 1) unless SetMass overrides it, which rescales the inertia. In 3D the mass is always authoritative. UseAutoMass goes back.
  • Triggers add no mass. A dynamic body with only triggers gets mass 1, so it still responds to forces.
  • Toggling a trigger re-creates the shape, because Box2D cannot change it. Its pairs end with an Exit and start again if still overlapping.
  • Material: dynamicFriction and restitution apply. staticFriction does not, as Box2D has one coefficient. Box2D combines two shapes by the geometric mean of friction and the larger restitution, unlike the 3D average.
  • Conveyors: SetSurfaceSpeed moves what touches the surface. On a shape's top surface, a positive speed moves things toward +x.
  • Invalid values (a negative density, damping, friction or restitution, anything not finite) log a warning and use a safe value, or make no shape for bad geometry.
  • Polygons take 3 to 8 points, wrapped in their convex hull. Geometry Box2D cannot use logs a warning and makes no shape. Vertices save in scenes and prefabs as JSON; the editor has no dedicated list editor for them yet.

Layers

2D uses the same 32 layers and collision matrix, with no second copy. A shape's category is its object's layer and its mask is that layer's matrix row. A matrix change or GameObject::SetLayer reaches every live world; a pair the matrix now rules out ends with an Exit, and one it now allows starts with an Enter. Triggers obey it too. The matrix does not affect queries, only their layer mask does.

Queries

Raycast, RaycastAll, CircleCast, BoxCast, OverlapCircle and OverlapBox, on the loaded scene's world, with a layer mask and QueryTriggers. They follow Physics::QueryRules:

  • Degenerate input finds nothing, and so does an empty mask or having no world.
  • A start inside a collider hits at distance 0, with the normal against the direction and the point at the start. For a ray, a start on a surface and pointing away, as in a ricochet, is not inside.
  • Nearest first; hits within the tie tolerance go by body handle, then collider order. Overlaps go by body handle, then collider order.
  • Triggers are hit by default.
  • One difference: every distance is clamped to kMaxSweepDistance, rays included.

Networking

Warning: not covered by the network modes

2D state is not in the desync hash and a rollback does not restore it, so a rollback session would rewind everything except the 2D world. Creating a world in SimulationMode::Deterministic logs one warning. Box2D's results have matched across CI legs (tests/box2d, and the determinism test in tests/engine/physics2d), which is the basis for adding this later.

Leaving it out of a game

A game that does not use 2D physics can build with -DN2ENGINE_USE_BOX2D=OFF:

  • No Box2D code is in the binary. Only engine/src/physics2d/Physics2DWorld.cpp names Box2D, and without the option it compiles to a Create that returns null.
  • The components still register and keep their data, so a scene loads and saves unchanged and the network fingerprint does not depend on the option. They do nothing, with one warning, and queries find nothing.

Compiled in but unused costs a null check per step and per transform change, and no Box2D allocation. The linker cannot remove the module by itself, because RegisterBuiltinComponents names every component type. Sizes are in the web build page.
