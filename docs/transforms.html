Transforms

A GameObject's spatial state lives in an optional Positionable, which stores the local transform and computes the world transform lazily from its parent. This page covers local vs world access, how world values are derived, dirty tracking, reparenting with keepWorldPosition, edge cases with zero or tiny scale, and how transform changes reach physics.

Positionable and Transform

Unlike Unity, a GameObject has no transform by default. GameObject::CreatePositionable() creates one (no-op if present); GetPositionable() returns nullptr until then, and HasPositionable() tells which. Some components create one on demand: Rigidbody::OnAttach and ICollider::OnAttach call CreatePositionable() if the object has none. A Positionable starts at the identity (position 0, identity rotation, scale 1).

Transform is a value type holding position, rotation (Math::Quaternion), scale and a cached TRS matrix. Its setters and GetMatrix() are private (only Positionable uses them). Outside code can read a Transform and obtain one from Transform::Identity(), Transform::Combine, or Positionable::GetLocalTransform()/GetGlobalTransform(), but cannot build an arbitrary one; Positionable::SetLocalTransform is therefore mainly useful to copy one object's local transform to another.

Source: engine/include/engine/Positionable.hpp; engine/include/engine/Transform.hpp; engine/src/gameobject/GameObject.cpp — GameObject::CreatePositionable

Local and world values

SpaceGettersSetters
Local (relative to the parent's Positionable)GetLocalPosition, GetLocalRotation, GetLocalScale, GetLocalTransformSetLocalPosition, SetLocalRotation, SetLocalScale, SetLocalPositionAndRotation, SetLocalTransform
WorldGetPosition, GetRotation, GetScale, GetGlobalTransform, GetLocalToWorldMatrix, GetWorldToLocalMatrixSetPosition, SetRotation, SetScale, SetPositionAndRotation

Direction helpers (GetForward, GetBack, GetLeft, GetRight, GetUp, GetDown) rotate the corresponding Vector3 constant by the world rotation. TransformPoint/InverseTransformPoint use the full local-to-world matrix (and its inverse); TransformDirection/InverseTransformDirection use the world rotation only, ignoring scale.

Local setters only do work if the new value differs (exact != comparison); setting the same value does not dirty anything or notify physics. Only the local transform is serialized (localPosition, localRotation, localScale).

From Lua, the Positionable handle exposes the world getters and setters (GetPosition/SetPosition, rotation, scale) and GetForward/GetRight/GetUp, but no local-space accessors; see Lua scripting.

Note

"Parent" here means the parent GameObject's Positionable. If the direct parent has no Positionable, the object is treated as a root for transform purposes (world = local), even if a grandparent has one: the lookup does not skip levels.

How the world transform is computed

Transform::Combine(parentWorld, childLocal):

  • position = parentPos + parentRot × (parentScale ⊙ childPos)
  • rotation = parentRot × childRot
  • scale = parentScale ⊙ childScale (component-wise)

The position and rotation match the TRS matrix (GetLocalToWorldMatrix). The world scale is a component-wise product, so under a rotated parent with non-uniform scale it is an approximation (the true matrix has shear, which a Transform cannot represent), similar to Unity's lossyScale.

The world transform is computed on demand and cached: a world getter recomputes only if the cache is dirty, recursively asking the parent for its (possibly recomputed) world transform.

Source: engine/src/Transform.cpp — Transform::Combine, Transform::BuildMatrix; engine/src/Positionable.cpp — CalculateGlobalTransform, UpdateGlobalTransform

Setting world values

SetterConverts to local by
SetPosition(p)parent->InverseTransformPoint(p) (inverse of the parent's world matrix)
SetRotation(r)parentWorldRot.Inverse() * r
SetScale(s)s / parentWorldScale per axis; on an axis where the parent's world scale is exactly 0, the current local value is kept
SetPositionAndRotation(p, r)Both of the above, applied as one change (one dirty/notify)

With no parent Positionable, world setters write the local values directly.

Guarantee

SetScale under a parent with a zero scale axis leaves the child's local scale on that axis unchanged (finite) and converts the other axes normally. Before PR #24 this divided by zero and produced NaN.

Test: SetScaleUnderAZeroParentAxisStaysFinite.

Warning

SetPosition, SetPositionAndRotation and InverseTransformPoint invert the parent's world matrix. The scalar inverse throws std::runtime_error("Matrix is singular and cannot be inverted") when |det| < 1e-7. For a TRS matrix the determinant is the product of the three scale components, so this throws not only for a zero scale axis but also for a small uniform scale (below about 0.0046 per axis). SetScale's zero-axis guard does not protect these calls.

Source: engine/src/Positionable.cpp — SetPosition, SetRotation, SetScale, SetPositionAndRotation, GetWorldToLocalMatrix; math/include/math/Matrix.hpp — InverseScalar; tests: CoreRobustnessTests

Dirty tracking

Each Positionable keeps a cached world transform and a dirty flag. Every effective local change calls MarkGlobalTransformDirty, which runs in this order:

  1. If the cache was clean, set the dirty flag and increment the hierarchy version counter.
  2. Notify physics on this object (see below). This happens after the flag is set, so a consumer that reads the world transform gets the new pose.
  3. Recurse into every child that has a Positionable.

Steps 2 and 3 run on every change, even when the object was already dirty. OnHierarchyChanged() (called by AddChild/RemoveChild) does the same.

Note

Always notifying was a deliberate decision in the PR #19 review. Before, physics was notified before the flag was set (so it read the stale pose), and a second move before any read took an early-out and never reached physics. The reviewer proposed restoring the early-out in the new order; it was kept as always-notify because the early-out relies on every notified consumer reading (and so cleaning) the transform, and Rigidbody::OnTransformChanged returns early for dynamic bodies without reading. A dynamic body would stay dirty, and if it were then switched to kinematic, its next move would be swallowed. The cost is that each change walks the whole subtree and scans each descendant's components, and SyncTransforms triggers this for every dynamic body each fixed step.

Open question

Positionable writes _hierarchyVersion, _cachedHierarchyVersion and _globalTransformValid, but nothing reads them and there is no accessor. They look like leftovers of a planned change-detection API; only IsGlobalTransformDirty() is public.

Source: engine/src/Positionable.cpp — MarkGlobalTransformDirty, MarkChildrenGlobalTransformDirty, OnHierarchyChanged, UpdateGlobalTransform; PR #19 review thread

Reparenting and keepWorldPosition

AddChild, RemoveChild and SetParent take keepWorldPosition (default true). Hierarchy semantics are on GameObjects & components.

  • keepWorldPosition == true and both child and parent have a Positionable: the child's world position, rotation and scale are read, the link is changed, OnHierarchyChanged dirties the child, then SetPosition, SetRotation and SetScale restore the world values (computing new local values).
  • Otherwise: the local values are kept and only OnHierarchyChanged runs, so the world pose changes to local-under-the-new-parent.

When the parent has no Positionable, both choices give the same world pose (the child's world equals its local value).

SetParent(newParent) unlinks the object from its old parent (the private DetachChild(this, keep), which RemoveChild also uses) and then calls newParent->AddChild(this, keep), so with keep the world pose is restored twice (first as a parentless object, then under the new parent). Scene deserialization uses AddChild(child, false): stored local values are kept as-is.

// Attach a weapon to a hand bone without moving it in the world
hand->AddChild(weapon);                 // keepWorldPosition = true

// Snap it to the hand's local origin instead
weapon->GetPositionable()->SetLocalPosition(N2Engine::Math::Vector3{0.0f, 0.0f, 0.0f});

Warning

With keepWorldPosition and a parent whose world matrix is singular (see Setting world values), the restore's SetPosition throws inside AddChild and the object is left half-reparented. By then a root child has already been erased from its scene's root list and removed from any old parent, and it is linked under the new parent, but its SetScene and active-state notifications never ran: _scene still points at the scene it came from (stale if the new parent is in another scene or none), its components were not re-queued, and no OnEnable/OnDisable fired. Catching the exception does not undo any of this. Pass keepWorldPosition = false when parenting under a zero- or tiny-scale object.

Note

The restore is exact for position and rotation; scale goes through the component-wise conversion, so under rotated non-uniformly scaled parents the restored world scale follows the same approximation as Combine.

Source: engine/src/gameobject/GameObject.cpp — GameObject::AddChild, RemoveChild, SetParent, Deserialize

Transform and physics

On every MarkGlobalTransformDirty, the Positionable notifies its own object's physics components (NotifyPhysicsComponents):

  • If GetComponent<Physics::Rigidbody>() finds a Rigidbody that is not destroyed, only Rigidbody::OnTransformChanged is called.
  • Otherwise every collider (GetComponents<Physics::ICollider>()) gets ICollider::OnTransformChanged.

The Rigidbody is looked up on every notification, not cached: a cached pointer dangled after RemoveComponent<Rigidbody> (fixed in PR #19).

ComponentOn transform change
Rigidbody, not yet initialized (no body created, e.g. no backend)Nothing.
Rigidbody, DynamicIgnored. Physics owns the pose; a script's SetPosition on a dynamic body does not move the body and is overwritten by the next fixed step's SyncTransforms.
Rigidbody, Kinematicbackend->SetBodyTransform with the new world position and rotation: the body follows the transform.
Rigidbody, Staticbackend->SetStaticBodyTransform; in debug builds also logs a warning on every move.
Collider with no Rigidbody (it owns its own static body)SetStaticBodyTransform with the world pose. Every 10th such move (counted across all colliders) logs a warning recommending a kinematic Rigidbody.
Collider attached to a Rigidbody's bodyNot notified (the Rigidbody is).

In the other direction, after each simulation step PhysXBackend::SyncTransforms writes the PhysX pose back with Positionable::SetPositionAndRotation, for simulated dynamic bodies only. Kinematic bodies are skipped, so the physics pose never overwrites a script's move that PhysX has not consumed yet. That write-back itself goes through MarkGlobalTransformDirty: the dynamic body ignores it, while kinematic or static children of the moved object follow.

Guarantee

A kinematic body follows the latest transform even when it is moved twice before anything reads the transform, and the script's position is not overwritten by the physics pose.

Test: KinematicBodyFollowsLatestTransform (requires the PhysX backend).

Notification happens for children too, because MarkGlobalTransformDirty recurses: moving a parent moves its kinematic children's bodies. See Physics for body types and the fixed step.

Matrix math before InitializeSIMD

Transform math uses Math::Matrix<float,4,4> (and 3×3), whose operations dispatch through static function pointers chosen by Math::InitializeSIMD(). Only Application::Init calls that. The pointers default to the scalar implementations, so inverse(), TransformPoint and the rest work before initialization (in tests, tools, or code that runs before Init). Previously they were null until InitializeSIMD, and any matrix call before it, including AddChild with keepWorldPosition, crashed (fixed in PR #24).

The 4×4 SSE2 path's inverse() also uses the scalar implementation, so the singular-matrix exception above applies on every tier. SIMD tier selection and the SIMD correctness fixes are covered on Math & SIMD PR #27.

Source: math/include/math/Matrix.hpp — static *_func defaults, InverseScalar, InverseSSE2; engine/src/Application.cpp — Application::Init
