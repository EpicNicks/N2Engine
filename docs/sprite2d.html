Sprites and 2D shapes

Sprite2D draws a flat shape in its object's x, y plane: a rectangle, triangle, circle, regular polygon or convex polygon, filled or outlined, in a colour, optionally textured. For 2D games, with an orthographic camera and 2D physics.

Fields

FieldDefaultMeaning
shape PR #318RectRect, Triangle (pointing up), Circle, RegularPolygon, Polygon
size(1, 1)World units. For a circle or regular polygon, the diameter on each axis, so an ellipse is possible
sides6RegularPolygon: 3 to 64, a corner at the top
verticesnonePolygon: 3 to 64 convex points in units of the size (-0.5 to 0.5 spans it), either winding
outline00 fills. Above 0, only a border this wide in world units, the same width on every side. Where a corner is sharper than the border, the border narrows there. Only a border so wide that nothing is left inside fills the shape

flash PR #327transparentA colour mixed over the sprite by its own alpha, after the saturation. The sprite's alpha, and so its shape, does not change. Each component is stored clamped to 0..1 (a value that is not finite as 0)
texturenoneAn image asset. Its filter setting (nearest for pixel art) applies
regionOffset, regionSize(0, 0), (1, 1)The part of the texture shown, in uv with v up: one cell of a sprite sheet. The size box maps onto it, so a textured circle shows the middle of its cell
flipX, flipYfalseMirror the shape and its texture around the object's position, as Unity's flipX does: with the pivot in the middle the sprite stays in place, with it at a corner the sprite turns over onto the other side
pivot(0.5, 0.5)Where the object's position sits within the size: (0, 0) is the lower-left corner
sortingOrder0Lower draws first, so further back

The shape rotates and scales with its transform. Invalid geometry (a size not above zero, sides out of range, a polygon that is not convex) draws nothing and logs one warning per reason.

Draw order

  • A sprite always draws in the Transparent queue, with sortingOrder as its sort key.
  • Lower orders draw first. Equal orders draw back to front by depth along the camera, then in hierarchy order, so the result is the same every frame.
  • Depth tested against opaque 3D geometry, not written: a 3D object in front still hides a sprite.
  • Both faces draw, so a flip or a negative scale never hides a sprite.

Design decision: always the Transparent queue

Only the Transparent queue has a draw order a component can set. An opaque sprite in the Opaque queue would be ordered by depth alone, and two sprites at the same z would fight. The cost is no early depth rejection for sprites, which does not matter at 2D scale.

Colour effects PR #327

saturation and flash are applied by the unlit shader on every renderer (OpenGL, Vulkan, WebGPU and software), to the colour after texture × color, in this order:

  • Saturation: rgb = clamp(mix(luma(rgb), rgb, saturation), 0, 1), with the Rec. 601 luma (0.299, 0.587, 0.114), the weights the dim and the screen tint use. The clamp comes at once, so above 1 the dim and tint see the same colour on every renderer (the software renderer stores 8-bit colour before them).
  • Flash: rgb = mix(rgb, flash.rgb, flash.a). Alpha is not changed.

Then the prefab stage's dim and the screen tint apply on top. Each step is skipped at its default, so a sprite that never sets them draws exactly what it drew before. Both are uniforms, so changing them every frame costs nothing extra.

  • Grayscale (a locked gallery icon): saturation = 0.
  • Hit flash: flash = Color(1, 1, 1, 0.8) for a few frames, then back to transparent.
  • Rainbow: set flash each frame to a hue that cycles, with alpha as the strength. On a white shape, setting color instead gives the same image.

The maths is Renderer::Common::ColorEffects (renderer/include/renderer/common/ColorEffects.hpp). The values reach the shader through Material::SetSaturation and Material::SetFlash, which apply to unlit materials only and are not saved in .mat files. The UI Image has the same two fields.

On the software renderer

The software renderer cannot blend (IRenderer::SupportsBlending is false). There a textured sprite's pixels whose texture alpha is below 0.5 are not drawn, whatever the sprite's own alpha, so a texture's transparent parts are cut out instead of drawn as boxes. Partial transparency, such as a soft edge, is lost there. Solid shapes look the same on every renderer, and so do the colour effects. The cut-out uses Material::SetBlendDiscardBelow, which applies only to blended materials and is not saved in .mat files. PR #358 A sprite whose colour alpha is 0 draws nothing there (the test never falls to 0, which would keep every pixel). The rule is Renderer::Common::BlendCutOutBelow (renderer/include/renderer/common/BlendCutOut.hpp), and the UI Image cuts a textured image out the same way (it sets the shader's uAlphaCutoff itself). A game can ask with Graphics.CanBlend() in Lua and skip soft glow sprites where it is false: a soft disc would become a hard one at half strength.

Outlines of textured sprites PR #366

outline draws a border of a shape. A textured sprite's visible shape is its texture's alpha, which no shape follows, so its outline is a second texture made from the first: Texture::MakeOutline(source, widthPixels, colour). It grows the source's solid texels (alpha at least 128, half opaque) by widthPixels in every direction (round corners), pads the texture by the same width on every side, and paints the grown shape in colour, transparent elsewhere. It is made once on the CPU and cached by (source, width, colour), so asking again costs a lookup. Being a plain texture, it draws the same on OpenGL, Vulkan, WebGPU and the software renderer; there, like any textured sprite, it is cut out at half alpha, which suits its hard edge.

Draw it as a second Sprite2D behind the original (a lower sortingOrder): the grown shape contains the original, which covers all of it but the ring. The second sprite must be larger by the padding. For a source texture of W × H pixels whose shown part (the region) is cw = regionSize.x · W by ch = regionSize.y · H pixels on a sprite of size world units, one texel is size.x / cw world units wide, so a width of p pixels adds p · size.x / cw world units on each side:

Outline sprite fieldValue
size(size.x · (cw + 2p) / cw, size.y · (ch + 2p) / ch)
regionOffset(regionOffset.x · W / (W + 2p), regionOffset.y · H / (H + 2p))
regionSize((cw + 2p) / (W + 2p), (ch + 2p) / (H + 2p))
pivot((pivot.x · cw + p) / (cw + 2p), (pivot.y · ch + p) / (ch + 2p)): the same point of the picture, so (0.5, 0.5) stays (0.5, 0.5)
flipX, flipYThe original's: both mirror around the object's position
sortingOrderLower than the original's

With the whole texture shown (the default region) this is simply a size of size · (W + 2p) / W on x (H on y), the default region and the same pivot when it is the middle. A Sprite2D can share its object with another (several per object are allowed), so the outline follows the original with no parenting:

-- An outline px texture pixels wide behind body, a textured Rect Sprite2D on go
local function AddTextureOutline(go, body, px, color)
    local ring = go:AddComponent('Sprite2D')
    ring:SetOutlineTextureOf(body, px, color) -- or a res:// path
    local tex = body:GetTextureSize()         -- W, H in pixels
    local size, pivot = body:GetSize(), body:GetPivot()
    local offset, region = body:GetRegionOffset(), body:GetRegionSize()
    local cw, ch = region.x * tex.x, region.y * tex.y
    ring:SetSize(Vector2(size.x * (cw + 2 * px) / cw, size.y * (ch + 2 * px) / ch))
    ring:SetRegion(Vector2(offset.x * tex.x / (tex.x + 2 * px), offset.y * tex.y / (tex.y + 2 * px)),
                   Vector2((cw + 2 * px) / (tex.x + 2 * px), (ch + 2 * px) / (tex.y + 2 * px)))
    ring:SetPivot(Vector2((pivot.x * cw + px) / (cw + 2 * px), (pivot.y * ch + px) / (ch + 2 * px)))
    ring:SetFlipX(body:GetFlipX())
    ring:SetFlipY(body:GetFlipY())
    ring:SetSortingOrder(body:GetSortingOrder() - 1)
    return ring
end

local ring = AddTextureOutline(player, body, 2, Color(1, 0.9, 0.2, 1))
  • Sprite sheets. The whole texture is outlined, so a neighbouring cell's texels within p pixels of the shown cell grow into its outline. Leave at least the width of transparent pixels between cells. A new region (an animation frame) needs the outline's region set again with the formulas above; the texture itself stays the same.
  • Colour and fading. The colour's alpha is stored in the texture. Keep it opaque and fade the outline sprite's color instead: on the software renderer an outline texture under half alpha is cut out entirely, while a faded color keeps it until 0 (the cut-out). A white outline tinted by the sprite's color serves every colour from one texture.
  • Width. A whole number of pixels from 0 to 256 (Texture::MaxOutlineWidth); 0 is the silhouette at the source's size (for a hit-flash shadow, say). Each new (source, width, colour) is a new texture, made in time linear in its pixel count, whatever the width; up to 32 are cached. To animate a moving outline, scale the outline sprite rather than asking for a new width every frame.
  • Not saved. The outline is a runtime texture, not a project asset: a scene saved with it does not find it again. Make it in a script (in Start, say).
  • Shapes. The recipe is for a Rect sprite. A textured circle shows only the middle of its texture, which the outline texture does not know about.

Performance

Each sprite is one draw call. Sprites with the same shape, size, outline, region and pivot share one mesh, kept while any sprite uses it. tests/engine/rendering/Sprite2DTests.cpp draws 2,000 circles on the software renderer and prints the time as a [SPRITE2D-PERF] line. Batching many sprites into one draw is not done yet.

From Lua

local bullet = GameObject.Create('Bullet')
local sprite = bullet:AddComponent('Sprite2D')
sprite:SetShape(Sprite2DShape.Circle)
sprite:SetSize(Vector2(0.2, 0.2))
sprite:SetColor(Color.Red)
sprite:SetSortingOrder(10)

local player = GameObject.Create('Player')
local body = player:AddComponent('Sprite2D')
body:SetTexture('res://sprites/player.png')
body:SetRegion(Vector2(0, 0.5), Vector2(0.25, 0.5)) -- one cell of a 4 x 2 sheet

-- A white hit flash, then back to normal; a locked icon in grey
body:SetFlash(Color(1, 1, 1, 0.8))
-- ... a few frames later:
body:SetFlash(Color(0, 0, 0, 0))
icon:SetSaturation(0)

Every field has a setter and a getter with the C++ name. SetTexture takes a res:// path or nil; SetVertices takes an array of Vector2. Annotations are in engine-api.lua.

PR #366 GetTextureSize() is the texture's size in pixels as a Vector2, or nil without a texture. SetOutlineTextureOf(source, widthPixels, color) sets the sprite's texture to the outline of source, a res:// path or another Sprite2D (its texture). A source that does not load, a Sprite2D with no texture, any other source, or a width that is not a whole number from 0 to 256 raises an error naming Sprite2D:SetOutlineTextureOf and keeps the sprite's texture.
