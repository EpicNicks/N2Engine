Application & frame loop

Application is the engine singleton. It starts the subsystems and reports which ones came up, runs the frame loop, turns a quit request into an orderly exit, and shuts the subsystems down in a fixed order. This page also covers Time, which the loop drives.

Init and ApplicationOptions

Application::GetInstance() returns a function-local static; the class cannot be copied or constructed elsewhere. Nothing is started until one of the Init overloads runs.

OverloadWhat it does
EngineHealth Init()Calls Init(options) with projectPath = "", PhysX, OpenGL, isHeadless = false.
EngineHealth Init(const Config::ApplicationOptions &)Starts every subsystem it can and returns their states. Never throws for a failed subsystem; the engine keeps running with whatever started. A repeated call before Shutdown is ignored PR #34 (see below).
void Init(std::unique_ptr<Scene> &&)Marked "for testing only". Calls Init(), adds the scene with loadAdded = true and processes the scene change immediately. Discards the health result. Passing a null scene is undefined behaviour (it ends up dereferencing the current scene, which does not exist).

Config::ApplicationOptions has four fields:

FieldEffect in Init
projectPathNot read by Application::Init. The editor host fills it from --project; projects initialise ResourceLoader themselves (see Resources).
physicsBackendOnly PHYSX exists. Used only when the build has PhysX (N2ENGINE_PHYSX_ENABLED).
renderBackendOPENGL, VULKAN or SOFTWARE; chooses the GLFW context hints and the renderer the window creates.
isHeadlessCreates the window invisible and skips audio. See Headless mode.

Init(options) runs these steps in order:

  1. If the application is already initialised (an Init with no Shutdown since), log the warning "Application::Init called again; ignored (call Shutdown first to re-initialize)" and return the stored health report. Nothing below runs PR #34.
  2. In Debug builds (N2ENGINE_DEBUG), install the console log subscriber, once per process (see Logger).
  3. Reset the health report and clear the quit flag (_quitRequested = false).
  4. Scripting: LuaRuntime::Instance().Initialize(). The result is cached by LuaRuntime, so an Init after Shutdown reports the first outcome again.
  5. Math::InitializeSIMD(), then Time::Init() (resets all clocks and timeScale to 1).
  6. Window and renderer: Window::InitWindow(options).
  7. Create the main camera, even without a window, so GetMainCamera() is never null after Init. Perspective 45°, near 0.1, far 100, at (0, 0, 10). Aspect is the window's, or 16:9 when the window has no size.
  8. Physics: construct and initialise PhysXBackend; on failure the backend is destroyed and left null.
  9. Audio: skipped when headless, else AudioSystem::Instance().Initialize().
  10. Store the health report, log a warning for every failed subsystem, return a copy.

Source: engine/src/Application.cpp — Application::Init; engine/include/engine/config/ApplicationOptions.hpp; engine/src/scripting/LuaRuntime.cpp — LuaRuntime::Initialize

auto &app = N2Engine::Application::GetInstance();
const N2Engine::EngineHealth health = app.Init({
    .projectPath = "",
    .physicsBackend = N2Engine::Config::ApplicationOptions::PhysicsBackend::PHYSX,
    .renderBackend = N2Engine::Config::ApplicationOptions::RenderBackend::OPENGL,
    .isHeadless = false,
});
if (!app.GetWindow().IsValid())
{
    // Run() would refuse to start; see GetHealth() for why
    return 1;
}
N2Engine::SceneManager::AddScene(N2Engine::Scene::Create("Main"), true);
app.Run(); // returns after OnApplicationQuit and Shutdown

Note

physicsBackend and renderBackend have no default member initialisers. Designated or brace initialisation (ApplicationOptions{}, or the form above with fields omitted) value-initialises them to the first enumerator (PHYSX, OPENGL). A default-initialised local (ApplicationOptions opts;) leaves them indeterminate.

Guarantee PR #34

Init runs once per Shutdown. A second call while initialised logs a warning and returns the current health report without touching the window, camera, physics backend or quit flag. Before PR #34 it opened another window and replaced the physics backend under live scenes. To re-initialise, call Shutdown() first; Shutdown clears the initialised flag. Not covered by a test, because Init needs a window.

Source: engine/src/Application.cpp — Application::Init, Application::Shutdown (_initialized)

Subsystem health

Init returns an EngineHealth: a list of SubsystemStatus{name, state, detail} in the fixed order Window, Renderer, Physics, Audio, Scripting. GetHealth() returns the same report later (as of the end of the last Init). Before any Init the list is empty, which counts as healthy.

StateMeaningCounts as failure?
NotStartedInit never reached this subsystem.No

DisabledDeliberately not started (headless audio, build without PhysX).No
FailedTried and failed; detail says why.Yes: IsHealthy() is false

Guarantee

IsHealthy() is false only when some subsystem is Failed; Disabled and NotStarted are healthy. Find(name) returns null for an unknown name. A Window that never initialised successfully is invalid, reports no renderer or input system, and its accessors are safe to call (ShouldClose() is true). The editor host serves the same report over TCP; see Health.

Headless mode and a failed window

isHeadless = true does two things and nothing else:

  • The GLFW window is created with GLFW_VISIBLE = false. It is still a real window with a real renderer when the machine can provide one.
  • Audio is not initialised and is reported Disabled.

Physics and scripting start as usual. On a machine with no monitor, the window size falls back to 1280×720; on one with no GPU (such as the CI runner), the window or renderer fails and is reported Failed.

A failed window is not fatal to Init, but Run() checks Window::IsValid() (window and renderer present) first. If invalid, it logs "Cannot run: no window or renderer (see GetHealth())", calls Shutdown() and returns without running a frame and without calling OnApplicationQuit. Hosts that can work without a window, like the editor host, run their own loop instead of Run().

Source: engine/src/Window.cpp — Window::InitWindow; engine/src/Application.cpp — Application::Init, Application::Run; editor-server/src/Main.cpp

The frame loop

Run() loops while the window is not closing and no quit was requested. Each iteration does the following, in this order:

  1. Window::PollEvents(): GLFW events, then InputSystem::Update() (actions fire here; see Input).
  2. Time::Update(): measure the frame delta and advance the clocks.
  3. Add min(unscaled delta, 0.25 s) to the fixed-step accumulator. With no scene loaded the accumulator is reset to 0 instead of being drained PR #34.
  4. If a scene is loaded: Scene::ProcessAttachQueue(), so components added since the last frame get attached before anything updates.
  5. If a scene is loaded: zero or more fixed steps (below).
  6. If a scene is loaded: Scene::Update().
  7. If a scene is loaded: Scene::AdvanceCoroutines() (see Coroutines).
  8. If a scene is loaded: Scene::LateUpdate().
  9. AudioSystem::Update(), after LateUpdate, where listeners and sources push their positions.
  10. Render(): clear, set the main camera's view/projection, upload scene lighting, render the scene, present. Skipped when there is no renderer.
  11. If a scene is loaded: Scene::ProcessDestroyed(): objects and components destroyed during the frame are torn down here.
  12. SceneManager::ProcessAnyPendingSceneChange(): a scene load requested during the frame takes effect now (see Scenes).

Source: engine/src/Application.cpp — Application::Run, Application::Render; engine/src/Window.cpp — Window::PollEvents

What happens when, from the point of view of game code:

Note

Steps 4–8 and 11 are skipped entirely while SceneManager::GetCurSceneIndex() is -1. Input, time, audio and rendering (of an empty frame) still run.

Fixed steps and physics

The accumulator is a double local to Run(), starting at 0. Each frame adds the unscaled frame delta, clamped to 0.25 s, then, while a scene is loaded:

while (accumulator >= Time::GetFixedUnscaledDeltaTime())   // 0.02 s
{
    if (Time::GetFixedDeltaTime() > 0.0f)                    // scaled; 0 when paused
        PhysicsUpdate(curScene);
    accumulator -= Time::GetFixedUnscaledDeltaTime();
}
  • Cadence is real time. Steps happen every 0.02 s of unscaled time regardless of timeScale; each step passes the scaled fixedDeltaTime to physics. Slow motion means the same number of smaller steps.
  • Clamp. A stall (debugger, loading) contributes at most 0.25 s, so at most 12 steps catch up in one frame instead of hundreds. The delta is used directly rather than a difference of float absolute times, which lost precision after hours of running (code review #16, fixed in PR #24).
  • Paused. With timeScale 0 the accumulator still drains at the same rate but no step runs: neither physics nor FixedUpdate. Stepping PhysX by 0 is an error, and this matches Unity. Unpausing does not replay the paused time.

PhysicsUpdate(scene) does, per step:

  1. backend->ApplyPendingChanges(): transform and body changes made by game code since the last step.
  2. scene.FixedUpdate(): component FixedUpdate callbacks.
  3. backend->Update(Time::GetFixedDeltaTime()): simulate.
  4. backend->SyncTransforms(): write simulated poses back to GameObjects.
  5. backend->ProcessCollisionCallbacks(): dispatch collision and trigger events.

Without a backend (PhysX failed, disabled, or not built), a step is just scene.FixedUpdate(). See Physics for the backend side.

Source: engine/src/Application.cpp — Application::Run, Application::PhysicsUpdate

Note PR #34

The accumulator only builds up while a scene is loaded. In a frame with no scene (GetCurSceneIndex() == -1) it is reset to 0, so the first scene to load starts with at most one frame's worth of steps instead of a burst of catch-up steps for the time spent without a scene. Before PR #34 it kept accumulating, and the per-frame 0.25 s clamp did not limit the total.

Time

Time is a static class. Init and Update are private and called only by Application. All getters return float; the state is kept in double.

GetterValue
GetUnscaledDeltaTime()Wall-clock seconds between the last two Time::Update calls (high_resolution_clock). Not clamped.
GetDeltaTime()Unscaled delta × timeScale.
GetUnscaledTime() / GetTime()Sums of the unscaled / scaled deltas since Init.
GetFixedUnscaledDeltaTime()0.02 s (50 Hz). There is no setter.
GetFixedDeltaTime()0.02 × timeScale, recomputed by SetTimeScale.
GetTimeScale() / SetTimeScale(s)Default 1. Takes effect from the next Time::Update for the frame delta, immediately for the fixed delta. Negative values are clamped to 0; NaN and infinity are ignored with a warning PR #34.

Lua sees the same values through the Time global (Time.deltaTime, Time.timeScale read/write, etc.; see Lua scripting).

Source: engine/include/engine/Time.hpp, engine/src/Time.cpp; engine/src/scripting/bindings/LuaTimeBindings.cpp — BindTime

Note

Time::Init (run by every Application::Init) resets timeScale to 1 and restarts the clocks; a time scale set before Init is lost. The first frame's delta covers everything between Init and that frame (scene setup, script loading); the accumulator clamps it, but GetDeltaTime() does not.

Guarantee PR #34

Time::SetTimeScale never makes time run backwards or become non-finite. A negative scale is clamped to 0 (a pause), and the fixed delta becomes 0 with it. A NaN or infinite scale is ignored: it logs a warning and keeps the previous scale. Lua's Time.timeScale setter goes through the same function. Test: CoreRobustnessTest.TimeScaleRejectsNegativeAndNonFiniteValues.

Quitting

Application::Quit() (static; also Application.Quit() in Lua) is a request: it logs "Quit requested" and sets a flag. It returns normally, so the calling component or Lua callback finishes. Before PR #24 it called std::exit(0) from inside callbacks with the scene and the Lua stack still live.

  • Run() checks the flag at the top of each iteration, so the frame in which Quit() was called runs to completion (including destroy processing and a pending scene change).
  • IsQuitRequested() exposes the flag to hosts that do not use Run(); the editor host polls it.
  • The flag is cleared only by Init (one that actually runs, so the first Init or one after Shutdown). It is not cleared by Run() or Shutdown(). A Quit() requested before Run() is honoured only if it comes after Init (for example from a scene script's file-scope code run while adding the first scene): Run() then exits before the first frame. A Quit() before Init is lost, because Init clears the flag.

When the loop ends, for either reason (window closed or quit requested), Run() calls OnApplicationQuit() on the current scene, if there is one, then Shutdown(). The editor host does the same after its own loop. Run()'s early return for an invalid window does not call OnApplicationQuit.

Source: engine/src/Application.cpp — Application::Quit, Application::Run; engine/src/scripting/bindings/LuaApplicationBindings.cpp; editor-server/src/Main.cpp; tests: CoreRobustnessTest.QuitIsARequestNotAnExit

Guarantee

Application::Quit() does not terminate the process; afterwards IsQuitRequested() is true. Test: CoreRobustnessTest.QuitIsARequestNotAnExit.

Design decision: Quit is a request

Quit() is almost always called from inside a component callback or a Lua function, with the scene, the component and the Lua stack live on the call stack. Exiting there (the old std::exit(0)) ran static destructors under that code and skipped OnApplicationQuit and Shutdown. Setting a flag instead gives one exit path for every reason the loop can end: the frame finishes with the usual end-of-frame work (destroy processing, a pending scene change), then OnApplicationQuit, then Shutdown in a fixed order. Teardown is the same whether the window closed or a script quit, and Quit() is safe to call from any callback. Hosts with their own loop, like the editor host, poll IsQuitRequested() and follow the same order. This is the same deferral the engine uses for destroy and scene switches.

Warning

Because only Init clears the flag, a test binary that calls Quit() leaves it set for every later test. A later test that spins Run() or the editor loop would exit at once. See Testing conventions.

Shutdown order

Shutdown() tears subsystems down in reverse order of Init:

  1. SceneManager::UnloadScenes() PR #28: drops any pending scene change, runs Clear() on the loaded scene (so components get OnDestroy) and frees it. Stored scene data is kept.
  2. AudioSystem::Instance().Shutdown(): stops and deletes one-shot and pooled sources, deletes sources still held by AudioSource components (and makes them forget the ids), destroys the OpenAL context.
  3. Destroy the physics backend (~PhysXBackend releases the PhysX SDK).
  4. Window::Shutdown(): input system, renderer, GLFW window, glfwTerminate.

Scenes go first so the audio sources and physics bodies their components hold are released while those subsystems still exist. Before PR #28 the loaded scene was only freed during static destruction, after audio and PhysX were gone.

Shutdown is safe without Init and safe to call more than once. Run() calls it; hosts that do not use Run() must call it themselves before returning from main, so teardown does not depend on static destruction order.

Source: engine/src/Application.cpp — Application::Shutdown; engine/src/sceneManagement/SceneManager.cpp — SceneManager::UnloadScenes; engine/src/audio/AudioSystem.cpp — AudioSystem::Shutdown; tests: ApplicationShutdownTest.SafeWithoutInitAndWhenRepeated

Note

Shutdown does not tear down the Lua runtime, the main camera, ResourceLoader/Resources caches or stored scene data; those live until static destruction. The health report also keeps its last values.

RenderEditorFrame

RenderEditorFrame() renders one frame for a host that drives the engine itself (the editor server's RenderFrame command). It returns immediately if the window is invalid; otherwise it runs PollEvents, Time::Update, AudioSystem::Update and Render.

It does not run the attach queue, fixed steps, Update, coroutines, LateUpdate, destroy processing or pending scene changes: the scene is drawn, not simulated.

Source: engine/src/Application.cpp — Application::RenderEditorFrame; editor-server/src/EditorServer.cpp — EditorServer::HandleRenderFrame

Using Application in tests and tools

Init needs a window, so tests never call it. The pieces a test needs are installed directly:

  • Set3DPhysicsBackend(std::unique_ptr<IPhysicsBackend>) installs a backend without Init. It replaces and destroys any existing backend; nullptr removes it. Unload or replace scenes holding bodies first, because the old backend is destroyed immediately.
  • Fixed steps are driven by hand the way PhysicsUpdate does (PhysicsUpdate itself is private).
  • GetHealth() is empty and healthy; Shutdown() is a safe no-op.
static void SetUpTestSuite()
{
    auto backend = std::make_unique<N2Engine::Physics::PhysXBackend>();
    ASSERT_TRUE(backend->Initialize());
    N2Engine::Application::GetInstance().Set3DPhysicsBackend(std::move(backend));
}

static void TearDownTestSuite()
{
    // Leave no loaded scene holding bodies of the backend that's about to go away
    N2Engine::SceneManager::AddScene(N2Engine::Scene::Create("Teardown"), true);
    N2Engine::SceneManager::ProcessAnyPendingSceneChange();
    N2Engine::Application::GetInstance().Set3DPhysicsBackend(nullptr);
}

Source: engine/include/engine/Application.hpp — Application::Set3DPhysicsBackend; tests: PhysicsTest fixture in tests/engine/physics/PhysicsTests.cpp, EngineHealthTest.ApplicationHasNoHealthBeforeInit

Singletons and static destruction

The engine relies on several process-wide singletons. Function-local statics are destroyed in reverse order of construction at exit, which is why teardown is done explicitly in Shutdown() and why some instances are deliberately never destroyed.

SingletonStorageWhy
Applicationfunction-local staticTeardown is in Shutdown(), not the destructor: statics created during Init (such as the debug console stream) would already be gone by the time ~Application runs.
SceneManagerfunction-local staticIts loaded scene is unloaded by Shutdown() PR #28; stored scene data lives until exit.
AudioSystemnew, never deleted (leaked on purpose)AudioSource destructors unregister from it and can run during static destruction (SceneManager's scene). In headless mode Init never touches AudioSystem, so it was first created after SceneManager and, as a function-local static, destroyed before it (raised in the PR #23 review).
Logger console streamnew, never deletedCreated after the Application singleton; destroying it first made log calls during later teardown crash.
