GPU Vulkan checklist PR #308

What to run by hand on a Windows PC with a GPU to check the Vulkan renderer's window path (stage F of #43: the surface, the swapchain, Present, resize and minimise, vsync and the GPU choice), which CI cannot run: the CI runners have no GPU and no display, so CI runs the Vulkan renderer on Mesa lavapipe, a CPU driver, and the swapchain only on lavapipe's headless surface. Nothing here needs more than the repository, the Vulkan SDK and a build. Report which steps pass, and the text of any warning, validation message or crash.

Hardware rule

The Vulkan swapchain stage (PR #308) is not merged until this checklist has been run on a real GPU PC and the result reported.

Requirements

  • Windows 10 or 11 x64 and a GPU with a current Vulkan 1.1 (or newer) driver: NVIDIA, AMD or Intel. A driver from the last year or two is fine; note its version.
  • The LunarG Vulkan SDK installed, so VULKAN_SDK is set (open a new terminal after installing). It provides glslangValidator, which compiles the built-in shaders when the renderer is built, and the Khronos validation layer the tests and the validated run use.
  • Visual Studio with the C++ workload, and CMake.

1. Build with Vulkan

From the repository root (N2ENGINE_RENDERER_VULKAN is ON by default):

cmake -S . -B build -A x64 -DN2ENGINE_BUILD_TESTS=ON
cmake --build build --config Release --parallel --target renderer_tests lua_project
  • Expected in the configure output: a line Vulkan shader compiler: glslangValidator at C:/VulkanSDK/<version>/Bin/glslangValidator.exe (--version: ...), and no warning Vulkan built-in shaders not compiled. If that warning appears, the SDK was not found: the renderer would initialise but draw nothing. Fix the SDK install (or VULKAN_SDK) first.
  • build\bin\Release then holds renderer_tests.exe and lua_project.exe.

2. Run the Vulkan tests on the GPU

In PowerShell, from the repository root:

$env:N2_REQUIRE_VULKAN='1'
build\bin\Release\renderer_tests.exe --gtest_filter=Vulkan*:CrossBackend*
Remove-Item Env:N2_REQUIRE_VULKAN
  • Do not set N2_VULKAN_EXPECT_CPU_DEVICE (that one demands lavapipe). N2_REQUIRE_VULKAN=1 makes a missing device or validation layer a failure instead of a skip.
  • Expected: every test passes on the GPU, with validation on (each test fails on any validation error or warning, or on a leaked Vulkan object). The log prints the device per test ([ vulkan ] device: <your GPU> (validation on)) and Vulkan renderer: using <your GPU> (discrete GPU), chosen by default: note the name.
  • Expected skips: the VulkanHeadlessSwapchainTest.* tests skip with VK_EXT_headless_surface not offered by this driver: the swapchain path was not executed on most desktop drivers, which do not offer that extension. That is fine here: steps 3 and 4 run the same swapchain code on a real window. Nothing else should skip.
  • Any failure is a real-driver finding: copy the test name and its whole message (lit, text and blended goldens compare against tolerances measured on lavapipe, so a small difference is worth reporting with its numbers).

3. Select the Vulkan backend and run the demo

lua_project takes the renderer on its command line. A game selects Vulkan with ApplicationOptions::renderBackend = RenderBackend::VULKAN in Application::Init; OpenGL stays the default renderer, and the editor host does not offer Vulkan (it refuses --renderer vulkan).

$env:N2_VULKAN_VALIDATION='1'
build\bin\Release\lua_project.exe --renderer vulkan
Remove-Item Env:N2_VULKAN_VALIDATION
  • N2_VULKAN_VALIDATION=1 loads the validation layer (it comes with the SDK; vkconfig is optional and not needed), so the log shows any validation message as a Vulkan error: or Vulkan warning: line. A Release build without it runs without the layer.
  • The window title says N2Engine lua_project (Vulkan), and the log says Vulkan renderer: using <your GPU> (discrete GPU), chosen by default (on a PC with one GPU it may say integrated GPU; that is its type, not a failure).
  • Then run the same build with --renderer opengl and compare station by station (keys 1 to 7, 8, 9, 0, -; the HUD and the GPU smoke test's table say what each should show).

Expected: each station looks like the same station on OpenGL. Small antialiasing or precision differences are fine. A failure is: anything missing or black, the whole picture too bright or too dark compared with OpenGL (a colour-space or swapchain-format problem: the swapchain must be a UNORM format, why), red and blue swapped, the picture upside down or mirrored, stretched in one direction, or flickering. The log must have no Vulkan error: or Vulkan warning: line.

4. Window behaviour

  • Resize by dragging an edge and a corner: while dragging and after release the picture fills the window without stretch artefacts that stay, and nothing crashes or logs a validation message.
  • Maximise and restore (the title bar button, or Win+Up / Down).
  • Minimise for a few seconds, then restore: the app keeps running (the soft bodies and particles moved on meanwhile), CPU use is not pegged while minimised (Task Manager), nothing is logged while minimised, and the picture comes back.
  • Alt-Tab away and back, a few times.
  • Fullscreen or borderless: the demo has no key for it, so skip this.
  • A second monitor, if there is one: drag the window to it, and if its scaling (Windows display settings) differs, check the picture stays sharp and fills the window after the move (HiDPI: the swapchain follows the framebuffer size in pixels).
  • Wireframe: the demo has no key for it, so skip this (a Vulkan test checks wireframe offscreen).
  • Vsync. By default the swapchain uses FIFO (vsync on): the frame rate (read it from an overlay such as NVIDIA's or the Xbox Game Bar's; the demo shows none) is the monitor's refresh rate. Run again with vsync off: 
    $env:N2_VULKAN_VSYNC='0'
build\bin\Release\lua_project.exe --renderer vulkan
Remove-Item Env:N2_VULKAN_VSYNC
    The frame rate should now be above the refresh rate (MAILBOX where the driver offers it, else IMMEDIATE). MAILBOX does not tear; IMMEDIATE may. Say which you saw.

5. Two GPUs (only on a PC with an integrated and a discrete GPU)

  • With nothing set, the log says the discrete GPU was chosen.
  • $env:N2_VULKAN_GPU='<index or part of the name>' (for example 'intel', or '1': the index in Vulkan's enumeration order) picks the other one: the log says chosen by the GPU preference ..., and the demo still runs and looks the same.
  • A nonsense value ($env:N2_VULKAN_GPU='nonsense') logs exactly one line the GPU preference name 'nonsense' names no Vulkan device ...; using '<GPU>' instead (N2_VULKAN_GPU) and runs on the default GPU.
  • Remove it afterwards: Remove-Item Env:N2_VULKAN_GPU.

6. Performance sanity

At two or three stations (for example 1, 7 and 8), note the frame rate or frame time on --renderer opengl and on --renderer vulkan (both with vsync off for Vulkan, N2_VULKAN_VSYNC=0; OpenGL sets no swap interval, so it uses the driver's default). No numbers are required to pass: report both, and whether Vulkan stutters, for example a hitch the first time a station appears (pipelines are made the first time a material and state are drawn) or while text and particles update.

7. Exit

Press Esc: the app quits promptly and cleanly, with no crash and no hang, and (with N2_VULKAN_VALIDATION=1) no validation message at shutdown: the layer reports any Vulkan object still alive when the device is destroyed.

Revert

Nothing to revert: no file is edited. If you set any of N2_REQUIRE_VULKAN, N2_VULKAN_VALIDATION, N2_VULKAN_VSYNC or N2_VULKAN_GPU persistently (System Properties), remove them.

What to report

  • The GPU(s) and driver version(s), and the Windows version.
  • Step 2: the summary line ([ PASSED ], [ SKIPPED ], [ FAILED ] counts), the device name it printed, and the name and message of any failing test.
  • Step 3: per station, anything that differs from OpenGL (a screenshot helps), and any Vulkan error: or Vulkan warning: line verbatim.
  • Step 4: resize, maximise, minimise, Alt-Tab, multi-monitor and HiDPI results; the vsync frame rates and which mode it looked like.
  • Step 5 (if two GPUs): which GPU the default chose, and whether the preference and the nonsense value behaved as described.
  • Step 6: the frame-rate comparison and any stutter.
  • Step 7: how the exit went.
