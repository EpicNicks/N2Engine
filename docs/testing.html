Testing & CI

N2Engine's tests are GoogleTest executables, one per module, run headless through CTest. CI builds and runs them on Windows in Debug with and without PhysX and in Release with PhysX, then starts the editor host and talks to it over TCP. This page covers the layout, how to run the tests, the CI workflow, the conventions headless tests follow, and how to add one.

How tests are organised

Tests are only configured when N2ENGINE_BUILD_TESTS is ON (the default). The root CMakeLists.txt then fetches GoogleTest 1.17.0 with FetchContent (with gtest_force_shared_crt on), calls enable_testing() and adds tests/, which has one subdirectory per module:

DirectoryExecutable / CTest nameLinksNotes
tests/math/math_testsmathNo engine dependency.
tests/text/ PR #45text_teststextNo engine or renderer dependency. Font tests are parameterised over every font backend in the build (stb_truetype, plus FreeType with N2ENGINE_TEXT_FREETYPE PR #47).
tests/assetimport/ PR #64assetimport_testsassetimportNo engine or renderer dependency. Builds its test images in memory: PNGs written by hand (stored deflate blocks, every colour type and 16-bit), and JPEG, TGA, BMP and compressed PNG from the vendored stb_image_write, which only this executable compiles. Builds its glTF files in memory too PR #68, with tests/common/GltfTestBuilder.hpp (header-only, shared with engine_tests).
tests/engine/engine_testsengine, renderer, mathDefines N2_LUA_PROJECT_DIR (the lua_project source folder) so LuaSceneTests can build lua_project/assets/scene.lua headless, and N2_TEST_ASSETS_DIR (tests/assets, the committed test models and their generator) PR #68. Includes tests/common.
tests/renderer/renderer_testsrenderer, engine, mathNo GL context. CPU-side logic, such as the software renderer's draw ordering (DrawOrderTest) PR #46, and texture options, sampling, UpdateMesh and the text-shader query on an uninitialized software renderer (TextureOptionsTest, UpdateMeshTest, TextShaderTest) PR #49; and real pixels from a headless software renderer (SoftwareHeadlessTest, SoftwareTextShaderTest) PR #51, and the frame in flight (SoftwareResourceLifetimeTest, SoftwareMaterialSnapshotTest) PR #55. The empty OpenGL placeholder file is gone.
tests/editor-server/editor_server_testsN2EditorServerProtocol encoding, bounds-checked reads, the main-thread command queue and command handlers. On Windows, EditorServerSocketTest also opens real loopback sockets PR #33.

Each subdirectory's CMakeLists.txt follows the same pattern:

  • Sources are collected with file(GLOB_RECURSE ... "*.cpp" "*.cc" "*.cxx"), so any source file in the directory tree is part of the executable. The glob runs at configure time (no CONFIGURE_DEPENDS): after adding a file, re-run the CMake configure step.
  • Linked with GTest::gtest and GTest::gtest_main; no test defines its own main.
  • C++23, no extensions, warnings at /W4 (MSVC) or -Wall -Wextra.
  • Registered with a single add_test(NAME <exe> COMMAND <exe>). CTest therefore sees six tests, one per executable, not one per GoogleTest case. Use --gtest_filter on the executable to run individual cases.

Source: CMakeLists.txt; tests/CMakeLists.txt; tests/*/CMakeLists.txt

Building and running

Three CMake options matter for tests:

OptionDefaultEffect
N2ENGINE_BUILD_TESTSONFetch GoogleTest and build the four test executables.
N2ENGINE_USE_PHYSXONUse PhysX. On Windows the binaries are downloaded from the repository's physx-dependencies release into external/PhysX/physx/bin at configure time; if the download fails, PhysX is turned off with a warning. PhysX is also turned off for MinGW/GCC on Windows and on Linux. With PhysX off, N2ENGINE_PHYSX_ENABLED is not defined and PhysicsTests.cpp compiles to nothing.
N2ENGINE_TEXT_FREETYPE PR #47OFFFetch and build FreeType and add the FreeType font backend. Every font test in text_tests then also runs against FreeType, and the cross-backend tests compare it with stb_truetype.

The same commands CI uses (Visual Studio generator, multi-config):

cmake -S . -B build -A x64 -DN2ENGINE_BUILD_TESTS=ON -DN2ENGINE_USE_PHYSX=ON
cmake --build build --config Debug --parallel
ctest --test-dir build --build-config Debug --output-on-failure

Executables land in build/bin/<Config>/ (build/bin/Debug/ here). For a Release build, pass --config Release to the build and --build-config Release to CTest; the test executables, the editor host and the copied PhysX DLLs are then in build/bin/Release/. To run part of one:

build/bin/Debug/engine_tests.exe --gtest_filter=CoreRobustnessTest.*
build/bin/Debug/engine_tests.exe --gtest_filter=SceneStorageTest.* --gtest_repeat=3

Note

Debug builds define N2ENGINE_DEBUG (Release builds do not, and define NDEBUG, so assert is compiled out). Tests never call Application::Init, so the debug console subscriber is not installed and engine log output is not printed during tests unless a test subscribes to Logger::logEvent.

CI

.github/workflows/tests.yml ("Tests") runs on pushes to master, on every pull request, and on manual dispatch. It has one job on windows-latest with a 90-minute timeout and fail-fast: false, run as three matrix legs named windows (<config>, PhysX <ON|OFF>), with , FreeType ON added to the name of the leg that builds the FreeType font backend PR #47:

Job nameConfigurationPhysXFreeTypeWhy
windows (Debug, PhysX ON)DebugONOFFThe main leg: everything enabled, assertions on.
windows (Debug, PhysX OFF, FreeType ON)DebugOFFONKeeps the no-physics build compiling and running (the engine then has no physics backend). It also builds the optional FreeType font backend, so text_tests runs every font test against both backends and compares them, without a fourth full build.
windows (Release, PhysX ON)ReleaseONOFFCatches problems that only show with optimisation and NDEBUG: compiled-out asserts, optimised SIMD code paths, and it confirms that the sol2 safety checks, which engine/CMakeLists.txt forces on with a PUBLIC SOL_ALL_SAFETIES_ON=1 in every configuration (sol2 would otherwise turn them off in Release), still hold there.

Release runs with PhysX because the physx-dependencies archive contains both debug/ and release/ folders under win.x86_64.vc143.mt/; the root CMakeLists.txt picks the folder from the configuration (PHYSX_LIB_DIR, $<LOWER_CASE:$<CONFIG>>), and the engine links from debug or release. Release × PhysX OFF is not run: the OFF leg only checks that the code compiles and runs without a backend, which does not depend on the configuration. Only Debug and Release are supported with PhysX; RelWithDebInfo and MinSizeRel would look for DLLs in folders the archive does not have.

Each leg runs these steps:

  1. Check out the repository.
  2. Install the Vulkan SDK (headers and libraries only; no runtime).
  3. PhysX ON only: restore the cached external/PhysX/physx/bin. The cache key is not per configuration, because the one archive holds both configurations.
  4. Configure: cmake -S . -B build -A x64 -DN2ENGINE_BUILD_TESTS=ON -DN2ENGINE_USE_PHYSX=<matrix> -DN2ENGINE_TEXT_FREETYPE=<matrix>. With FreeType on, configuring downloads the pinned FreeType release.
  5. Build the leg's configuration: cmake --build build --config <Debug|Release> --parallel.
  6. Test: ctest --test-dir build --build-config <Debug|Release> --output-on-failure with ALSOFT_DRIVERS=null, which routes OpenAL Soft to its silent null backend because the runner has no sound card.
  7. Editor host smoke test (below), against the leg's build.

Editor host smoke test

A PowerShell step exercises the real N2EditorHost.exe end to end. The runner has no GPU, so the host's window fails and it serves without one; this checks that path too.

  1. Create a project folder, $RUNNER_TEMP/n2-smoke-project, with one asset, assets/startup.mat PR #84.
  2. Start build/bin/<Debug|Release>/N2EditorHost.exe --port 0 --project <folder>, capturing stdout and stderr PR #84. The host binds to 127.0.0.1 by default PR #33, which is where the test connects.
  3. Read the port from the host's ready line, as a launcher would PR #84: every 500 ms, up to 240 times, read the redirected stdout file (opened with read/write sharing, since the host holds it open) and match complete lines against ^N2EditorHost ready port=(\d+)( |$). Fail if the host exits first or never prints it.
  4. Connect to 127.0.0.1 on that port (a few retries for safety; the socket is listening before the line is printed).
  5. Send GetEngineHealth (0x50, zero-length payload). Expect a 0x09 response, read its payload, print its size and the healthy byte. Unhealthy is not a failure; a wrong response type is.
  6. Send GetAudio (0x03). Expect an AudioSamples (0x0A) response with 48000 Hz and 2 channels, and print its format and frame count PR #56. This checks that the headless host opened its loopback audio device on a runner with no sound card; an Error fails the step with its message.
  7. Check the project's resources were initialised PR #84: .import/startup.mat.meta exists and its uuid is not all zeros (all zeros would mean ResourceUUID was never initialised). Then add assets/added.mat, send RescanAssets (0x41), expect Ok, and check .import/added.mat.meta the same way.
  8. Send Shutdown (0xFF). Expect an Ok (0x00) response.
  9. Wait up to 30 s for the process to exit; fail (and kill it) if it doesn't.
  10. Fail on a non-zero exit code. This catches crashes during Shutdown and static destruction, which only show up when the process exits.
  11. Fail if the host's log contains "Assets directory not found" or "ResourceUUID not initialized" PR #84.
  12. Always print the host's stdout and stderr.

The wire format it uses is described in Wire format.

Conventions for headless tests

All tests run without a window, GPU or sound device. No test calls Application::Init; instead each test sets up only the parts it needs. Init does not require a window: without one it carries on and reports the window subsystem as Failed in its health result (the editor host relies on this in CI). Tests avoid it because a meaningful Init wants a real window and audio device, starts every subsystem in the shared singleton, and clears the quit flag that other tests may depend on. Every test in one executable shares the same process-wide singletons (Application, SceneManager, LuaRuntime, AudioSystem, Logger, ResourceLoader), so tests must leave them as they found them or tolerate earlier state.

Warning

Note

Math types work without Math::InitializeSIMD(): Vector3, Quaternion and the 3×3/4×4 float matrices default to their scalar implementations (PR #24), and so does Vector4 PR #30. Tests should not need to initialise SIMD, and should not leave a non-scalar tier selected.

Pixels: the headless software renderer PR #51

Rendering is tested with real pixels through a SoftwareRenderer started with Initialize(nullptr, width, height), which never touches GL (headless mode), so it runs on the GPU-less CI runner. A test:

  1. constructs a SoftwareRenderer on the stack, asserts Initialize(nullptr, w, h), and sets a clear colour that no draw uses;
  2. runs a frame as Application::Render does: BeginFrame, SetViewProjection (a camera's matrices, or identity to draw in NDC), the draws (or Scene::Render, UISystem::Render), EndFrame, Present;
  3. reads the frame with ReadFramebuffer at the renderer's size (RGBA8, row 0 at the bottom, so y grows upwards like NDC);
  4. releases what components hold on the renderer (CleanupRenderResources), then calls Shutdown. Declare the renderer before the scene, so it outlives it.

Assertions are structural, never exact images or hashes (why): pixel counts and bounding boxes within a pixel or a few percent, colours exact only where they are flat (unlit and alpha-tested text are; lit shading and anything resampled are not), and comparisons between two frames of the same run. Pick colours that are 0 or 1 per channel so packing can't round them.

What cannot be tested headless

  • Application startup and the frame loop. Application::Init runs headless but only reports Failed health for the window and renderer, so the parts worth testing need a real window and audio device; Run() refuses to start without a valid window. The loop order on the Application page is not covered by a test; tests replicate parts of it by hand.
  • Windowing. Window::InitWindow, window modes, resize callbacks. Only the uninitialised-window state is tested (WindowHealthTest).
  • GPU renderers. OpenGL and Vulkan need a context, so their pixels are not tested; the OpenGL text shader, including its effects (outline, shadow, softness) PR #66, is checked by eye. The software renderer is tested with real pixels in headless mode PR #51: its text shader, depth writes and read-back (SoftwareTextShaderTest, SoftwareHeadlessTest), material uniforms taken at DrawMesh and destroys during a frame in flight (SoftwareMaterialSnapshotTest, SoftwareResourceLifetimeTest) PR #55, a TextRenderer through Scene::Render and a UI Image and UIText PR #53 through the UI pass (SoftwareTextGoldenTest, SoftwareUIGoldenTest). Without pixels: the scene's draw order and per-draw state through a recording IRenderer (RenderQueueTest) and the software renderer's draw ordering (DrawOrderTest) PR #46; TextRenderer's meshes, resources and draws through a recording renderer (TextRendererTest) PR #49, and UIText's (UITextTest) PR #53; the polygon renderers' resource lifetime across renderers (PolygonRendererLifetimeTest) PR #52. The windowed software path (the GL blit in Present), RenderEditorFrame and the editor's RenderFrame command are untested.
  • Real input devices. Keyboard, mouse and gamepad state come from GLFW; tests use fake bindings.
  • Audible output. The null OpenAL backend accepts playback but produces nothing to check.
  • The editor server's rendering commands. Command handlers, payload and viewport limits, DeleteScene path checks and the command queue have unit tests, and on Windows EditorServerSocketTest drives a real loopback socket PR #33. RenderFrame needs a GL context and is untested. The CI smoke test covers GetEngineHealth, GetAudio PR #56, RescanAssets with --project, the ready line with --port 0 PR #84, and Shutdown against the real executable. Playing streamed audio in an editor client is untested (no client in the repository plays it).

Line endings

The repository has no .gitattributes, and line endings in the index are mixed. git ls-files --eol on master shows, for example:

Across engine/, math/, renderer/, tests/, editor-server/ and .github/, roughly two thirds of tracked files are CRLF in the index; files added or largely rewritten recently tend to be LF. In practice: keep a file's existing line endings when you edit it, so diffs show only real changes, and expect new files to be LF. With core.autocrlf=true on Windows the working copy shows CRLF either way, so check the index with git ls-files --eol <path> (the i/ column) rather than an editor.

Open question

No line-ending policy is written down or enforced (no .gitattributes, no CI check). Whether the repository should normalise to LF is undecided.

Adding a test

  1. Pick the executable by module: engine behaviour under tests/engine/<area>/, pure math under tests/math/, protocol encoding under tests/editor-server/.
  2. Create <Area>Tests.cpp (or add to an existing file for the same area). No CMake edit is needed; the directory is globbed. Re-run the CMake configure step so the new file is picked up.
  3. Name suites <Thing>Test and cases as a sentence describing the behaviour (ParentingARootRemovesItFromTheRoots). Other pages cite these names, so a good name documents the guarantee.
  4. Do not call Application::Init. Set up only what you need using the fixtures above; guard PhysX-dependent files with #ifdef N2ENGINE_PHYSX_ENABLED so the PhysX OFF leg still builds.
  5. Leave shared singletons as you found them: unique scene names, distinct Lua globals, restored Logger settings, scalar SIMD, physics backend removed.
  6. Build and run locally with --gtest_filter and, for anything touching shared state, --gtest_repeat=2. CI then runs it in all three legs (Debug with and without PhysX, Release with PhysX), so do not rely on assert for checks the test needs.
#include <gtest/gtest.h>

#include "engine/GameObjectScene.hpp"
#include "engine/sceneManagement/SceneManager.hpp"

using namespace N2Engine;

TEST(MyFeatureTest, AddedRootCanBeFoundByUUID)
{
    // A name unique to this test: re-adding a stored name replaces that scene
    SceneManager::AddScene(Scene::Create("MyFeatureTest_FindByUUID"), true);
    SceneManager::ProcessAnyPendingSceneChange();
    Scene &scene = SceneManager::GetCurSceneRef();

    auto go = GameObject::Create("Thing");
    scene.AddRootGameObject(go);

    EXPECT_EQ(scene.FindGameObjectByUUID(go->GetUUID()), go);
}
