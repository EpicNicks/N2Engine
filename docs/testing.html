Testing & CI

N2Engine's tests are GoogleTest executables, one per module, run headless through CTest. CI builds and runs them on Windows with and without PhysX, then starts the editor host and talks to it over TCP. This page covers the layout, how to run the tests, the CI workflow, the conventions headless tests follow, and how to add one.

How tests are organised

Tests are only configured when N2ENGINE_BUILD_TESTS is ON (the default). The root CMakeLists.txt then fetches GoogleTest 1.17.0 with FetchContent (with gtest_force_shared_crt on), calls enable_testing() and adds tests/, which has one subdirectory per module:

DirectoryExecutable / CTest nameLinksNotes
tests/math/math_testsmathNo engine dependency.
tests/engine/engine_testsengine, renderer, mathDefines N2_LUA_PROJECT_DIR (the lua_project source folder) so LuaSceneTests can build lua_project/assets/scene.lua headless.
tests/renderer/renderer_testsrenderer, engine, mathOnly a placeholder source file; the executable contains no tests.
tests/editor-server/editor_server_testsN2EditorServerProtocol encoding tests; never opens a socket.

Each subdirectory's CMakeLists.txt follows the same pattern:

  • Sources are collected with file(GLOB_RECURSE ... "*.cpp" "*.cc" "*.cxx"), so any source file in the directory tree is part of the executable. The glob runs at configure time (no CONFIGURE_DEPENDS): after adding a file, re-run the CMake configure step.
  • Linked with GTest::gtest and GTest::gtest_main; no test defines its own main.
  • C++23, no extensions, warnings at /W4 (MSVC) or -Wall -Wextra.
  • Registered with a single add_test(NAME <exe> COMMAND <exe>). CTest therefore sees four tests, one per executable, not one per GoogleTest case. Use --gtest_filter on the executable to run individual cases.

Source: CMakeLists.txt; tests/CMakeLists.txt; tests/*/CMakeLists.txt

Building and running

Two CMake options matter for tests:

OptionDefaultEffect
N2ENGINE_BUILD_TESTSONFetch GoogleTest and build the four test executables.
N2ENGINE_USE_PHYSXONUse PhysX. On Windows the binaries are downloaded from the repository's physx-dependencies release into external/PhysX/physx/bin at configure time; if the download fails, PhysX is turned off with a warning. PhysX is also turned off for MinGW/GCC on Windows and on Linux. With PhysX off, N2ENGINE_PHYSX_ENABLED is not defined and PhysicsTests.cpp compiles to nothing.

The same commands CI uses (Visual Studio generator, multi-config):

cmake -S . -B build -A x64 -DN2ENGINE_BUILD_TESTS=ON -DN2ENGINE_USE_PHYSX=ON
cmake --build build --config Debug --parallel
ctest --test-dir build --build-config Debug --output-on-failure

Executables land in build/bin/Debug/. To run part of one:

build/bin/Debug/engine_tests.exe --gtest_filter=CoreRobustnessTest.*
build/bin/Debug/engine_tests.exe --gtest_filter=SceneStorageTest.* --gtest_repeat=3

Note

Debug builds define N2ENGINE_DEBUG, but tests never call Application::Init, so the debug console subscriber is not installed and engine log output is not printed during tests unless a test subscribes to Logger::logEvent.

CI

.github/workflows/tests.yml ("Tests") runs on pushes to master, on every pull request, and on manual dispatch. It has one job, windows (PhysX ON|OFF), on windows-latest with a 90-minute timeout, as a matrix over physx: [ON, OFF] with fail-fast: false. The OFF leg keeps the no-physics build compiling and running.

  1. Check out the repository.
  2. Install the Vulkan SDK (headers and libraries only; no runtime).
  3. PhysX ON only: restore the cached external/PhysX/physx/bin.
  4. Configure: cmake -S . -B build -A x64 -DN2ENGINE_BUILD_TESTS=ON -DN2ENGINE_USE_PHYSX=<matrix>.
  5. Build the Debug configuration.
  6. Test: ctest --test-dir build --build-config Debug --output-on-failure with ALSOFT_DRIVERS=null, which routes OpenAL Soft to its silent null backend because the runner has no sound card.
  7. Editor host smoke test (below).

Editor host smoke test

A PowerShell step exercises the real N2EditorHost.exe end to end. The runner has no GPU, so the host's window fails and it serves without one; this checks that path too.

  1. Start build/bin/Debug/N2EditorHost.exe --port 9999, capturing stdout and stderr.
  2. Connect to 127.0.0.1:9999, retrying every 500 ms up to 120 times; fail if it never accepts.
  3. Send GetEngineHealth (0x50, zero-length payload). Expect a 0x09 response, read its payload, print its size and the healthy byte. Unhealthy is not a failure; a wrong response type is.
  4. Send Shutdown (0xFF). Expect an Ok (0x00) response.
  5. Wait up to 30 s for the process to exit; fail (and kill it) if it doesn't.
  6. Fail on a non-zero exit code. This catches crashes during Shutdown and static destruction, which only show up when the process exits.
  7. Always print the host's stdout and stderr.

The wire format it uses is described in Wire format.

Source: .github/workflows/tests.yml

Conventions for headless tests

All tests run without a window, GPU or sound device. Application::Init opens a window, so no test calls it; instead each test sets up only the parts it needs. Every test in one executable shares the same process-wide singletons (Application, SceneManager, LuaRuntime, AudioSystem, Logger, ResourceLoader), so tests must leave them as they found them or tolerate earlier state.

Warning

The quit flag sticks. CoreRobustnessTest.QuitIsARequestNotAnExit calls Application::Quit(), and only Application::Init clears the flag, which tests never call. For the rest of engine_tests, IsQuitRequested() may be true (depending on test order), so a test that spins Application::Run() or an editor-style loop would exit immediately. Nothing does today. See Quitting.

Note

Math types work without Math::InitializeSIMD(): Vector3, Quaternion and the 3×3/4×4 float matrices default to their scalar implementations (PR #24). Tests should not need to initialise SIMD, and should not leave a non-scalar tier selected.

What cannot be tested headless

  • Application startup and the frame loop. Application::Init needs a window; Run() refuses to start without one. The loop order on the Application page is not covered by a test; tests replicate parts of it by hand.
  • Windowing. Window::InitWindow, window modes, resize callbacks. Only the uninitialised-window state is tested (WindowHealthTest).
  • Renderers. OpenGL, Vulkan and software renderers need a context; renderer_tests is a placeholder. RenderEditorFrame and the editor's RenderFrame command are untested.
  • Real input devices. Keyboard, mouse and gamepad state come from GLFW; tests use fake bindings.
  • Audible output. The null OpenAL backend accepts playback but produces nothing to check.
  • The editor server's command handlers. Only the GetEngineHealth encoding has unit tests; the smoke test covers GetEngineHealth and Shutdown over a real socket.

Line endings

The repository has no .gitattributes, and line endings in the index are mixed. git ls-files --eol on master shows, for example:

Stored with CRLFStored with LF
tests/CMakeLists.txt, tests/engine/CMakeLists.txt, tests/math/CMakeLists.txt, tests/renderer/CMakeLists.txt, QuaternionTests.cpp, InputSystemTests.cpp, PrefabTests.cpp, most of editor-server/.github/workflows/tests.yml, root CMakeLists.txt, tests/editor-server/*, CoreRobustnessTests.cpp, HealthTests.cpp, AudioTests.cpp, PhysicsTests.cpp, LifecycleTests.cpp, the Lua and coroutine tests, SerializationRobustnessTests.cpp, editor-server/include/editor-server/Commands.hpp

Across engine/, math/, renderer/, tests/, editor-server/ and .github/, roughly two thirds of tracked files are CRLF in the index; files added or largely rewritten recently tend to be LF. In practice: keep a file's existing line endings when you edit it, so diffs show only real changes, and expect new files to be LF. With core.autocrlf=true on Windows the working copy shows CRLF either way, so check the index with git ls-files --eol <path> (the i/ column) rather than an editor.

Open question

No line-ending policy is written down or enforced (no .gitattributes, no CI check). Whether the repository should normalise to LF is undecided.

Adding a test

  1. Pick the executable by module: engine behaviour under tests/engine/<area>/, pure math under tests/math/, protocol encoding under tests/editor-server/.
  2. Create <Area>Tests.cpp (or add to an existing file for the same area). No CMake edit is needed; the directory is globbed. Re-run the CMake configure step so the new file is picked up.
  3. Name suites <Thing>Test and cases as a sentence describing the behaviour (ParentingARootRemovesItFromTheRoots). Other pages cite these names, so a good name documents the guarantee.
  4. Do not call Application::Init. Set up only what you need using the fixtures above; guard PhysX-dependent files with #ifdef N2ENGINE_PHYSX_ENABLED so the PhysX OFF leg still builds.
  5. Leave shared singletons as you found them: unique scene names, distinct Lua globals, restored Logger settings, scalar SIMD, physics backend removed.
  6. Build and run locally with --gtest_filter and, for anything touching shared state, --gtest_repeat=2. CI then runs it in both PhysX legs.
#include <gtest/gtest.h>

#include "engine/GameObjectScene.hpp"
#include "engine/sceneManagement/SceneManager.hpp"

using namespace N2Engine;

TEST(MyFeatureTest, AddedRootCanBeFoundByUUID)
{
    // A name unique to this test: re-adding a stored name replaces that scene
    SceneManager::AddScene(Scene::Create("MyFeatureTest_FindByUUID"), true);
    SceneManager::ProcessAnyPendingSceneChange();
    Scene &scene = SceneManager::GetCurSceneRef();

    auto go = GameObject::Create("Thing");
    scene.AddRootGameObject(go);

    EXPECT_EQ(scene.FindGameObjectByUUID(go->GetUUID()), go);
}
