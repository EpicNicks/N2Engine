Project modules

A game can leave out the engine modules it does not use, so its build is smaller. The project lists its modules, a scan checks the list against what the project uses, and the build compiles the rest out. So far the list covers physics; other modules will follow.

The list

A project lists its modules in project.n2proj. The editor keeps the key when it saves the file.

"build": {
  "modules": {
    "physics3d": "none",
    "physics2d": true
  }
}
ModuleValuesSets
physics3dnone, physx, jolt, bothN2ENGINE_USE_PHYSX, N2ENGINE_USE_JOLT
physics2dtrue, falseN2ENGINE_USE_BOX2D

A module the list does not name keeps its usual option. A project with no list builds everything. Unknown modules and values stop the configure with a message.

Design decision: the list is explicit, and the scan only checks it

Lua can reach a component through a computed name, as in AddComponent(kinds[i]), and no scan can resolve that. Stripping from the scan alone could remove something a script needs, and the game would break only when that line ran. So a person writes the list, and the scan suggests one and checks it.

Building a game with its list

cmake -S . -B build-mygame -DN2ENGINE_PROJECT=path/to/game

The engine is one static library, so the list applies to the whole build tree, and a game gets a tree of its own. An editor's tree never sets it, because a project can use anything while it is being edited.

  • Web: N2ENGINE_PROJECT also picks the project the player packs, in place of N2_WEB_PROJECT_DIR. Build the web-package target as usual (Web build).
  • Native: a native game is its own executable linking engine, as lua_project is. It can call n2_check_project_modules(<target>) in its CMakeLists.txt to check again each time it links.

The scan

node scripts/project-modules.mjs path/to/game             # what it uses against its list
node scripts/project-modules.mjs path/to/game --suggest   # the smallest list the scan can justify

It reads the component types in scenes and prefabs, and in Lua the module's globals, its event handlers and component names in quotes. Comments do not count. It also reads the project settings: physics.backend, and the deterministic network preset, which needs Jolt.

  • A conflict stops the build. It names the file and line, and runs at configure time, so before anything compiles, and again when the game links.
  • A computed name is reported as "could not be checked". It does not stop the build. Check those by hand.
  • Without node the check is skipped with a warning at configure time.

What a stripped module does at run time

The components stay registered, so a scene that names one still loads and saves without losing data, and the editor still lists it. The registry, and so the network fingerprint, does not depend on the list.

  • 3D physics: no backend, as when physics fails to start. Components warn and do nothing (Application), and Physics queries find nothing.
  • 2D physics: see Leaving it out of a game.
