Post-processing and render textures

A PostProcessStack component gives a scene full-screen effects: a blur, a screen warp, bloom, colour inversion, chromatic aberration and a vignette. A RenderTexture is a texture a frame can be drawn into, for a snapshot of the scene shown on a sprite or UI image. Both are from issue #445 and work on every renderer (OpenGL, Vulkan, WebGPU and software).

PostProcessStack

Add it to any object of the scene (go:AddComponent("PostProcessStack"), or in the inspector). The first active one the scene finds is used. A scene with none, or with every effect off, draws exactly as before and runs no extra pass. The fields are saved with the scene.

FieldDefaultMeaning
bloomfalseGlow around the bright parts
bloomThreshold0.7The brightness (the largest of r, g, b) above which a pixel glows. 0 makes everything glow, 1 nothing
bloomIntensity1How much of the blurred glow is added back, 0 to 16
bloomIterations4Blur passes, 1 to 8. The glow widens with each, and each costs two half-resolution passes
bloomTintwhiteMultiplies the glow's colour. Alpha is ignored
invert00 (none) to 1 (a full negative)
chromaticAberration0Red and blue fringes, 0 to 0.25, as a fraction of the distance from the screen centre (0.02 is strong)
vignette0Darkened corners, 0 to 1, starting 0.3 of the way out
blurfalseBlur the whole scene (a pause menu, a focus pull)
blurStrength10 (the sharp image) to 1 (the blurred one): a mix of the two, so a fade in is a number going up
blurIterations3Blur passes, 1 to 8. The blur widens with each, and each costs two half-resolution passes
distortion0Lens distortion, -1 to 1: above 0 the middle bulges out (barrel), below 0 it pinches in. The corners stay put
waveAmplitude0How far a wave moves a point, 0 to 0.1 of the screen; 0 is no wave
waveFrequency4Waves from one edge to the other, 0 to 64
wavePhase0Where the wave is in its cycle, in cycles (only the fraction counts)
waveSpeed0Cycles a second the wave travels by itself, on unscaled time, so it keeps moving while the game is paused

Out-of-range values are clamped when a frame uses them, and a value that is not finite takes its default.

Order and what it covers

  1. Blur issue #445: the frame is drawn at half resolution, blurred blurIterations times (the bloom's Gaussian, across and then down, spread one texel further each pass) and drawn back over the frame, mixed with the sharp image by blurStrength. Everything after it, the bloom's bright parts included, sees the blurred frame. Since it works at half resolution, even one pass softens the picture by a couple of pixels; the radius in pixels does not follow the window's size.
  2. Warp issue #445: each pixel is read from a displaced point. The distortion moves the point along the line from the screen centre by 1 + distortion / 2 × (r² − 1), where r² is 1 in the corners; then the wave adds waveAmplitude × sin(2π(waveFrequency × v + phase)) across and the same with u up and down (u rightwards, v upwards, 0 to 1). A point outside the picture reads its edge, so a strong pinch or wave streaks the borders. The warp is not applied to the pointer: a UI drawn over a warped scene stays where it is, and picking in the scene uses unwarped positions.
  3. Chromatic aberration: the red channel is read from a point moved away from the screen centre, blue from one moved towards it.
  4. Bloom: the parts brighter than bloomThreshold are taken at half resolution, blurred bloomIterations times (a 9-tap Gaussian across and then down, spread one texel further each pass) and added back times bloomIntensity and bloomTint.
  5. Invert, then vignette.
  • The effects run over the scene and before the screen-space UI, so a HUD is not bloomed.
  • Alpha is the frame's, untouched.
  • Frames are 8-bit, so a bloom sum is clamped to 0..1: the threshold is what picks out the "bright" parts. A neon look wants bright colours (full-value hues, or additive sprites) on a dark background.
  • The GPU backends keep the half-resolution bloom images in 8 bits, the software renderer (a CPU path, a few full-frame passes) in floats, so the pictures agree to within a few levels, not bit for bit.
  • A renderer without post-processing (a test fake) logs one warning and draws the scene unprocessed. Graphics.CanPostProcess() tells a script whether the renderer runs it.

Render textures

RenderTexture.new(width, height) makes a texture of 1 to 8192 on a side: linear filtering, clamped to the edge, no mipmaps, opaque, transparent black until the first capture. Its first row is the bottom of the frame, so it shows upright.

  • camera:RenderToTexture(texture) fills it once with the next frame's scene, after post-processing and without the screen-space UI, scaled to its size.
  • camera:SetTargetTexture(texture) copies every frame's scene into it (nil stops); the frame still shows on the screen. GetTargetTexture() returns it.
  • Show it with sprite:SetRenderTexture(texture) or image:SetRenderTexture(texture) (nil for none). sprite:GetTexture() then returns "", since it has no path.
  • texture:GetWidth(), GetHeight() and GetCaptureCount() (how many captures succeeded).

The GPU texture is freed with its last user: the RenderTexture object and every sprite or image showing it. A capture needs an open frame and a renderer that supports it; otherwise it does nothing and the capture count stays put.

From Lua

local fx = camera_object:AddComponent("PostProcessStack")
fx:Set({ bloom = true, bloomThreshold = 0.6, bloomIntensity = 1.5,
         bloomTint = Color(0.6, 0.9, 1, 1), vignette = 0.4 })
print(fx:Get().bloomIterations) -- 4

-- A snapshot of the scene, shown on a sprite next frame (a zoom-out prestige)
local snap = RenderTexture.new(512, 512)
camera:RenderToTexture(snap)
-- ... the next frame:
sprite:SetRenderTexture(snap)

Set changes the fields given and leaves the others. A field of the wrong type or an unknown name is an error and changes nothing.

Not yet

A shockwave or other warp around one point is not offered. Post-processing runs once over the whole scene frame, not per camera, and there is no user-written post shader, depth of field or tone mapping. A render texture holds an 8-bit picture, not HDR.
