Audio

Audio is built on OpenAL (OpenAL Soft). A process-wide AudioSystem owns the device, context, a pool of OpenAL sources and the mixer groups; AudioSource and AudioListener components play and position sound in a scene, and fire-and-forget one-shots play without a component. This page covers lifetimes, the frame timing, mixing rules, the source pool, clip loading and the Lua surface.

AudioSystem lifetime

AudioSystem::Instance() returns a singleton that is deliberately leaked: a heap object created on first use and never destroyed. AudioSource unregisters itself from the system in its destructor, and that destructor can run during static destruction (a scene still held by SceneManager's static). With a function-local static, the system could be destroyed first whenever it was first used after SceneManager (the headless path, where Init used to skip audio), and the unregister would touch a dead object.

Creating the instance does not open a device. That is Initialize(AudioOutput output = AudioOutput::Device):

  1. Returns true immediately if already initialized with the same output (idempotent), and false with a warning if it is running on the other one PR #56.
  2. Opens the output and creates a context on it: the default device for AudioOutput::Device, or an OpenAL Soft loopback device with a fixed format for AudioOutput::Loopback PR #56 (see Loopback output). Then it makes the context current. Any failure is logged with Logger::Error, everything created so far is released, and it returns false.
  3. Pre-allocates up to 32 pooled sources (a source that fails to generate is just not pooled).
  4. Creates the default mixer groups, overwriting any existing groups of those names (see mixer groups).
  5. Sets the listener gain to the stored master volume, so the master volume survives a re-initialize.

Shutdown() is a no-op when not initialized and safe to call twice; see Shutdown semantics. IsInitialized() reports the state. Application::Init calls Initialize(), or Initialize(AudioOutput::Loopback) when headless PR #56, and Application::Shutdown calls Shutdown(), which also leaves loopback mode.

Guarantee

Initialize is idempotent; IsInitialized tracks Shutdown and a later Initialize; the master volume survives a re-initialize; default groups are reset by it.

When the system is not initialized, its entry points are safe no-ops: Update and Stop do nothing, IsPlaying is false, PlayOneShot returns an invalid handle, CountPlayingInGroup is 0, AcquireSource returns 0 and ReleaseSource does nothing. An AudioSource then never gets a source, so Play(), UnPause(), Pause() and Stop() do nothing and its queries report not playing.

No call makes an OpenAL call without a context PR #37:

  • SetListenerPosition/SetListenerOrientation (called every LateUpdate by an AudioListener, and from Lua) do nothing; the listener pushes its pose again each frame.
  • SetMasterVolume clamps and stores the value; Initialize applies it to the new listener.
  • AudioClip::CreateFromData fails with the warning "Cannot create AudioClip: the AudioSystem is not initialized (no OpenAL context)", so audio files do not load headless: Resources::Load<AudioClip> and ResourceLoader::Load<AudioClip> return nullptr, and an AudioSource's clip reference in scene data stays unresolved (no clip). Lua has no resource-loading binding, so scripts never see such a clip. See AudioClip.
  • A clip unloaded or destroyed after Shutdown deletes nothing: its buffer died with the context.

Design decision: no audio clips without an audio context

An AudioClip is an OpenAL buffer, and OpenAL buffers only exist inside a context. Keeping the decoded samples around in a context-less "pending" clip would double memory for every clip and still not be playable, and making headless mode create a context would need a device. So a clip fails to load without an initialized AudioSystem, visibly (a warning and a null asset), rather than appearing loaded with an invalid buffer. Code that runs without audio (tests that don't initialize it, or a headless engine whose loopback device failed) must not rely on audio assets; scene data that references them still loads, with the reference unresolved. Since PR #56 a headless engine normally has a context (on the loopback device), so the editor host loads and plays clips like a game does. Each clip also remembers which context made it, so after a Shutdown and a later Initialize a stale clip reports not loaded and never deletes a buffer id that now belongs to another clip.

Loopback output and streaming to the editor PR #56

A headless engine (the editor host, N2EditorHost) has no speakers to play to: its audio is mixed on the server and sent to the editor client, which plays it. AudioSystem::Initialize(AudioOutput::Loopback) opens an OpenAL Soft loopback device (the ALC_SOFT_loopback extension) instead of a sound card. Sources, mixer groups, clips, one-shots, AudioSource, AudioListener and the Lua API work exactly as on a device; only where the mix goes changes.

The device and its format

  • AudioSystem::IsLoopbackSupported() asks OpenAL whether the extension exists (no device needed). The three entry points (alcLoopbackOpenDeviceSOFT, alcIsRenderFormatSupportedSOFT, alcRenderSamplesSOFT) are loaded with alcGetProcAddress.
  • The format is fixed: 48 kHz, stereo, interleaved (LoopbackSampleRate, LoopbackChannels). The sample type is float32 when alcIsRenderFormatSupportedSOFT accepts it (OpenAL Soft always does), otherwise int16; both little-endian. GetLoopbackFormat() returns the choice (sampleRate, channels, sampleFormat, BytesPerFrame()), and ToString(SampleFormat) names it "float32" or "int16". The context is created with ALC_FORMAT_CHANNELS_SOFT = ALC_STEREO_SOFT, ALC_FORMAT_TYPE_SOFT and ALC_FREQUENCY = 48000.
  • IsLoopback() is true while initialized on the loopback device; GetOutput() reports the output.
  • A missing extension, missing entry points, or neither sample type being supported logs an error and Initialize returns false: no audio, nothing else affected.

Rendering samples

A loopback device has no clock of its own: its time only moves when samples are rendered. RenderSamples(buffer, frameCount) mixes the next frameCount frames into buffer (frameCount × BytesPerFrame() bytes) on the calling thread, and the sources advance by exactly that much: a playing one-shot reaches its end, and turns AL_STOPPED, once enough frames have been rendered. Until then nothing finishes, so Update recycles nothing. It returns false and leaves the buffer untouched unless IsLoopback(). Tests use it directly; the engine uses AdvanceStream.

Pacing by elapsed time

The editor pulls frames one request at a time and irregularly, but audio has to come out at a steady 48 000 frames a second. So the mix is paced by time, not by requests: AdvanceStream(unscaledSeconds) adds unscaledSeconds × 48000 to a fractional accumulator and renders the whole frames (in chunks of 1024) into the stream buffer, carrying the remainder to the next call. One call advances at most MaxStreamAdvanceSeconds (1 s), so a long stall such as a debugger pause doesn't mix minutes of audio at once. Zero, negative or NaN times do nothing, as does any call unless IsLoopback().

Who calls itWith what time
Application::RunTime::GetUnscaledDeltaTime() each frame, right before AudioSystem::Update (see frame timing). A no-op on a sound card.
N2EditorHost's main loopEditorServer::UpdateAudio() each iteration (at least every 16 ms or so, and right after every request), after ProcessCommands: the real time since its previous call (steady_clock), then AudioSystem::Update. The host runs no game frames (Time only moves in RenderFrame), so this is its clock. It runs whether or not a client is connected.

Pacing is unscaled: audio keeps time while the game is paused (timeScale 0), as a sound card would.

The bounded stream buffer

Rendered frames go into a ring buffer that holds at most StreamBufferMilliseconds = 250 ms (12 000 frames; GetStreamCapacityFrames()). When a write would overflow it, the oldest frames are discarded and counted. TakeStreamedAudio() moves everything held out, oldest first (samples, frameCount, and droppedFrames since the previous take), and empties it; GetStreamedFrameCount() reports what is held, and ClearStream() discards it without touching the audio clock. With no client connected, or a client that stops asking, rendering continues, so one-shots finish and return to the pool, while memory stays at 250 ms of audio (96 KB in float32).

Sending it to the editor: GetAudio

The editor protocol's GetAudio (0x03, no request fields) returns everything mixed since the previous GetAudio as an AudioSamples response (0x0A). Without a loopback device it is an Error ("No audio stream: audio isn't running on a loopback device (see GetEngineHealth)"). Payload, in order (see the wire format):

FieldTypeMeaning
sampleRateuint3248000
channelsuint322 (interleaved left, right)
sampleFormatstring"float32" or "int16" (little-endian)
frameCountuint32Frames in samples; 0 when nothing was mixed since the last call
droppedFramesuint32Frames discarded since the last call because the 250 ms buffer was full: a gap before these samples
samplesbytesframeCount × channels samples, raw, to the end of the payload (no length prefix, like FrameData.pixels)

A client polls GetAudio alongside RenderFrame (every frame, or on its own timer), appends the samples to a small jitter buffer (50 to 100 ms) and plays from that at 48 kHz. A positive droppedFrames means the client fell more than 250 ms behind; it can insert that much silence to stay in step with the frames, or simply carry on (the Electron editor resyncs instead; see below). Audio and frames share the server's clock, so polling both every frame keeps them within one frame plus the client's jitter buffer of each other. The first GetAudio of a connection can return up to 250 ms mixed before the client connected.

Client playback: the Electron editor

The Electron editor frontend (a separate repository) plays the stream through Web Audio since its frontend PR #1:

  • Polling. It sends GetAudio 25 ms after the previous response arrives (requests never overlap), on its own timer, independently of the RenderFrame loop; after an unexpected error it retries after 1 s. Both share the one connection and the server answers in order, so a GetAudio queued behind a slow frame waits for it. When GetAudio answers the "No audio stream" Error (no loopback device) it stops asking and shows the audio as unavailable; it stops on disconnect.
  • Jitter buffer. Samples (float32 or int16, converted to float) are scheduled as AudioBufferSourceNodes on a 48 kHz AudioContext where the device allows it (otherwise one at the device's rate, and Web Audio resamples), keeping about 100 ms scheduled ahead of playback, so audio trails the frames by about that much. A first chunk too large to fit keeps only its newest frames, and when more than 250 ms is buffered, the excess is dropped at once, back to the 100 ms target.
  • droppedFrames. A positive count (the client fell more than 250 ms behind) is a gap: the buffer resyncs at the target instead of inserting silence, the first chunk after it fades in over 3 ms so it doesn't click, and the gap is logged to the console and counted in the toolbar. Frames dropped before the first chunk of a connection (while no client was reading) are not counted as a gap. An underrun (the buffer ran dry) resyncs the same way.
  • Drift correction. The buffer level is smoothed over chunks (an exponential moving average); when it leaves a ±20 ms band around the target, each chunk is resampled (linear interpolation) by at most 0.1% (at least one frame per chunk) until the level is back within 10 ms, which corrects the server's and the sound card's clocks differing (see why the server mixes by its own clock).

The decoding and jitter-buffer logic (src/audio-stream.ts) has unit tests in that repository, including drift and noisy-clock cases; the Web Audio output itself is not tested automatically. The generated C#, TypeScript and C++ clients in this repository still only declare GetAudio and AudioSamplesData/AudioSamplesResponse (declarations only, like the rest of the generated code): none of them decodes or plays audio. The server side is covered by tests and the CI smoke test.

Guarantee

Rendering through the loopback device is deterministic and needs no sound card: a known clip renders the requested number of frames at the expected level and is silent before it plays and after it ends; nothing finishes without rendering, and a one-shot finishes and returns its source to the pool after enough frames. AdvanceStream renders by elapsed time, however it is split up, and caps one step; the stream buffer never holds more than 250 ms and keeps the newest audio in order. Tests: LoopbackAudioTest.*, LoopbackAudioUninitializedTest.*, AudioStreamProtocolTest.*, AudioStreamServerTest.*.

Design decision: a loopback device, not the null backend

OpenAL Soft's null backend also needs no sound card, but it mixes on its own thread in real time and throws the result away: nothing can be sent anywhere, and tests must sleep and poll to see a sound finish. A loopback device hands the mix to the caller and runs only when asked, so the server decides when and how much to mix, gets the samples, and tests are exact (render 50 ms, and a 50 ms clip has ended). The cost is that the engine must keep rendering, or time stops; that is what pacing and the bounded buffer are for. The format is fixed at 48 kHz stereo because one format keeps the protocol and every client simple; float32 is preferred as it keeps the mixer's headroom and needs no dither, with int16 as the universal fallback.

Design decision: pace by elapsed time, render every frame

Mixing once per RenderFrame or GetAudio request would tie audio speed to how often the client asks: a client at 30 fps would hear half-speed time, and with no client one-shots would never end and never return their sources (the issue's main hazard). Mixing elapsed × sampleRate frames on the main thread every iteration keeps the audio clock equal to real time whatever the client does, and the fractional accumulator means no drift however the time is split. It runs on the main thread, alongside every other OpenAL call, so no locks are needed.

Two consequences for clients. Clock drift: the server mixes against its own clock at a nominal 48 kHz, while the client's sound card plays at its own, slightly different rate, so a client's jitter buffer slowly fills or drains; it must correct for that (skip or repeat a frame now and then, or resample). Stalls: one step mixes at most 1 s, so a main-loop stall longer than that (a long scene load) loses the excess time silently, and it is not counted in droppedFrames, which counts only audio dropped from the full buffer.

Design decision: a 250 ms buffer that drops the oldest audio

Because rendering never stops, something must bound what is kept. 250 ms is several frames of slack for a client that polls once per rendered frame (even at 10 fps), while staying small (96 KB) and short enough that a reconnecting client doesn't hear a long backlog. Dropping the oldest frames keeps what the client gets closest to now, which is what keeps audio in step with the frames; the dropped count tells the client there was a gap.

Design decision: a separate GetAudio request

Audio could ride along in FrameData, but that would change a response every client already decodes, make audio depend on a working renderer (CI and GPU-less machines have none; RenderFrame is an Error there), and couple audio's rate to the frame rate. A separate request/response fits the existing design (one request, one response, no server push), keeps FrameData unchanged, and lets a client poll audio on its own timer. Samples are raw bytes to the end of the payload, as pixels are, rather than base64: the protocol is binary throughout. The format fields come with every response, so a client needs no separate query and a future format change can't be misread.

Where audio runs in the frame

In Application::Run, AudioSystem::Update() runs once per frame after the scene's LateUpdate (and coroutines) and before Render, right after AdvanceStream, which mixes a loopback device for the frame's unscaled time (a no-op on a sound card) so that Update sees what finished PR #56. Components push positions in OnLateUpdate: AudioListener sets the listener, and a playing spatial AudioSource sets its source position. So positions are current when the frame's audio work happens. AudioSystem::Update itself only reclaims finished one-shots (see One-shots). Application::RenderEditorFrame also calls it.

AudioSource component

AudioSource is a SerializableComponent (several per GameObject allowed). Defaults: volume 1, pitch 1, not looping, spatial, mixer group "SFX", min (reference) distance 1, max distance 100, rolloff 1, _playOnAwake false, no clip. AudioSource::Serialize writes all of these and the clip (as an asset reference). Each setting has a getter, including GetPlayOnAwake, GetMinDistance, GetMaxDistance and GetRolloffFactor, and play-on-awake has a setter, SetPlayOnAwake PR #34.

Guarantee: sources and listeners survive scene loads PR #34

AudioSource and AudioListener are registered as built-in components, so every scene load and switch (each one rebuilds the scene from its stored JSON) brings them back. An AudioSource keeps its clip, volume, pitch, loop, spatial flag, play-on-awake, min/max distance, rolloff and mixer group. Before PR #34 neither was registered and both were dropped silently on every load. Tests: AudioSourceAndItsSettingsSurviveASceneLoad, AudioListenerSurvivesASceneLoad; see Serialization.

Registration and source acquisition

  • The constructor registers the component with AudioSystem (so group limits count it and group changes reach it); the destructor unregisters it, then stops and releases its OpenAL source if it holds one.
  • No OpenAL source is held until the first successful Play(): EnsureSource acquires one from the pool on demand. GetSourceHandle() returns the id, or 0 while it has none (for diagnostics and tests).
  • OnDestroy stops and releases the source back to the pool. A later Play() would acquire a new one.
  • ForgetSource() zeroes the held id without touching OpenAL; only AudioSystem::Shutdown calls it.

Design decision: Play restarts, UnPause resumes

These are Unity's semantics, which most scripts are written against, and they give each call one meaning whatever the source's state: Play() always means "this sound, from the start" (a re-triggered footstep or gunshot), and resuming is an explicit choice. Making Play() resume a paused source would make it depend on hidden state, and a script that wants to restart would first have to Stop(). A restart keeps the source's slot in its mixer group, since it is still one sound.

Volume, pitch and group

  • SetVolume clamps to 0..1; SetPitch clamps to 0.5..2.
  • Applied gain is ComputeFinalVolume(volume, group); applied pitch is pitch × group pitch (see mixer groups).
  • SetVolume, SetPitch and SetMixerGroup re-apply to a held source immediately. ApplyMixing() re-applies both and is what the system calls when a group changes.
  • A group name that does not exist is accepted: the source's own volume and pitch are used and there is no concurrency limit.

Spatial settings

  • Spatial (default): world-relative source, positioned at the GameObject's global position, with reference distance, max distance and rolloff from the component.
  • Non-spatial: listener-relative at the origin with rolloff 0, so distance has no effect.
  • SetSpatial switches mode on a held source immediately, but SetSpatial(true) on a held source re-applies only the rolloff and position, not the min/max distance: a source that was played non-spatial keeps the pool's reset values (reference distance 1, max distance FLT_MAX) until the next Play(). SetMinDistance clamps to ≥ 0; SetMaxDistance clamps to ≥ the current min distance; SetRolloffFactor clamps to ≥ 0. Each applies immediately only to a held source in spatial mode; otherwise it takes effect on the next Play().
  • OnLateUpdate updates the position while the source is spatial and playing.

Warning

Spatial playback creates a Positionable on the GameObject if it has none (AudioSource::UpdatePosition), unlike AudioListener, which skips. Playing a spatial source on a transform-less object therefore adds a transform at the origin. Use SetSpatial(false) for 2D sounds.

No distance model is set by the engine, so OpenAL's default applies; velocity (Doppler) is not set.

Guarantee

Default values and clamping are as listed; play/pause/stop report the right state; setting a clip while playing keeps playing the new clip, while stopped it does not start; a playing source counts toward its group's limit and is refused by a full group.

auto *music = go->AddComponent<Audio::AudioSource>();
music->SetSpatial(false);
music->SetMixerGroup("Music");
music->SetLoop(true);
music->SetClip(IO::Resources::Instance().Load<Audio::AudioClip>("res://audio/theme.ogg"));

AudioListener component

AudioListener is a plain Component, at most one per GameObject (IsSingleton = true). In OnLateUpdate, if active, it copies its GameObject's global position, forward and up vectors to the OpenAL listener. A GameObject without a Positionable is skipped silently (it used to dereference null). Nothing arbitrates between several active listeners in a scene: each writes the single global listener, so the last one to run its OnLateUpdate wins. Without any listener, the listener stays wherever it was last set (OpenAL starts it at the origin); Lua can also set it directly.

Guarantee

A listener on a GameObject without a Positionable does not crash.

One-shots

AudioSystem::PlayOneShot(clip, PlaybackParams) plays a clip without a component. PlaybackParams defaults: volume 1, pitch 1, non-spatial, position (0, 0, 0), not looping, group "SFX".

  1. Returns an invalid AudioHandle (id 0) if the system is not initialized, the clip is null or not loaded, the group's maxConcurrent is reached, or no source can be acquired (the last case logs a warning).
  2. Otherwise it takes a pooled source, sets buffer, gain (ComputeFinalVolume), pitch (ComputeFinalPitch), looping and either a world position (spatial) or listener-relative origin with rolloff 0, and plays.
  3. It records the source, group, requested volume and pitch, and a shared_ptr to the clip, under a new handle id (incrementing from 1, unique per process).

The one-shot holds its clip until it finishes, so dropping your last reference to the clip right after PlayOneShot is safe. AudioSystem::Update finds one-shots whose source state is AL_STOPPED, returns their sources to the pool, and erases the record (which releases the clip). After that, the handle is unknown.

CallBehaviour
Stop(handle)Stops, releases the source and forgets the handle. Unknown or invalid handles are ignored.
IsPlaying(handle)True only while the source is AL_PLAYING; false for unknown handles.
GetOneShotSource(handle)The OpenAL source id, or 0 if unknown (diagnostics/tests).

Note

A looping one-shot never reaches AL_STOPPED, so it plays (and holds a source and its clip) until you call Stop(handle) or the system shuts down. Keep the handle.

Missing or unloaded clips are rejected; handles are unique; Stop ends playback; unknown handles are ignored; a finished one-shot is cleaned up by Update; a looping one keeps playing.

Mixer groups and master volume

A mixer group (AudioMixerGroup) has AudioMixerGroupSettings: volume (1), maxSourceVolume (1), pitch (1), muted (false) and an optional maxConcurrent (no limit). Initialize (re)creates the defaults:

GroupNon-default settings
Master— (an ordinary group; not the master volume)
MusicmaxConcurrent = 2
SFX— (default for sources and one-shots)

VoicemaxConcurrent = 4
Ambient—

Mixing rules

  • Gain: ComputeFinalVolume(v, group) = 0 if the group is muted, else min(v, maxSourceVolume) × group volume. Unknown group: v.
  • Pitch: ComputeFinalPitch(p, group) = p × group pitch (1 for an unknown group). Before PR #23 group pitch was stored but never applied.
  • Master volume: SetMasterVolume clamps to 0..1 and sets the OpenAL listener gain (only stored while uninitialized; Initialize applies it). It is applied exactly once, through the listener, not in ComputeFinalVolume.
  • Concurrency: CountPlayingInGroup(group) counts one-shots and registered AudioSources in that group that are currently AL_PLAYING (paused ones do not count). Play() and PlayOneShot refuse to start when the count is ≥ maxConcurrent (for Play() on a source that is already playing, the count excludes the source itself). A limit only gates new playback; lowering it does not stop anything.

All setters ignore unknown group names. CreateMixerGroup(name, settings) creates or overwrites a group (overwriting does not refresh playing sounds).

Note

Group settings live in the singleton and are not cleared by Shutdown; Initialize overwrites only the six default groups, so a custom group survives a shutdown/initialize cycle with its settings while changes to default groups are lost. AudioMixerGroup::currentlyPlaying and activeSources are declared but not used by the engine; use CountPlayingInGroup.

Guarantee

Default groups and their settings; setter clamping; unknown groups ignored; muted groups silent; master applied once; group volume, mute and pitch reach a playing source (0.8 × 0.5 = 0.4 gain; pitch 1.2 × 1.5 = 1.8) and a playing one-shot (gain 0.25, pitch 2.0); maxConcurrent limits one-shots and sources together.

Source pool

Sources are recycled through a LIFO pool of at most 32 ids.

  • AcquireSource(): returns 0 when not initialized. Otherwise pops a pooled source; if the pool is empty it generates a new one, first clearing any pending OpenAL error so an unrelated earlier failure cannot make the new source look failed (and leak it). Returns 0 if generation fails. The total is not capped at 32; only the pool is.
  • ReleaseSource(id): ignores 0, and does nothing when not initialized (pooling an id from a dead context would alias a fresh source after the next Initialize). Otherwise it stops the source and resets everything the engine may have set: buffer 0, gain 1, pitch 1, not looping, not relative, position origin, rolloff 1, reference distance 1, max distance FLT_MAX. It is pooled if the pool has room, else deleted.

Guarantee

A released source comes back from the next acquire with gain 1, pitch 1, no looping and no buffer; acquiring beyond the pool size (40 with a pool of 32) still succeeds.

Source: engine/src/audio/AudioSystem.cpp — AcquireSource, ReleaseSource; tests: ReleasedSourcesAreReset, AcquireSourceGrowsBeyondPool

Shutdown semantics

AudioSystem::Shutdown(), when initialized:

  1. Stops and deletes every one-shot source and clears the one-shot records (releasing their clips).
  2. Deletes all pooled sources.
  3. For every registered AudioSource holding a source: stops and deletes it, then calls ForgetSource() so the component's id is 0.
  4. Releases the context and closes the device; IsInitialized() becomes false.

Because held ids are forgotten, a component that survives a shutdown and a later Initialize acquires a fresh source on its next Play() instead of driving an id that now belongs to something else. Components stay registered across the cycle. Calling Shutdown when not initialized does nothing.

In the application, Application::Shutdown unloads scenes first (SceneManager::UnloadScenes, which runs OnDestroy), so AudioSources release their sources while the context is alive, then shuts audio down, then physics and the window. PR #28

Guarantee

After Shutdown, a playing AudioSource's GetSourceHandle() is 0; double shutdown is harmless.

AudioClip and loaders

AudioClip is a Base::Asset (resource type "AudioClip") wrapping one OpenAL buffer with fully decoded PCM.

  • CreateFromData(AudioData): fails with a logged error for empty samples or a channel count other than 1 or 2, and with a warning when the AudioSystem is not initialized PR #37 (see why). Supports 8- and 16-bit mono/stereo. It unloads any previous buffer, clears stale OpenAL errors, then creates the buffer; an OpenAL error logs "Failed to create OpenAL buffer" and returns false. On success it records sample rate, channels and duration (bytes / (rate × channels × bytes per sample)).
  • IsLoaded() is true while it holds a buffer made in the current context: it turns false at Shutdown and stays false after a later Initialize PR #37. Unload() deletes the buffer (only in the context that made it) and resets metadata; the destructor unloads.
  • A buffer cannot be deleted while a source still plays it; stop sources (or rely on one-shots retaining their clip) before dropping the last reference.
