Audio

Audio is built on OpenAL (OpenAL Soft). A process-wide AudioSystem owns the device, context, a pool of OpenAL sources and the mixer groups; AudioSource and AudioListener components play and position sound in a scene, and fire-and-forget one-shots play without a component. This page covers lifetimes, the frame timing, mixing rules, the source pool, clip loading and the Lua surface.

AudioSystem lifetime

AudioSystem::Instance() returns a singleton that is deliberately leaked: a heap object created on first use and never destroyed. AudioSource unregisters itself from the system in its destructor, and that destructor can run during static destruction (a scene still held by SceneManager's static). With a function-local static, the system could be destroyed first whenever it was first used after SceneManager (the headless path, where Init skips audio), and the unregister would touch a dead object.

Creating the instance does not open a device. That is Initialize():

  1. Returns true immediately if already initialized (idempotent).
  2. Opens the default device, creates a context and makes it current. Any failure is logged with Logger::Error, everything created so far is released, and it returns false.
  3. Pre-allocates up to 32 pooled sources (a source that fails to generate is just not pooled).
  4. Creates the default mixer groups, overwriting any existing groups of those names (see mixer groups).
  5. Sets the listener gain to the stored master volume, so the master volume survives a re-initialize.

Shutdown() is a no-op when not initialized and safe to call twice; see Shutdown semantics. IsInitialized() reports the state. Application::Init calls Initialize() (unless headless) and Application::Shutdown calls Shutdown().

Guarantee

Initialize is idempotent; IsInitialized tracks Shutdown and a later Initialize; the master volume survives a re-initialize; default groups are reset by it.

Headless and no-device behaviour

SituationResult
ApplicationOptions::isHeadlessInitialize is never called. Audio subsystem health is Disabled ("Headless mode (streaming not yet implemented)"). The intent is to stream mixed audio to the editor client later.
No audio device / context failureInitialize returns false; the engine logs "Failed to initialize audio!" and "Audio will be disabled. Game will continue without sound."; health is Failed. The game keeps running.
CI and testsThe Tests workflow sets ALSOFT_DRIVERS=null, and the audio test fixture sets it too before the first ALC call, so OpenAL Soft uses its silent null backend and a real context exists without a sound card.

When the system is not initialized, its entry points are safe no-ops: Update and Stop do nothing, IsPlaying is false, PlayOneShot returns an invalid handle, CountPlayingInGroup is 0, AcquireSource returns 0 and ReleaseSource does nothing. An AudioSource then never gets a source, so Play() returns silently and its queries report not playing.

Open question

Some calls do not check IsInitialized and issue OpenAL calls with no current context: AudioSystem::SetListenerPosition/SetListenerOrientation (called every LateUpdate by an AudioListener, and from Lua), SetMasterVolume, and AudioClip::CreateFromData/Unload (engine/src/audio/AudioClip.cpp). What these do without a context is left to OpenAL; in particular it is unclear whether audio clips are expected to load at all in headless mode (buffer creation needs a context), and a clip destroyed after Shutdown calls alDeleteBuffers with no context.

Where audio runs in the frame

In Application::Run, AudioSystem::Update() runs once per frame after the scene's LateUpdate (and coroutines) and before Render. Components push positions in OnLateUpdate: AudioListener sets the listener, and a playing spatial AudioSource sets its source position. So positions are current when the frame's audio work happens. AudioSystem::Update itself only reclaims finished one-shots (see One-shots). Application::RenderEditorFrame also calls it.

Source: engine/src/Application.cpp — Application::Run, RenderEditorFrame; engine/src/audio/AudioSystem.cpp — AudioSystem::Update, CleanupFinishedSources

AudioSource component

AudioSource is a SerializableComponent (several per GameObject allowed). Defaults: volume 1, pitch 1, not looping, spatial, mixer group "SFX", min (reference) distance 1, max distance 100, rolloff 1, _playOnAwake false, no clip. All of these and the clip (as an asset reference) are serialized; see Serialization.

Registration and source acquisition

  • The constructor registers the component with AudioSystem (so group limits count it and group changes reach it); the destructor unregisters it, then stops and releases its OpenAL source if it holds one.
  • No OpenAL source is held until the first successful Play(): EnsureSource acquires one from the pool on demand. GetSourceHandle() returns the id, or 0 while it has none (for diagnostics and tests).
  • OnDestroy stops and releases the source back to the pool. A later Play() would acquire a new one.
  • ForgetSource() zeroes the held id without touching OpenAL; only AudioSystem::Shutdown calls it.

Playback

CallBehaviour
Play()Does nothing if there is no clip or it is not loaded, if the group's maxConcurrent is already reached (counting one-shots and sources), or if no source can be acquired. Otherwise binds the clip's buffer, applies volume/pitch with the group's settings, looping and the spatial settings, and starts playback.
Pause()alSourcePause if it holds a source.

Open question

AudioSource::Play (engine/src/audio/AudioSource.cpp) re-binds AL_BUFFER on every call, which OpenAL rejects for a playing or paused source, and then calls alSourcePlay. The test PlayPauseStop shows Play() after Pause() plays again, but whether it resumes or restarts, and what Play() on an already playing source should do, is not specified or tested. The concurrency check in Play() also counts the source itself if it is already playing, so restarting a playing source in a full group is refused.

Volume, pitch and group

  • SetVolume clamps to 0..1; SetPitch clamps to 0.5..2.
  • Applied gain is ComputeFinalVolume(volume, group); applied pitch is pitch × group pitch (see mixer groups).
  • SetVolume, SetPitch and SetMixerGroup re-apply to a held source immediately. ApplyMixing() re-applies both and is what the system calls when a group changes.
  • A group name that does not exist is accepted: the source's own volume and pitch are used and there is no concurrency limit.

Spatial settings

  • Spatial (default): world-relative source, positioned at the GameObject's global position, with reference distance, max distance and rolloff from the component.
  • Non-spatial: listener-relative at the origin with rolloff 0, so distance has no effect.
  • SetSpatial switches mode on a held source immediately. SetMinDistance clamps to ≥ 0; SetMaxDistance clamps to ≥ the current min distance; SetRolloffFactor clamps to ≥ 0. Each applies immediately only to a held source in spatial mode; otherwise it takes effect on the next Play().
  • OnLateUpdate updates the position while the source is spatial and playing.

Warning

Spatial playback creates a Positionable on the GameObject if it has none (AudioSource::UpdatePosition), unlike AudioListener, which skips. Playing a spatial source on a transform-less object therefore adds a transform at the origin. Use SetSpatial(false) for 2D sounds.

No distance model is set by the engine, so OpenAL's default applies; velocity (Doppler) is not set.

Guarantee

Default values and clamping are as listed; play/pause/stop report the right state; setting a clip while playing keeps playing the new clip, while stopped it does not start; a playing source counts toward its group's limit and is refused by a full group.

auto *music = go->AddComponent<Audio::AudioSource>();
music->SetSpatial(false);
music->SetMixerGroup("Music");
music->SetLoop(true);
music->SetClip(IO::Resources::Instance().Load<Audio::AudioClip>("res://audio/theme.ogg"));
music->Play();

AudioListener component

AudioListener is a plain Component, at most one per GameObject (IsSingleton = true). In OnLateUpdate, if active, it copies its GameObject's global position, forward and up vectors to the OpenAL listener. A GameObject without a Positionable is skipped silently (it used to dereference null). Nothing arbitrates between several active listeners in a scene: each writes the single global listener, so the last one to run its OnLateUpdate wins. Without any listener, the listener stays wherever it was last set (OpenAL starts it at the origin); Lua can also set it directly.

Guarantee

A listener on a GameObject without a Positionable does not crash.

Source: engine/src/audio/AudioListener.cpp — AudioListener::OnLateUpdate; tests: AudioListenerTest.WorksWithoutPositionable

One-shots

AudioSystem::PlayOneShot(clip, PlaybackParams) plays a clip without a component. PlaybackParams defaults: volume 1, pitch 1, non-spatial, position (0, 0, 0), not looping, group "SFX".

  1. Returns an invalid AudioHandle (id 0) if the system is not initialized, the clip is null or not loaded, the group's maxConcurrent is reached, or no source can be acquired (the last case logs a warning).
  2. Otherwise it takes a pooled source, sets buffer, gain (ComputeFinalVolume), pitch (ComputeFinalPitch), looping and either a world position (spatial) or listener-relative origin with rolloff 0, and plays.
  3. It records the source, group, requested volume and pitch, and a shared_ptr to the clip, under a new handle id (incrementing from 1, unique per process).

The one-shot holds its clip until it finishes, so dropping your last reference to the clip right after PlayOneShot is safe. AudioSystem::Update finds one-shots whose source state is AL_STOPPED, returns their sources to the pool, and erases the record (which releases the clip). After that, the handle is unknown.

CallBehaviour
Stop(handle)Stops, releases the source and forgets the handle. Unknown or invalid handles are ignored.
IsPlaying(handle)True only while the source is AL_PLAYING; false for unknown handles.
GetOneShotSource(handle)The OpenAL source id, or 0 if unknown (diagnostics/tests).

Note

A looping one-shot never reaches AL_STOPPED, so it plays (and holds a source and its clip) until you call Stop(handle) or the system shuts down. Keep the handle.

Guarantee

Missing or unloaded clips are rejected; handles are unique; Stop ends playback; unknown handles are ignored; a finished one-shot is cleaned up by Update; a looping one keeps playing.

auto &audio = Audio::AudioSystem::Instance();
Audio::AudioHandle h = audio.PlayOneShot(clip, {.volume = 0.7f, .spatial = true, .x = p.x, .y = p.y, .z = p.z});
if (!h.IsValid()) { /* not initialized, group full, or no source */ }

Mixer groups and master volume

A mixer group (AudioMixerGroup) has AudioMixerGroupSettings: volume (1), maxSourceVolume (1), pitch (1), muted (false) and an optional maxConcurrent (no limit). Initialize (re)creates the defaults:

GroupNon-default settings
Master— (an ordinary group; not the master volume)
MusicmaxConcurrent = 2
SFX— (default for sources and one-shots)
UImaxSourceVolume = 0.8
VoicemaxConcurrent = 4
Ambient—

Mixing rules

  • Gain: ComputeFinalVolume(v, group) = 0 if the group is muted, else min(v, maxSourceVolume) × group volume. Unknown group: v.
  • Pitch: ComputeFinalPitch(p, group) = p × group pitch (1 for an unknown group). Before PR #23 group pitch was stored but never applied.
  • Master volume: SetMasterVolume clamps to 0..1 and sets the OpenAL listener gain. It is applied exactly once, through the listener, not in ComputeFinalVolume.
  • Concurrency: CountPlayingInGroup(group) counts one-shots and registered AudioSources in that group that are currently AL_PLAYING (paused ones do not count). Play() and PlayOneShot refuse to start when the count is ≥ maxConcurrent. A limit only gates new playback; lowering it does not stop anything.

Changing a group

SetterClampReaches playing sounds
SetGroupVolume0..1Yes
SetGroupMaxVolume0..1Yes
SetGroupPitch0.5..2Yes
SetGroupMuted—Yes
SetGroupMaxConcurrent—New playback only

The first four call RefreshGroup, which (when initialized) re-applies gain and pitch to every one-shot in the group, from its recorded volume and pitch, and calls ApplyMixing() on every registered AudioSource in the group. All setters ignore unknown group names. CreateMixerGroup(name, settings) creates or overwrites a group (overwriting does not refresh playing sounds).

Note

Group settings live in the singleton and are not cleared by Shutdown; Initialize overwrites only the six default groups, so a custom group survives a shutdown/initialize cycle with its settings while changes to default groups are lost. AudioMixerGroup::currentlyPlaying and activeSources are declared but not used by the engine; use CountPlayingInGroup.

Guarantee

Default groups and their settings; setter clamping; unknown groups ignored; muted groups silent; master applied once; group volume, mute and pitch reach a playing source (0.8 × 0.5 = 0.4 gain; pitch 1.2 × 1.5 = 1.8) and a playing one-shot (gain 0.25, pitch 2.0); maxConcurrent limits one-shots and sources together.

Source pool

Sources are recycled through a LIFO pool of at most 32 ids.

  • AcquireSource(): returns 0 when not initialized. Otherwise pops a pooled source; if the pool is empty it generates a new one, first clearing any pending OpenAL error so an unrelated earlier failure cannot make the new source look failed (and leak it). Returns 0 if generation fails. The total is not capped at 32; only the pool is.
  • ReleaseSource(id): ignores 0, and does nothing when not initialized (pooling an id from a dead context would alias a fresh source after the next Initialize). Otherwise it stops the source and resets everything the engine may have set: buffer 0, gain 1, pitch 1, not looping, not relative, position origin, rolloff 1, reference distance 1, max distance FLT_MAX. It is pooled if the pool has room, else deleted.

Guarantee

A released source comes back from the next acquire with gain 1, pitch 1, no looping and no buffer; acquiring beyond the pool size (40 with a pool of 32) still succeeds.

Source: engine/src/audio/AudioSystem.cpp — AcquireSource, ReleaseSource; tests: ReleasedSourcesAreReset, AcquireSourceGrowsBeyondPool

Shutdown semantics

AudioSystem::Shutdown(), when initialized:

  1. Stops and deletes every one-shot source and clears the one-shot records (releasing their clips).
  2. Deletes all pooled sources.
  3. For every registered AudioSource holding a source: stops and deletes it, then calls ForgetSource() so the component's id is 0.
  4. Releases the context and closes the device; IsInitialized() becomes false.

Because held ids are forgotten, a component that survives a shutdown and a later Initialize acquires a fresh source on its next Play() instead of driving an id that now belongs to something else. Components stay registered across the cycle. Calling Shutdown when not initialized does nothing.

In the application, Application::Shutdown unloads scenes first (SceneManager::UnloadScenes, which runs OnDestroy), so AudioSources release their sources while the context is alive, then shuts audio down, then physics and the window. PR #28

Guarantee

After Shutdown, a playing AudioSource's GetSourceHandle() is 0; double shutdown is harmless.

Source: engine/src/audio/AudioSystem.cpp — Shutdown; engine/include/engine/audio/AudioSource.hpp — ForgetSource; engine/src/Application.cpp — Application::Shutdown; tests: AudioSourceTest.ShutdownDropsHeldSourceIds, AudioSystemUninitializedTest.CallsAreSafeNoOps

AudioClip and loaders

AudioClip is a Base::Asset (resource type "AudioClip") wrapping one OpenAL buffer with fully decoded PCM.

  • CreateFromData(AudioData): fails with a logged error for empty samples or a channel count other than 1 or 2. Supports 8- and 16-bit mono/stereo. It unloads any previous buffer, clears stale OpenAL errors, then creates the buffer; an OpenAL error logs "Failed to create OpenAL buffer" and returns false. On success it records sample rate, channels and duration (bytes / (rate × channels × bytes per sample)).
  • IsLoaded() is true while it holds a buffer. Unload() deletes the buffer and resets metadata; the destructor unloads.
  • A buffer cannot be deleted while a source still plays it; stop sources (or rely on one-shots retaining their clip) before dropping the last reference.

File formats

ExtensionDecoder
.wavdr_wav, converted to 16-bit
.oggstb_vorbis (implementation compiled once in StbVorbis.cpp)

LoadAudioClipFromFile(path) picks the decoder by lower-cased extension, decodes the whole file, and returns the clip or nullptr (unsupported extension, decode failure, or buffer failure, each logged). A missing or invalid WAV yields empty data and so nullptr.

The loader is registered for the four extensions by a static registrar in AudioClip.cpp, which every program using audio links (it used to live in a file the static-library linker dropped). It registers through IO::Resources::RegisterLoader, which passes it on to IO::ResourceLoader, so res:// paths and the project asset scan see audio files PR #28. See Resources & paths.

Guarantee

WAV mono/stereo and 8-bit files load (8-bit converted to 16-bit) with sample values preserved; missing or invalid files return empty data; clip creation rejects empty data and unsupported channel counts, replaces a previous buffer, and is not failed by a stale OpenAL error.
