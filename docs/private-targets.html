Private targets

A private target is a target folder kept outside this repository, such as a console whose SDK cannot be public. It adds a target to n2build, with its own player, platform backend, renderer and toolchain, without changing a file of the engine. This repository holds only the mechanism and a neutral sample. This is stage 11 of the build targets plan PR #TBD.

The target folder

A folder of targets holds one subfolder per target, each with its target.json (descriptors). n2build reads extra folders from three places:

  • the targetFolders list in your n2build.json;
  • the N2BUILD_TARGET_DIRS environment variable;
  • --targets-dir.

A name that is already taken is an error that names both files, so a private target can never replace a public one silently. Two descriptor keys exist for private targets:

KeyWhat it does
cmake.sourceDirA folder inside the target's folder that holds a CMakeLists.txt. n2build passes it to the engine's configure as N2ENGINE_EXTRA_TARGET_DIR, and the root CMakeLists.txt adds it with the engine's targets in scope (engine, renderer, MathCore::math, n2_player_options).
cmake.toolchainFileThe target SDK's CMake toolchain file, also inside the target's folder. It is passed as CMAKE_TOOLCHAIN_FILE.

Both must be relative paths without ..: the target's files stay in its folder. cmake.target names the player the folder builds, and package works as for the desktop targets: a file list beside the player names what a package ships.

Its code: player, backend, renderer

  • The player is the target's own main. It hands its platform backend to the window before the engine starts (Window::SetPlatformHost), as the Android and iOS players do.
  • The platform backend implements Platform::IPlatformHost (the platform layer). Its surface may be of kind Custom: the backend and its renderer agree on what the handle is.
  • The renderer: a backend that returns one from IPlatformHost::CreateRenderer() gets it instead of the configured renderer. It is initialised with RenderSurface() like any other. The default returns none, so the engine's own renderers are used. A backend can also keep the software renderer and take its frames as pixels (Surface::presentPixels).

Source: engine/include/engine/platform/PlatformHost.hpp — CreateRenderer; engine/src/Window.cpp — InitWindow; the root CMakeLists.txt — N2ENGINE_EXTRA_TARGET_DIR

Guarantee

A platform that brings a renderer gets that renderer, whatever renderer was configured, and never starts GLFW (PlatformHostTest.APlatformThatBringsItsOwnRendererGetsItInsteadOfTheConfiguredOne). No engine source names a private target (an n2build test scans them).

The sample

samples/private-targets/sample-console is a made-up console with a fixed 640×360 screen and no window system:

  • Its backend takes each frame as pixels and prints a summary to stdout (frame number, size, and a hash of the pixels), where a real target would give the frame to its display API.
  • It brings its own renderer, the software renderer under its own name.
  • Its player uses the desktop player's start-up code, so it runs the same packages.
node tools/n2build/n2build.mjs list  --targets-dir samples/private-targets
node tools/n2build/n2build.mjs build --targets-dir samples/private-targets --target sample-console --project lua_project
node tools/n2build/n2build.mjs run   --targets-dir samples/private-targets --target sample-console --project lua_project --no-build --frames 90

CI builds and runs it in the Linux n2build job, and checks that the target's own renderer drew and that its frames reached the backend.

What stays out of this repository

  • Every file of a real private target: its descriptor, player, backend, renderer, toolchain file and the SDK.
  • Any name, header, API or code shape taken from a platform holder's SDK. The sample uses only the engine's own interfaces and generic names.
  • Signing material and credentials: they follow the same rules as the public targets (signing profiles).
