The platform layer

Everything the engine asks of the platform it runs on (a window or surface, its events, the lifecycle, who owns the frame loop, the input devices and the folders) goes through one interface, Platform::IPlatformHost, with one backend per platform. GLFW is used only inside the desktop backend. This is stage 6 of the build targets plan PR #TBD; it changes no behaviour on the platforms that exist.

The interface

engine/include/engine/platform/PlatformHost.hpp:

PartWhat a backend provides
The surfaceCreateSurface (title, size, an OpenGL context or not, sRGB, visible), DestroySurface, Surface() (a NativeSurface: its kind and handle, for the renderer), its size in pixels, the content scale, the safe-area insets, and a resize handler
The windowTitle, window mode (windowed, fullscreen, borderless), cursor, clipboard, the soft keyboard (text input on and off), keeping the screen on; no-ops where there is no window
Events and the lifecyclePollEvents once a frame; ShouldClose; a handler for LifecycleEvents: Paused, Resumed, SurfaceLost, SurfaceRecreated, LowMemory, QuitRequested, BackRequested
The loopOwnsLoop(): false where the engine runs its own loop (desktop, headless); true where the OS calls the engine once a frame (the web, Android, iOS)
InputInput(): the input device, in engine codes, or null (input is then injected)
PathsThe project root (or a pack's mount point; Packs), user://, and a temporary folder

Backends

BackendWhereWhat it is
desktop-glfwWindows, Linux, macOSA GLFW window (engine/src/platform/DesktopGlfwHost.cpp), its events, window modes and monitors, and the GLFW input device. Moved from Window.cpp as it was: the window's size (half the primary monitor, else 1280 x 720), its hints and its modes behave exactly as before.
headlessEverywhereNo window, no surface, no input device (engine/src/platform/HeadlessHost.cpp). The editor host (Docker included), n2server, the test suites, the replay legs and the web player run on it. A program can hand it lifecycle events with PostLifecycleEvent (tests, or a host that relays a browser tab's visibility).
android, iosStages 8 and 10Their own surfaces, lifecycle and input behind the same interface; the OS owns the loop

Window chooses the backend in InitWindow: RenderBackend::NONE and the windowless renderers (Window::UsesNoWindow) run on the headless backend, everything else on the desktop one. Window::GetPlatformHost() returns it, Window::GetInputDevice() its input device, and Window::SetLifecycleHandler receives its lifecycle events. The desktop backend sends none today.

Renderer surfaces stage 7

A renderer starts on a Renderer::Common::Surface (renderer/include/renderer/common/Surface.hpp), not a GLFWwindow*: the platform's native surface (its kind and handle) and the few window-system operations a renderer needs, supplied by the platform backend (IPlatformHost::RenderSurface()), so no renderer calls the window system itself.

OperationWho uses itdesktop-glfw supplies
makeContextCurrent, getProcAddress, swapBuffersThe OpenGL renderer; the software renderer presents its frame through the same contextglfwMakeContextCurrent, glfwGetProcAddress, glfwSwapBuffers (only for a window made with an OpenGL context)
presentPixelsThe software renderer, on a platform that shows a CPU frame by copying it into the window (Android’s ANativeWindow buffer): no OpenGL context is needed. RGBA8, rows bottom to top, as ReadFramebuffer returns themNothing: the desktop presents through OpenGL
vulkanInstanceExtensions, createVulkanSurfaceThe Vulkan rendererglfwGetRequiredInstanceExtensions (empty when glfwVulkanSupported is false: the renderer refuses the window), glfwCreateWindowSurface
framebufferSizeVulkan's swapchain after a resize (0 x 0 while minimised)glfwGetFramebufferSize

Initialize(nullptr, width, height) is still an offscreen renderer (a Surface converts from nullptr), as headless hosts, the tests and the web start them. Android supplies the same operations from EGL and its ANativeWindow (stage 8); Apple's from a CAMetalLayer (stage 10). Outside the desktop backend and the GLFW input device, no source in engine/ or renderer/ includes a GLFW header.

The web build has no GLFW

The web build compiles neither the desktop backend nor the GLFW input device, and the web player's renderers have no window (they draw offscreen and the page shows what they read back), so no GLFW function is called. external/web-stubs no longer has a stand-in GLFW; since stage 7 no web source includes a GLFW header either (the glfw target there is an include path only, for targets that list it). Its <generator> shim stays: every libc++ toolchain (Emscripten, the NDK, Apple's) needs it.

Tests

  • tests/engine/platform/PlatformHostTests.cpp: the headless backend; every lifecycle event's name; a windowless Window on the headless backend forwarding lifecycle events; a fake mobile backend written against the interface alone (the OS owns the loop, the surface is lost and recreated around the background, insets, the soft keyboard).
  • Every existing test, smoke plan, web package smoke and web budget passes unchanged: the stage changes no behaviour.
